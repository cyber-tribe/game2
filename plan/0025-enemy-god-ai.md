# 敵AIに奇跡の使用と人口ベースの判断を追加する

## 背景

ユーザーからかなり詳細な戦略レビューを2本受け取った。要旨は共通して
いた：「game2はゴッドゲームの核となるループ（整地→定住→発展→人口→
マナ→介入）は正しく掴めているが、当時の熱狂を再現するにはまだ届いて
いない。その最大のボトルネックは敵AIで、現状は`enemyAi.ts`のコメントが
自ら認める通り"A minimal stand-in for real enemy decision-making"に
過ぎない」というもの。

具体的な指摘：

- 敵の行動判断はウォーカー数の閾値でfight/settleを切り替えるだけ。
- 敵は`plan/0020`で地形の整地はするようになったが、地震・洪水・
  騎士化・最終決戦といった攻撃的な奇跡を一切使わない。つまり
  「本物の神はプレイヤーだけ」になっている。
- レビュー内で提案された具体的な判断基準の例：「人口差1.8倍→
  最終決戦を狙う」「敵人口が多い→地震・火山による経済破壊」
  「自軍リーダーが巨大化→騎士化」。

レビューは改善項目を多数挙げていたが（UI、グラフィック、ミニマップ、
マップサイズ等）、両レビューとも「敵AIを最優先にすべき」と明言して
いたため、まずここに着手した。

## 対応

`game/systems/enemyMiracles.ts`に`createEnemyMiracleSystem`を新設した。
`enemyTerraform.ts`と同じく一定間隔（既定8秒）ごとに判断し、
優先順位付きで以下を評価する。

1. **人口差が`ARMAGEDDON_POPULATION_RATIO`（1.8、レビューの提案値を
   そのまま採用）以上** かつ`ARMAGEDDON_MANA_COST`を払えるなら
   最終決戦を発動する。
2. **behaviorModeが`fight`かつリーダーが騎士化していない** なら
   `KNIGHT_MANA_COST`を払って騎士化する。
3. どちらにも該当しなければ、`EARTHQUAKE_MANA_COST`を払えて
   相手の家が存在する場合、ランダムに選んだ相手の家へ地震を放つ
   （経済破壊）。

いずれもプレイヤーのタップと全く同じ`trySpendMana`を通すため、
マナが足りない手番は安いものにフォールスルーする（最終決戦が
払えなければ騎士化を試し、それも無理なら地震を試す）。

`Simulation`のスケジューラに追加し、`heightmap`と`worldCenter`
（`triggerArmageddon`が両陣営を集結させる中心座標、既存の
`this.worldCenter`をそのまま渡すだけで済んだ）を渡している。

## 副作用として見つけた不具合の修正

敵の地形操作（`enemyTerraform.ts`、`plan/0020`で導入済み）も今回の
地震も、`heightmap.vertices`を直接書き換えるが、`main.ts`の
`app.ticker`は`simulation.update()`のあとに`renderer.redraw()`を
一度も呼んでいなかった。つまり **敵が地形を変えても、プレイヤーが
自分でどこかをタップして偶然再描画が走るまで画面には一切反映されて
いなかった**。レビューが強調していた「向こうの大陸もガリガリ変形し、
気づくと敵神が地形を変えている」という感覚は、この不具合のせいで
そもそも見えない状態だった。

`app.ticker`のコールバックに`renderer.redraw()`を追加し、毎フレーム
地形を再描画するようにした（20×20マスなのでコスト上の問題はない）。
これで敵の整地・地震が即座に画面へ反映されるようになった。

## テスト

- `game/systems/enemyMiracles.test.ts`を新設（heightmap/worldCenter
  未指定時no-op、人口差が十分なら最終決戦を発動、不十分なら発動しない、
  リーダーを騎士化する、既に騎士なら何もしない、相手の家に地震を放つ、
  相手に家がなければ何もしない、finalBattle中は何もしない、
  decisionInterval経過前は再実行しない）。
- 既存の`simulation.test.ts`の「洪水で全ての家が水没する」テストが、
  敵の地震（本番と同じ`Math.random`を使うため確率的に地形を荒らす）
  により孤立した高台が生き残ってしまい失敗するようになった。これは
  テストの前提（「シミュレーション中の地形操作は起きない」）が今回の
  変更で崩れたことによるもので、フラッド判定の直前に地形を明示的に
  再度平坦化することで、テストの本来の意図（水没判定のロジック検証）
  はそのままに修正した。
- `npm run typecheck` / `npm run test`（199件） / `npm run build`
  すべて成功。
- ヘッドレスブラウザで2分間実際にプレイさせたところ、敵が実際に
  地形を荒らし（地図に不規則な尾根が出現）、人口で優位に立った時点で
  最終決戦を発動し、両陣営とも家が0になって`goToShrine`へ切り替わり、
  最終的に敵が勝利する一連の流れをスクリーンショットで確認した。

## 積み残し

レビューが挙げた項目のうち、今回はまだ手を付けていないもの：

- 洪水を戦略的に狙う（相手が低地に集中しているかの判定）。
- 敵の「集結」「防衛」的な判断（現状は定住/戦闘の二択のまま）。
- ミニマップ、戦場全体の把握UI。
- 地形操作そのものの演出強化（アニメーション、パーティクル等）。
- マップサイズ・征服モードなどコンテンツ量に関する項目。

これらは別タスクとして今後検討する。
