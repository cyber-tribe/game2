# 0036 walker-animation

## 背景

2回の敵対的評価がどちらも指摘した弱点：「民（ウォーカー）に生活感が
ない」。ドット絵化（PR#26）で円から人型のシルエットにはなったが、
歩いていても座っていても常に同じ1枚の絵のままで、静止画が
Position（座標）だけ動いているだけの状態だった。「本当に必要なのは、
民を操作できなくても、見ているだけで面白い状態」という指摘への、
最小の第一歩として、簡易な歩行アニメーション（2コマの足の切り替え＋
上下の揺れ）を追加した。

## アプローチ

`pixelArt.ts`のウォーカー用パターンを1つから2つ（足を揃えた
`WALKER_PATTERN_STAND`、足を開いた`WALKER_PATTERN_STEP`）に分割し、
`drawWalkerSprite`に`stepping: boolean`引数を追加してどちらを描くか
選べるようにした。

`EntityLayer.ts`に純粋関数`walkCycle(elapsedTime, pos)`を追加。
ウォーカーごとの座標からその場で位相オフセットを計算する
（`pos.x*3 + pos.y*5`）ため、追加の状態管理なしに全軍が同時に
足踏みする不自然さを避けられる。`Math.sin(phase)`の符号で2コマを
交互に切り替え、`Math.abs(Math.sin(phase))`で0〜1pxの上下の揺れ
（bob）を作る。リーダーの後光（halo）も揺れに追従させた。

`EntityLayer.update()`は`deltaSeconds`を新たに受け取り内部で積算する
（`main.ts`の`entityLayer.update(simulation.world, deltaSeconds)`）。
ウォーカーが実際に移動中かどうかは判定しておらず、常に揺れ続ける
「アイドル状態でも小さく動いている」という扱いにした——歩行状態の
判定（MoveTargetの有無など）を追加する設計は今回のスコープ外。

## テスト

- `EntityLayer.test.ts`（新規）：`walkCycle`の純粋な数値ロジックを
  直接テスト。2コマが時間経過で両方出現すること、bobが0〜振幅の範囲に
  収まること、座標が違えば同時刻でも位相がずれること、同じ入力には
  同じ結果を返すこと（決定的であること）を確認。PixiJSの`Graphics`
  自体の描画結果はこのプロジェクトの既存方針通りテスト対象外。
- `npm run typecheck` / `npm run test -- --run`（222件）/
  `npm run build`がすべて成功。
- ヘッドレスブラウザで実際の試合を45秒間走らせ、`deltaSeconds`を
  毎フレーム`EntityLayer`に渡すよう変更した後もコンソールエラーが
  発生しないことを確認。

## 残作業

- ウォーカーが実際に停止しているか移動しているかで演出を変える
  （立ち止まっているときはbobをやめる、など）はまだ未実装。
- 戦闘・建築・逃走といった行動ごとに異なるアニメーションを持たせる
  ことは、レビューが指摘した「生活感」への対応としてまだ大きく
  残っている。今回はその最初の一歩（常時の歩行アニメーション）のみ。
