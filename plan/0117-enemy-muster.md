# 敵に出撃前の編成をさせる

## 計測（前回の調査の続き）

「敵の民・英雄が奪った家は0軒」の原因は調整不足ではなく、**算術的に
不可能**だった。

`combat.ts` は `walker.strength > HOUSE_LEVELS[level].defense` のときだけ
家を奪い、そうでなければ**攻撃側が死ぬ**。防御力は小屋3・中規模6・
大きな家12・城砦20。

最終戦線・3試合・10分の全サンプルで、

| 経過 | 敵ウォーカー | 最大強さ | 平均強さ | 小屋を奪える数 |
|---|---|---|---|---|
| 120秒 | 17 | **1** | **1** | **0** |
| 240秒 | 36 | **1** | **1** | **0** |
| 480秒 | 28 | **1** | **1** | **0** |

**強さは常に1**。`1 > 3` は成立しないので、敵の民は家に触れた瞬間に
死ぬだけだった。

## 強さ1を超える手段は集結だけ

- `gather.ts` の合流だけが強さを**足し算**する（`a + b`）
- `HERO_TRAITS` は**倍率**なので、強さ1の民が英雄になっても1
  （ヘラクレスで2）。**守護者は小屋にすら勝てない**
- `populationRelease` は `population / capacity * 0.75` で**最大0.75**。
  当初これを使う案を出したが、読み違えだった（比率であって人口ではない）

強制的に集結モードへ固定して計測すると、敵の最強ウォーカーは
**3分で3を超え、8分で20〜51**まで育つ。機構は動いていた。使われて
いなかっただけである。

## 変更

出撃条件（ウォーカー数と経済フロア）を満たしても、**相手の一番弱い家を
奪える民ができるまで集結**し、できてから戦闘へ移る。

- 攻め込まれているときは編成を待たない（防衛が最優先なのは従来通り）
- 相手に家が1軒も無いときは編成しない。残っているのが民だけなら、
  民同士の戦いに強さの下限は無い

プレイヤーは 集結 → 戦闘 と自分で切り替えられる。敵にその段階が無かった。

## 効果（最終戦線・無操作・3試合×8分）

| | 変更前 | 変更後 |
|---|---|---|
| **敵が奪ったプレイヤーの家** | **0** | **3** |
| 敵が破壊した家（奇跡以外） | 26 | 35.3 |
| 奇跡1回あたりの家の損失 | 1.05 | 1.58 |

**0から3へ**——「不可能」から「起きる」への変化である。数として小さい
のは、`combat.ts` が**奪った側のウォーカーを消費する**ためで、強さ50の
部隊でも奪えるのは1軒だけだから。**編成した部隊を大きくしても意味が
無い**という構造で、これは別の設計判断（強い部隊は生き残って進軍を
続けるべきか）なので今回は触っていない。

## 検証

- 701 → 705テスト。`enemyAi`（**家を奪える民が居ないうちは集結する**／
  居れば出撃する／相手に家が無ければ編成しない／**弱くても攻められれば
  応戦する**）
- `simulation.test.ts` の気質テストは、AIが「編成へ行け」と判断して
  `fight` を上書きするようになったため、リーダーの強さを4にした
  （`totalPopulation` は強さに関わらず1人と数えるので、テストが見ている
  人口比は動かない）
- typecheck / build / `sprites:check` / `palette:check` 通過
- 実機確認なし。効果が出るのは数分後の敵の内部状態で、描画にもUIにも
  触れていないため、上のヘッドレス計測の方が証拠として強い
