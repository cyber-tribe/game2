# 0125 wall-lets-leader-pass

## 背景

`docs/original-miracles.md` #12 の城壁の項は、当初から食い違いを抱えたまま
記録されていた。

> 12 城壁：信者の進行を遮る壁。英雄以外は越えられない
> **（資料により「敵リーダー・英雄だけが越えられる」とも）**

game2 は狭い方（英雄だけ）を実装していた。原作記事を取得したところ、
一次資料の記述は広い方だった。

> 城壁：**敵リーダー・ヒーロー以外**の信者を遮る効果を持つ。

したがって越えられるのは**リーダーと英雄の2種類**である。

## なぜこの差が効くか

括弧書きの但し書きを解消するだけの話ではない。game2 の構造では、
リーダーは次の2つを同時に担っている。

- **英雄になる唯一の存在**（`hero.ts` の `promoteHero` はリーダーを昇格
  させる）
- **集結の中心**（`goToShrine.ts` で、他の民はリーダーへ向かう）

つまり狭い読みのままだと、`WALL_MANA_COST`（小）の奇跡ひとつでリーダーを
囲い込むだけで、その勢力から**英雄を作る能力そのもの**を奪えてしまう。
1つの英雄を止めるどころか、以後すべての英雄を止められる。値段と効果が
釣り合っていない。

広い読みはこの穴を塞ぐと同時に、原作の記述そのままでもある。

## 変更

`createMovementSystem` の `blockable` 判定に「現在どこかの勢力のリーダーで
ある」を追加した。判定は毎tick `FactionState` から `leaderId` を集めた
`Set` で行う。

「敵リーダー」の「敵」は壁を築いた側から見た表現なので、陣営を問わず
リーダーは越える（自陣の壁に自陣のリーダーが引っかかるのも同じく不自然
である）。

壁の上に立ってしまった民がその1歩だけ壁を無視する既存の扱い（生き埋めに
できてしまわないための措置）はそのまま。

## 検証

`src/game/systems/movement.test.ts` に追加。

- 勢力のリーダーが壁を直進して越えること
- 同じ勢力の**普通の民**は従来通り止まること
  （「リーダーが居る勢力は全員通れる」になっていないこと）

既存の「英雄は越える」「普通の民は迂回する」「壁の中から出られる」などは
そのまま通る。

`npm run typecheck` / `npm run test`（748件）/ `npm run build` すべてパス。
