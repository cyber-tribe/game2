# 0127 bottomless-swamp-look

## 背景

`plan/0124-bottomless-swamp.md` で、原作の「面ごとに底なしかどうか設定される」
に合わせて沼を2種類にした。しかし**見た目を分けていなかった**。

実際に動かして確認したところ、底なし沼と通常の沼は完全に同じ絵で描かれて
いた。これは自分で入れた欠陥である。

## なぜ直す必要があるか

2種類の挙動はまったく違う。

| | 通常の沼 | 底なし沼 |
|---|---|---|
| 何人飲み込むか | `SWAMP_CAPACITY`（5）で枯れる | 無制限 |
| その土地は | いずれ戻る | 試合が終わるまで戻らない |

沼に対してプレイヤーが下す判断は事実上ひとつしかない——「ここをまだ通せるか」。
その答えが種類によって正反対なのに、見て区別できなかった。**見られて避けられる
ことが仕事の地形**で、見ても分からないというのは機能していないのと同じである。

原作が両者を別の名前（底なし沼）で呼んでいることも、区別されるべきものだと
いう傍証になる。

## アプローチ

同じ泥が**黒く深くなった**ものとして描く。別の物質にはしない——読み取って
ほしいのは深さであって、材質の違いではない。

- 泥のディザを `0x352336 / 0x201522` → `0x1a0f1c / 0x0d060e` へ落とす
- 穴を、タイルごとに散らばる小さいもの2つ（半径2）から、**タイル中央の
  大きいもの1つ**（半径5）へ変える

穴の扱いが効く。散らばった小穴は「模様」に見えるが、中央にひとつ開いた
大きな穴は「深さ」に見える。底なしの穴という、底なし沼が目に見えて持って
いる唯一のものがこれである。

泡（`SWAMP_BUBBLE_PERIOD`）は両方に残した。どちらも生きている沼である。

## 実装

描き分けの判断は `swampVisual(bottomless)` という純粋関数へ出した。
`impactEffectVisual` と同じ方式で、Graphics やキャンバスなしで単体テスト
できる。

## 検証

- `swampVisual` が2種類で違う塗りを返すこと
- 底なしが「中央に1つ・より大きい穴」、通常が「散らばった複数・より小さい穴」
  になること

さらに、実機（`npm run dev` + ヘッドレスChromium）で両方を並べて描画し、
一目で区別できることを目視確認した。左＝通常（紫がかった泥に小さな斑点）、
右＝底なし（ほぼ黒く、タイルごとに大きな空洞）。

`npm run typecheck` / `npm run test`（753件）ともにパス。
