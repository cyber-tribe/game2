# 0093 コマンドアイコンのアトラス化と描き直し

## 背景

ご指示 §5（Emoji全面廃止）で導入したコマンドアイコンを、§26 に沿って
sprite atlas へ移す。ただし本タスクの主目的は移行そのものではなく
**アイコンが読めないこと**の解消である。

実際のパネルを実寸で確認したところ、19個中およそ半数が判読できなかった:

| アイコン | 旧状態 |
| --- | --- |
| 集結 | 点が散っているだけ。方向がない |
| 戦闘 | 細い折れ線1本。何にも見えない |
| 地震 | 短い線の散らばり。地面がないので「亀裂」に見えない |
| 最終決戦 | 点の散らばり |
| 騎士化 | 1pxの斜線。傷にしか見えない |
| 沈降 | 細い楔 |

加えて全体に、ボタン地色（`--stone-mid` `#7f6f4d`）に対して**コントラストが
不足**しており、輪郭のないアイコンが地に沈んでいた。

## パターンを直接書く

`src/ui/pixelIcons.ts` の手続き描画（`fillCircle` / `drawLine` /
`fillMountain` と各アイコンの描画呼び出し、約270行）を捨て、
`tools/sprites/icons.py` に**16x16のパターン文字列**として書き直した。

この規模では**アイコンとはそのピクセルそのもの**であり、計算すべき形状は
ない。パターンがソースであり、同時にレビュー対象そのものになる。

貫いた2つの規則:

1. **すべてのアイコンにinkの輪郭を付ける。** 地色が中間調の石なので、
   暗い縁がないものは沈む。
2. **意味はシルエットが担う。** 色は第2チャンネル（溶岩のオレンジ、水の
   ティール、陣営の青）であって唯一の手がかりにはしない。パネルは無効な
   ボタンを減光するので、色に依存したアイコンは**プレイヤーが最も知りたい
   ときに読めなくなる**。

## 検証の置き場所を移した

`pixelIcons.test.ts` にあった3つの検査 ——「16x16であること」「空でない
こと」「シルエットが重複しないこと」——は、パターンが絵そのものになった
以上、**その欠陥は Python 側のファイルの欠陥**である。`icons.py` の
`_validate()` へ移した。CI は `npm run sprites:check` で全シートを
ビルドするので、そこで必ず走る。

TS側には他のアトラスと同じ**双方向のキー照合**を残した。

4種類の欠陥（空・シルエット重複・サイズ違い・凡例にない文字）を実際に
注入して、すべて `ValueError` で止まることを確認している。
**この確認で空アイコンの検査が機能していないバグが見つかった** —
`"|".join(...)` の区切り文字が残るため `strip()` が空文字列にならず、
全面透明でも通過していた。

## 読み込み

アイコンは起動時に1度 `<canvas>` へ描くだけ（毎フレームではない）なので、
アトラス画像を1枚デコードして `drawImage` でサブ矩形を切り出す方式にした。
DOM のツールバーはそのままで、Pixi 化はしていない。

`loadCommandIcons()` を `main.ts` で `EntityLayer.loadAssets()` と
並列に await する。解決前の `paintIcon` は例外ではなく no-op にした。
一瞬アイコンが出ないことより起動時クラッシュの方が悪い。

## 検証

- `npm run typecheck` 通過、`npm run test -- --run` 462件通過
- `_validate()` が4種類の欠陥をすべて捕捉することを注入して確認
- `npm run sprites:check` — クリーンで exit 0
- `npm run build` 成功
- 実ゲーム画面のツールバーを実寸で確認。上記6個を含む全19個が
  判読できること、無効時の減光状態でも形が残ることを目視確認。
  ステータス行のマナ・人口アイコンも同じアトラスから描かれている。
  コンソールエラー0件

## 残っている点

`集結` は「内向きの矢印」で方向は出せたが、他のアイコンほど一目で
分かるとは言い難い。4方向の斜め矢印にした最初の版は中央で交わって
ただの X に見えたため今の形にしている。より良い比喩があれば差し替える
余地がある。
