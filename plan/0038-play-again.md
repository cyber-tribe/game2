# 0038 play-again

## 背景

「game2 第3回 敵対的検証」の結論：コードレビューでの検証はそろそろ
限界に近く、次に価値があるのは実際の人間によるプレイテストそのもの。
その具体的な観測手法として、レビューは「もう一度遊びますか？」と
直接尋ねるのではなく、試合終了後に「再戦」ボタンをただ置いておき、
プレイヤーが誰にも促されず自発的に押すかどうかを見る——
「自発的再戦率」を主要KPIとして扱う——ことを提案している。

このゲームには現状「もう一度遊ぶ」導線が一切なく（`plan/0037`の
残作業にも記載の通り、試合終了後は`#match-record`が出たきり何も
起きない）、上記の観測手法を試すための前提条件そのものが欠けている。
これは新機能というよりプレイテストのための最小限のインフラであり、
レビュー自身が「プレイテストまでは新機能を増やすな」と勧める対象
ではないと判断し、ユーザーの承認を得て実装した。

## アプローチ

`#match-record`パネル内、スクロールする`#match-record-list`の
「外」（下に固定表示される兄弟要素）として「もう一度遊ぶ」ボタンを
追加した。リストの中に置くとスクロールしないと見えない場合があり、
ボタン自体が押されたかどうかを観測したいので常に見える位置に置く
必要がある。

クリック時の処理は`window.location.reload()`のみ。`Simulation` /
`IsoRenderer` / `EntityLayer` / `Minimap`や`main.ts`内のクロージャ
状態（zoomFactor、rotation、shake、toast、matchRecordShownなど）を
individually teardown/rebuildする案も検討したが、この機能の目的は
「自発的に再戦ボタンを押すかどうかを見る」ための観測インフラであって
シームレスな遷移演出ではないため、複雑さとバグリスクを避けて
最も単純な手段を選んだ。リロードにより新しいheightmapのロールを
含む完全に新しい試合が始まる。

## テスト

- `npm run typecheck` / `npm run test -- --run`（226件）/
  `npm run build`がすべて成功。
- ヘッドレスPlaywrightで`#match-record`を直接表示させ、
  `#play-again`ボタンが見つかること、クリック可能であること、
  クリックによって実際に`load`イベントが再発火する（＝実際に
  ページがリロードされる）ことを確認した。
