# 0051 miracle-sound-effects

## 背景

POPULOUS 2との比較調査で、原作の重要な工夫として「奇跡ごとに固有の
効果音があり、敵味方どちらが使ってもその音が鳴る」ことが挙げられて
いた。プレイヤーは画面外で何が起きたかを音だけで判断し、すぐ反応する
か後回しにするかを決められる——単なる演出ではなく情報UIとして機能
している、という指摘。

現状のgame2は、奇跡発動時に振動（`vibrate()`）とトースト表示はある
ものの、音による合図が一切ない。特に敵AIが画面外で奇跡を使った場合、
トーストを見逃せば気づく手段がなかった。

## アプローチ

音源ファイルを追加する代わりに、`src/audio/miracleSounds.ts`で
Web Audio APIによる短い効果音をその場で合成する方式にした
（バイナリのアセットファイルを一切追加しない）。

- `MiracleSoundType`は`docs/game-system.md`のマナコスト階層に対応する
  7種類（`shrineMove`/`earthquake`/`swamp`/`volcano`/`knight`/
  `armageddon`/`flood`）——`main.ts`が既存の`vibrate()`を呼んでいる
  箇所と完全に一致する（`raise`/`lower`の地形編集は、`vibrate()`自体が
  そうしているのと同じ理由で対象外：あまりに頻繁な基本操作のため）。
- 各奇跡は「オシレーター（音程スイープ）のレイヤー」＋任意で「ノイズ
  （フィルタ付きの短いホワイトノイズバースト）」の組み合わせとして
  `RECIPES`にレシピ形式で定義。波形の種類・周波数の上下方向・トーン
  かノイズかを奇跡ごとに変えることで、音量だけでなく音色そのもので
  聞き分けられるようにした（例：地震＝低いsawtoothの下降＋低域ノイズ、
  騎士化＝高めのsquareの短い2連打、最終決戦＝2回に分けて重なる低音＋
  長めのノイズ）。
- `playMiracleSound(type)`が、共有の`AudioContext`を遅延生成・
  （サスペンド状態なら）再開し、レシピからオシレーター/ノイズノードを
  組み立てて再生する。`vibrate()`と同じ「ベストエフォート」方針
  ——Web Audioが使えない環境（`window`が存在しない/`AudioContext`が
  ない）では静かに何もしない。

### 敵の奇跡にも同じ音を鳴らす

`main.ts`の`onEnemyAction`（画面外で敵が奇跡を使った際にトースト＋
カメラシェイクを出す既存の仕組み）に`playMiracleSound(event.type)`を
追加した。プレイヤー自身の発動と敵の発動、どちらでも同じ音が鳴る
——「音だけで何が起きたか分かる」という原作の狙いをそのまま再現する
ため、視覚的な演出だけを敵アクションに紐付けていた既存の非対称を解消
した形。

`main.ts`の変更は、7箇所の`playMiracleSound(type)`呼び出し追加と、
`onEnemyAction`への1行追加のみ。

## テスト

- `src/audio/miracleSounds.test.ts`：
  - 7種類すべてに対応するレシピが存在すること。
  - 各レシピが少なくとも1つの音源レイヤー（トーンかノイズ）を
    持つこと。
  - トーン/ノイズレイヤーの時間・音量・周波数がすべて正の有限値
    であること。
  - 最終決戦（最高コスト）の総再生時間が、集結地移動（最低コスト）
    より長いこと——マナコストの階層と音の存在感が対応していることの
    簡易チェック。
  - `playMiracleSound`がこのテスト環境（`window`なし）でも例外を
    投げないこと。
- `npm run typecheck` / `npm run test -- --run`（256件）/
  `npm run build`がすべて成功。
- ヘッドレスChromiumで実際に7種類すべての`playMiracleSound`を呼び、
  エラーが出ないことを確認。さらに`AudioContext.prototype.
  createOscillator`を計装した上で実際にツールバーの「集結地移動」を
  タップして地形をタップし、本物のUI操作フロー（タップ→
  `applyTool`→マナ消費→`playMiracleSound`）でオシレーターが1つ
  生成されることを確認した（レシピ通り、shrineMoveはトーン1層のみ・
  ノイズなし）。

## 残作業

- ミュート/音量調整のUIはない（`vibrate()`にも同様のトグルがない
  ことに合わせた）。
- 家の奪取・焼き討ち・戦闘死・溺死（PR「戦闘・奪取・焼き討ち・溺死に
  破壊演出を追加」で視覚演出を追加した4種）には専用の効果音を付けて
  いない。これらは奇跡そのものではなく、その結果として頻繁に起こる
  出来事であり、単発の奇跡ほど「音で聞き分ける」価値が薄いと判断した
  ため、今回のスコープからは意図的に外した。
