# 隆起/沈降を頂点単位の編集に戻す

## 背景

ユーザーから「操作するのは1面ずつにしてください。今はタップすると
周りがまとめて動きます」との指摘。確認したところ、具体的には
「1タップでも隣接タイルが少し傾く」ことを指しているとのこと。

`plan/0065-tile-based-terraform.md`で、隆起/沈降の対象を頂点
（`raiseVertex`）からタイル全体（`raiseTile`、そのタイルの4頂点すべて）
に変更していた。当時のユーザーの要望「高さを上げ下げするポイントは
点ではなく原作同様に面にしたい」に応えたもので、意図は正しかったが、
1つのタイルの4頂点はそれぞれ最大3つの**別の**タイルとも共有されて
いるため、1回のタップで最大8枚もの隣接タイルの見た目がわずかに
傾いてしまい、「タップすると周りがまとめて動く」という体験になって
いた。

`plan/0065`が頂点編集をやめた理由（「頂点は最大4つのタイルに共有される
ため、1回の編集が中途半端に隣接タイルの平均高度をずらし、境界に
細かい段差が発生していた」）は、当時の地形描画（`plan/0064`のタイル
平均値ブロック表現）を前提にしたものだった。その後`plan/0073`の
一連の対応で、地形描画は頂点ごとの傾斜メッシュ（各頂点の実高度を
そのまま使う）に作り直されており、タイルを平均値で丸めてブロック化
する処理自体がもう存在しない。つまり`plan/0065`の問題は前提ごと
解消されており、頂点単位に戻しても当時の「境界の段差」問題は
再発しない。

## 対応

`main.ts`の隆起/沈降を、`pickTile`+`raiseTile`から`pickVertex`+
`raiseVertex`に戻した。影響を受けた3箇所（単発タップ・ブラシの
長押し開始・ブラシのドラッグ継続）はすべて新設の
`pickTerrainEditPoint(localX, localY)`に集約し、`toolMode`に応じて
隆起/沈降なら頂点、平坦化ならタイルを返すようにした。

「平坦化」は今回変更していない——平坦化はそもそも「区画を均す」という
面（エリア）単位の操作であり、タイル全体を対象にすることは違和感が
ない（むしろ隣接タイルへの波及こそ「広い区画を一度に均す」という
機能の一部）。隆起/沈降のような「1点を少しだけ動かす」操作とは
性質が異なるため、こちらだけを頂点単位に戻した。

内部的には、旧`applyTerrainEditAt(tile)`を`applyFlattenEditAt(tile)`と
`applyRaiseEditAt(vertex)`に分割し、`applyTerrainEditAt(point)`は
`toolMode`に応じてどちらかへ委譲するだけの薄いディスパッチャにした。

なお、リファクタ中に`#82`（面ごとの敵地干渉制約）とのマージ由来で
`applyRaiseEditAt`内の敵地チェックが未定義の`tile`変数を参照する
バグが混入していたため、`vertex`を参照するよう修正し、同じチェックを
`applyFlattenEditAt`側にも追加した（平坦化も地形操作である以上、
敵陣地への直接干渉制約は同じく適用されるべきため）。

## 検証

- `npm run typecheck` / `npm run test -- --run`（436件）/
  `npm run build`: すべて成功。
- Playwright（chromium）で実機確認: ズームインした状態でマナを
  貯めてから隆起ツールで同じ地点を複数回タップしたところ、
  タイル全体が持ち上がるブロック状ではなく、1点から尖った山のように
  盛り上がる、より局所的な変化になったことを確認。隆起/沈降/平坦化を
  連続して操作してもコンソールエラーは無かった。
