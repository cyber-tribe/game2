# 0119 auto-flatten

## 背景

原作記事を取得できたことで（`docs/original-miracles.md`の冒頭を参照）、
奇跡以外の記述も突き合わせられるようになった。原作の**評価点**には
「操作性の良さ」として次の2つが名指しで挙がっている。

> 自動整地（Xボタンで建物を中心に7x7マスの平地を確保）、スプログ（建物の
> 中心にカーソルを合わせてBボタンを押すと、信者の一部が追い出される）等、
> 操作性も練られている。

このうち**自動整地**が game2 に無い。game2 の「平坦化」はブラシで、
プレイヤーがタイルの上をなぞり、最初に触れたタイルの高さへ順に均していく。
動作としては正しいが、家が城砦へ育つだけの平地を確保するには49マスを
正確にドラッグする必要があり、原作が建物へ向けた1回のボタンで渡している
ものをプレイヤーの手作業に置き換えていた。

奇跡の数の問題ではなく、原作が「練られている」と評価された操作性そのものが
欠けていたことになる。

## アプローチ

### 何を狙うか

原作は「**建物を中心に**7x7マスの平地を確保」である。地面ではなく**家**を
狙う。これが1タップで済む理由でもある——どこを均すかは家が決めるので、
プレイヤーは範囲を指定しなくてよい。自分の家だけを対象とする。自陣の村を
手入れするための近道であって、敵の足元を作り替える手段ではない。

### 高さの決め方

対象の高さは**中心タイルだけ**から取る。7x7全体を平均すると、整地して
やりたいその家の足元が動いてしまう。中心を基準にして周りをそこへ合わせる。

`terrainEditRule`の扱いは平坦化のブラシと同じで、`raiseOnly`なら中心タイルの
最高角、`lowerOnly`なら最低角、`both`なら平均。ただし**平均は丸める**。
ブラシの目標値は「ストロークの起点タイルがたまたま平均した値」でよいが、
「平地を確保する」ツールが端数の高さへ均すと、同じ家をもう一度押したときに
全タイルが永久に「まだ均されていない」と判定されてしまう。

### 値段

`TERRAIN_EDIT_MANA_COST` × **実際に動くタイル数**。手作業と同じ値段であり、
これは操作性の近道であって整地の割引ではない。実際に動くタイルだけを数える
ので、すでに平らな家をもう一度押しても0マナで、「すでに平地です」と返る。

支払い前に総額を確定して`trySpendPlayerMana`へ渡すので、マナが足りなければ
地形に触れる前に必要量つきで断られる。

### 敵陣地の制限

面によっては敵の陣地を直接操作できない（`WorldDefinition.enemyTerritoryEditable`）。
7x7が境界をまたぐ場合、禁止されたタイルは**計画から落とす**。整地できる側は
整地され、落とした分は課金もされない。キャスト全体を失敗させるより、
プレイヤーの意図（自分の家の周りを均す）に沿う。

### 実装の分け方

`planAutoFlatten`は地形を**変えない**。目標高さと「実際に動くタイル」の一覧を
返すだけの純粋関数で、`src/world/heightmap.ts`に置いた。main.ts側が
それを見て課金し、`flattenTile`を順に呼ぶ。値段を確定してから地形へ触る、
という順序を型で守れる。

`isEditable`述語を引数に取ることで、敵陣地の規則（simulation側の知識）を
heightmapへ持ち込まずに済ませている。

### UI

`#toolbar`に「自動整地」ボタンを追加し、`ALWAYS_VISIBLE_TOOLS`へ入れた
（隆起/沈降/平坦化と同じ、系統に属さない地形ツール）。アイコンは
`tools/sprites/icons.py`に16x16パターンを追加。平坦化の矢印を流用すると
「土地を均す」とは言えても「どこを」が言えず、2つのボタンの違いが
出ないため、家を四隅の杭が囲む図にした。

## 検証

`src/world/heightmap.test.ts`に`planAutoFlatten`のテストを追加。

- 中心の周り`AUTO_FLATTEN_SIZE`四方をすべて計画すること
- 目標高さを中心タイルから取ること（周囲の高地に引きずられないこと）
- 適用後、区画の内部が1つの段丘になること
- すでに平らな地面では何も計画しない（＝2度目は無料）こと
- マップ端では区画がはみ出さずに切り詰められること
- `isEditable`が禁じたタイルを落とし、残りは計画すること
- `raiseOnly` / `lowerOnly`で目標高さが中心タイルの最高角／最低角になること

`npm run typecheck` / `npm run test`（722件）/ `npm run sprites:check` /
`npm run build` すべてパス。

## 残り

原作が名指しで挙げているもう一方の**スプログ**（建物1軒を狙って信者の
一部を追い出す）は別PRとする。game2の「送出」は勢力の全戸を一括で
空にする独自のもので、原作の1軒ずつ狙う操作とは別物である。
