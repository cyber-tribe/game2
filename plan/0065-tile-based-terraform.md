# 0065: 地形の隆起/沈降を頂点ではなくタイル（面）単位にする

## 背景

`plan/0064-terraced-terrain.md`で地形描画を断層（テラス状のブロック）表現に
変更した直後、ユーザーから追加要望があった。

> あと高さを上げ下げするポイントは点ではなく原作同様に面にしたいです

これまでの地形編集（隆起/沈降ツールの単発タップ・ブラシ長押し）は
`IsoRenderer.pickVertex`でグリッドの頂点（点）を選び、`raiseVertex`で
その1頂点だけを上げ下げしていた。頂点は最大4つのタイルに共有されるため、
1回の編集が中途半端に隣接タイルの平均高度をずらし、境界に細かい段差が
発生していた（`plan/0064`の「単一タイルの隆起も隣接タイルの平均高度に
波及する」という観察と同根の問題）。断層描画でタイルがブロックとして
表現されるようになった以上、編集も「面（タイル）」単位で行うほうが、
原作Populousの地形操作の感覚に近く、テラス表現ともかみ合う。

## 設計

- `world/heightmap.ts`に`raiseTile(heightmap, tileX, tileY, delta)`を追加。
  既存の`raiseVertex`をそのタイルの4頂点ぶん呼び出すだけの薄いラッパーで、
  クランプ・rockHardnessの削り取りなど既存の1頂点あたりのロジックは
  そのまま再利用する。
- `render/IsoRenderer.ts`に`pickTile(localX, localY, maxDistance)`を追加。
  `pickVertex`のタイル版で、各タイルの中心（screen座標）までの距離が
  最も近いタイルを返す。タイル中心の高さは4頂点の平均で、これは
  `sampleElevation(heightmap, x+0.5, y+0.5)`のバイリニア補間が
  ちょうど計算する値と一致するため、平均を再実装せずそのまま利用した。
- `main.ts`の隆起/沈降ツール（`applyTerrainEditAt`・単発タップ・ブラシ
  長押しの3箇所）を`pickVertex`+`raiseVertex`から`pickTile`+`raiseTile`に
  差し替えた。地震・洪水・火山・沼・神殿移動など他の奇跡は「点」を狙う
  操作として意味があるため、そちらは`pickVertex`のまま変更していない。

`raiseTile`は4頂点それぞれに同じdeltaを足すだけで、タイルを強制的に
平らにするわけではない（元々4頂点の高さがバラバラなら、editの後も
バラバラなまま同じ量だけ底上げされる）。原作でも「タイルを均す」のは
繰り返しタップして徐々に平らにしていく操作であり、1回のタップで
自動整地する機能ではないため、この挙動は意図通り。

## 検証

- `npm run typecheck` / `npm run test -- --run`（341件）/ `npm run build`
  すべて通過。
- `heightmap.test.ts`に`raiseTile`のテストを追加（対象タイルの4頂点だけが
  動く、既に平らなタイルは平らなまま、頂点ごとに独立してクランプされる、
  頂点ごとにrockHardnessが削れる）。
- `IsoRenderer.test.ts`に`pickTile`のテストを追加（タイル中心に最も近い
  タイルを返す、中心から外れたタップでも同じタイルに丸められる、
  maxDistanceを超えるとnull、隆起したタイルでも実際の高さに沿って
  ピックする）。
- headless Playwrightで実機シナリオを検証: 既知のタイルを平らにしておき、
  隆起ツールで1回タップした結果、そのタイルの4頂点すべてがちょうど+1
  され、隣接する別頂点（そのタイルの4隅に含まれない頂点）は変化しない
  ことを確認した。ブラシ（長押し+ドラッグ）でも複数タイルにまたがって
  同様の編集が発生することをスクリーンショットで確認した。
