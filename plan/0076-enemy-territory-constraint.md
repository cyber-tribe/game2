# 面ごとの敵地干渉制約

## 背景

ユーザーからのフィードバック「敵陣地や敵信者へ直接土地の上げ下げで
干渉できるかは面によって制約がある」を受けて調査したところ、
`terrainEditRule`は隆起/沈降の**方向**（両方/隆起のみ/沈降のみ）しか
制限しておらず、**誰の土地を編集できるか**という制約は一切存在しない
ことが分かった。プレイヤーはどの面でもマップ上のどこでも（自陣が
画面内に見えている限り）自由に地形を編集でき、敵の家をいきなり
海に沈めるような直接干渉が常に可能だった。

なお、`enemyTerraform.ts`（敵AIの地形操作）はそもそも自分の家の
周辺しか編集しないため、逆方向（敵がプレイヤーの土地を直接操作する）
の制約は最初から考える必要がなかった。

## 対応

### `src/game/worlds.ts`: `WorldDefinition.enemyTerritoryEditable`

`terrainEditRule`と同じ「面ごとのルールバリエーション」という考え方で
新しいboolean軸を追加。既存の5ワールドは`true`（今まで通りどこでも
編集可能）のまま、最終ワールド「最終戦線」だけ`false`にした
（他の軸と同じ「一度制限されたら緩まない」単調性を維持）。

「陣地」の定義には、`EntityLayer`が既に家の周囲に描画している
農地ティント（`FARMLAND_RADIUS`、"視覚的に勢力圏を示す"という既存の
doc commentがある）をそのまま流用した——新しい概念を持ち込むのではなく、
プレイヤーに既に見えている「この家の周りは陣地」という表現と地形操作の
制約を一致させた。

### `src/game/simulation.ts`: `Simulation.isEnemyTerritory`

タイルの中心点が、指定faction以外の所有する家の`FARMLAND_RADIUS`
以内にあるかを判定する読み取り専用メソッドを追加。

### `src/main.ts`: `applyTerrainEditAt`

`world.enemyTerritoryEditable`が`false`のワールドで、対象タイルが
`simulation.isEnemyTerritory("player", tile)`に該当する場合、マナを
消費する前に「この面では敵の陣地を直接操作できません」を表示して
編集を止めるようにした（`isOwnFactionVisible`のチェックと同じ位置・
同じパターン）。

## 検証

- `npm run typecheck` / `npm run test -- --run`（415件、`isEnemyTerritory`
  の新規テスト2件と`WORLDS`の単調性テスト2件を含む）/ `npm run build`:
  すべて成功。
- Playwright（chromium）で実機確認: パスワード「final-frontline」で
  最終ワールドをアンロックして開始し、コンソールエラーが出ないことを
  確認。敵の家がその時点で存在しなかった（敵AIが攻撃的で家を維持
  できていなかった）ため、実際に制約が発動する瞬間そのものは
  ブラウザ上では再現できなかったが、`isEnemyTerritory`の幾何判定は
  単体テストで直接検証済みで、それ以外のワールド（`enemyTerritoryEditable
  : true`）では本セッション内の他の検証（マナフィードバック・平坦化
  ツール）で隆起/沈降/平坦化を多数回実行しており、新しいチェックが
  通常時の編集を誤ってブロックしていないことも合わせて確認できている。
