# 段階的な溺死モデルの実装

## 背景

ユーザーからの一連のフィードバックのうち以下3点:

- 「4マス水が正方形に出来るとその中にいる人は溺れる」
- 「基本は溺れてもエネルギーが0になるまでは生きており陸に上がると
  普段の動きに戻る」
- 「溺れるとすぐに死ぬなどの制約のある面もある(海がマグマなど)」

を受けて調査したところ、現状の溺死判定は`drownFlood`（洪水の魔法を
使った瞬間だけ、その場で水没している家/民を即座に破壊）と
`swampSystem`（沼の範囲内の民を即座に破壊）の2箇所にしか存在せず、
**通常の地形操作（隆起/沈降/平坦化）で土地を水面下に沈めても、そこに
立っている民には一切何も起きない**ことが分かった。`isBuildable`の
doc commentには元々「通常の民は入ると溺れる」と書かれていたにも
関わらず、実際にはどこにも実装されていなかった。

## 対応

### `src/world/heightmap.ts`: `isInWaterPool`

タイル(x, y)を含む4通りの2x2ブロックのいずれかが全て水没している
（`isWaterTile`、レンダラーの水タイル判定と同じ基準）かを判定する
関数を新設。「4マス水が正方形になると」という表現の通り、水際の
1マスだけがたまたま沈んでいるケースは対象外とし、実際にまとまった
池ができた場合だけを危険とみなす。

### `src/game/components.ts`: `Drowning`

水没中の民にだけ付与される新しいコンポーネント。`breath`（残り秒数）
を持ち、陸に上がると即座に（`world.remove`で）取り除かれる——
「陸に上がると普段の動きに戻る」を素直にコンポーネントの有無で表現。

### `src/game/systems/drowning.ts`: `createDrowningSystem`（新規）

毎ティック、`isInWaterPool`内にいる民から`DROWNING_BREATH_SECONDS`
（4秒、`DEFAULT_WALKER_SPEED`で6マス分の移動時間に相当）を1秒ずつ
減らし、0になった時点で破壊+`drowned`インパクトを報告する。
`instant: true`が渡された場合は猶予なしで即死する（後述）。
`swampSystem`と同じく騎士/守護者は免除（`isHeroState`）。
家はこのシステムの対象外——建物は陸に泳いで逃げられないため、
従来通り`drownFlood`側の即死のまま変更していない。

`Simulation`に`instantDrowning`設定を追加し、`heightmap`が
渡されなければ何もしない（`enemyTerraform.ts`と同じパターン）。

洪水（`drownFlood`）・沼（`swampSystem`）自体の挙動はあえて変更して
いない——これらは既存のdocs/game-system.mdで明示的に即死として
設計された、独立した魔法の効果であり、今回のフィードバックが指す
「普通の地形操作で沈んだ水」とは別物と判断した。

### `src/game/worlds.ts`: `WorldDefinition.instantDrowning`

「面によっては即死の制約もある(海がマグマなど)」に対応する新しい軸。
このコードベースでは既に`terrain: "rock"`が「溶岩地帯」を表す
（`TERRAIN_LABELS`・`TERRAIN_GROWTH_MULTIPLIER`のdoc comment）ため、
新しい概念を持ち込まず、rock地形のワールド（灰の荒野・最終戦線）だけ
`instantDrowning: true`にした。他の軸のような単調な「難易度カーブ」
ではなく、地形タイプに紐づく性質として扱っている（テストでもその旨
明示）。

### `src/main.ts`

`new Simulation({...})`に`world.instantDrowning`を渡すだけ。

## 検証

- `npm run typecheck` / `npm run test -- --run`（426件、`isInWaterPool`
  の新規テスト4件、`createDrowningSystem`の新規テスト9件、`WORLDS`の
  `instantDrowning`検証テスト2件を含む）/ `npm run build`: すべて成功。
- Playwright（chromium）で実機確認: 静かな草原で沈降ツールを使い、
  自陣の近くに実際に2x2以上の水たまりを掘った状態で長時間プレイを
  継続し、コンソールエラーが出ないことを確認。民は元々`settle`/
  `wander`/`gather`の各ターゲティングが買えるべき地点を選ぶ際に水没
  地点を避ける仕組みが既にあるため、この短い実機確認の間に実際に
  民が池に迷い込んで溺れる瞬間を映像として捉えることはできなかった
  （これは洪水魔法による既存の即死処理も同様で、通常プレイでは
  そもそも民が自分から水に入ろうとしない）。そのため、実際の溺死
  ロジック（水没時のエネルギー減少・陸上復帰による即時回復・即死
  モード・騎士/守護者の免除・池と孤立した1マスの水の区別）は、
  ECSワールドを直接操作する単体テスト（`drowning.test.ts`)9件で
  網羅的に検証した。

## 備考

これで、今回のバッチフィードバック9項目のうち、ユーザーが優先指定した
4項目（マナフィードバック改善・平坦化ツール・面ごとの敵地干渉制約・
段階的な溺死モデル）すべてに対応した。残る項目（火山の状態表示改善）
は今回のスコープ外。
