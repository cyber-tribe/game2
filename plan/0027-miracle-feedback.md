# 0027 miracle-feedback

## 背景

戦略レビューで指摘された懸念のひとつ：`enemyMiracles.ts`（#28）で敵AIが
地震・騎士化・最終決戦を自律的に発動するようになったが、それがプレイヤーの
現在の視点の外で起きた場合、画面上には何も起きた形跡が残らない。プレイヤー
自身の奇跡（隆起・沈降・地震・沼・火山・洪水・騎士化・最終決戦）にも、
発動時の「派手さ」がタップ音以外に何もなく、レビューが指摘した「奇跡に
スペクタクル感がない」という弱点そのものだった。

この2つは独立した問題に見えるが、どちらも「奇跡が起きたことをプレイヤーに
体感させる」という同じ土台（画面演出のフィードバックチャンネル）を必要と
するため、1つの変更としてまとめる。

## アプローチ

### 画面シェイク

`main.ts`にPIXIの`renderer.view`を包む`worldContainer`を追加し、カメラの
本来の状態（パン・回転・ズーム）は従来通り`renderer.view.position`が
真実の情報源のまま保ちつつ、`worldContainer.position`にだけ一時的な
ランダムオフセットを重ねる。`triggerShake(magnitude)`で残り時間と強度を
セットし、`app.ticker`内で残り時間に比例して強度を減衰させながら
ランダムに揺らし、0になったら位置を(0,0)に戻す。

規模の異なる奇跡ほど強く揺らす：最終決戦(10) > 火山(8) > 地震(6) ≒
敵の地震(6) > 洪水(5) > 敵の騎士化(3)。プレイヤー自身の隆起・沈降・沼・
騎士化・集結地移動は元々地味な操作のため対象外。

### 敵の奇跡トースト

`enemyMiracles.ts`に`EnemyMiracleEvent`（`earthquake`/`knight`/
`armageddon`）と、各アクション成功直後に呼ばれる`onAction`コールバックを
追加。`Simulation`はこれを`SimulationConfig.onEnemyAction`としてそのまま
中継するだけで、シミュレーション自体は描画について何も知らない
（このセッションで確立した「イベントコールバックを橋渡しする」パターンを
再利用）。

`main.ts`側は`onEnemyAction`で`index.html`に追加した`#enemy-event-toast`
要素にラベル（例：「💥 敵が地震を起こした」）を設定して表示し、3秒後に
フェードアウトさせる。同時に該当する強度で画面シェイクも起動する。
プレイヤーが現在どこを見ていても、少なくとも「何かが起きた」ことと
「何が起きたか」は伝わる。

## テスト

- `enemyMiracles.test.ts`：`onAction`が渡された場合に、armageddon成功時
  ・knight成功時・earthquake成功時にそれぞれ対応するイベントが1回だけ
  発火すること、何もしなかった場合は発火しないことを確認（既存の4テストに
  アサーションを追加）。
- `npm run typecheck` / `npm run test -- --run`（199件）/ `npm run build`
  がすべて成功。
- ヘッドレスブラウザ（`toast-qa.mjs`）で実際に敵が地震を起こすまで待機し、
  トースト「💥 敵が地震を起こした」が正しく表示されることをスクリーンショット
  で確認済み（t=18s）。

## 残作業

- 揺れの強度・持続時間の具体的な値は感覚的に決めたもので、実プレイでの
  調整余地がある。
- プレイヤー自身の奇跡にも同様のトースト（例：「地震を起こした」）を出すか
  どうかは検討していない。プレイヤーは自分の操作の結果を画面上で直接見て
  いるため、今回は敵側のみに絞った。
