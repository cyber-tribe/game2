# 0148 verify-diff-table

## なぜ書き直したか

`plan/0143` で攻略資料から差分を24行拾ったとき、**資料しか見ていなかった**。
「原作はこう書いてある」は正しく写したが、「game2 はこうなっている」の側は
確かめずに書いた。

実装に入って3行目で気づいた。嵐を直そうとして `storm.ts` を開いたら、
**もともとウォーカーを殺していなかった**——そう書いたコメントまである。
表の方が間違っていた。

そのまま続ければ、直す必要のないものを直し、直すべきものを見落とす。
全24行をコードと突き合わせ直した。

## 分かったこと

**3行が事実と違っていた。**

- **嵐**：`storm.ts` は家と地面だけを焼く。民は無事。原作どおりだった。
- **毒カビ**：`spreadFungus` は近傍数で成長も枯死も決まる細胞オートマトンで、
  孤立した種はたいてい枯れ、固めて置けば広がる。原作の「数個まとめて置くと
  活性化」「短時間で終息」は、既にこの形で入っていた。
- **アーマゲドン**：家はウォーカーに変わっている（強さは家の防御力）。
  原作の「ヒーローの姿に変身」との差は見た目だけである。

**3行は差分だが、そのまま持ち込めない。**

- **津波の「3段」**：段数は原作の地形スケールの値である。game2 の地形は
  0〜7（中央値3）で、`DEFAULT_TSUNAMI_HEIGHT = 5` は実測で較正されている。
  数字だけ移すと較正が壊れる。
- **渦巻きの「消費マナがかなり少ない」**：高い安いは相対値で、game2 の
  マナ経済は原作と別物である。
- **情報コマンドの表示先**：右上の円形劇場は人口ゲージにすると決めてある
  （`plan/0130`）。差分ではあるが、採用済みの設計判断とぶつかる。

残る**12行が本当に直すべきもの**である。

## 表の形を変えた

各行に 済／要／不要／保留 を付けた。「要」以外を実装しにいかない、と
明記してある。差分表は実装の入口なので、確かめていない行が混ざっていると
入口そのものが壊れる。

## この一件から

資料を読んで表を作るときは、**両側を見る**。「原作にこう書いてある」だけ
では差分ではない。`palette.ts` の草の色で一度、この表で三度、同じ形の
間違いをしている——**片側だけ見て「違う」と決めた**、という形である。
