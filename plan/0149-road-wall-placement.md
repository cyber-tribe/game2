# 0149 road-wall-placement

## 資料

> **道**：なお、**敵陣や斜面には設置できない**。
> **城壁**：道と同じく、敵陣や斜面には設置できない。**城壁にかかる土地上下が
> できなくなる。**

game2 はどこにでも置け、置いた後の地面も自由に上下できた。

## 直したもの

### 斜面には置けない

`isLevelVertex(heightmap, x, y)` を足した——その頂点と上下左右の隣が同じ
高さか。舗装も石壁も**平らな地面に置くもの**である。

判定を厳しく（1段の差でも斜面）したのは、これが**家を建てるのと同じ基準**
だからである。「家が建つ平らさ」と「道が敷ける平らさ」を別の閾値にすると、
プレイヤーが覚える規則が2つに増える。

### 壁の胸壁は斜面ではない

最初に書いたとき、テストが3件落ちた。城壁は自分の立つ地面を持ち上げるので、
**1本目の城壁が2本目を「斜面」にして拒む**。資料は城壁を繋げて線にすると
書いている（「通常は手動で延ばして連続した城壁を設置する」）ので、両方が
成り立つ読みは1つしかない——**壁の隆起は地形ではない**。

`isLevelVertex` は壁の乗った隣を測定から外す。同じ読みで、道は壁の手前まで
来て止まる（隣に壁があるだけでは拒まれない）。

### 敵陣には置けない

地形の高さは `heightmap` だけで分かるが、**敵陣かどうかは world を見ないと
分からない**。判定は詠唱側（`main.ts`）に置いた。既存の「敵陣で土地上下
できるか」が取っているのと同じ分け方である。

ただしそれと違って**面ごとの設定ではない**。資料は道・城壁について無条件に
「敵陣には置けない」と書いている。

### 城壁の下は上下できない

`raiseVertex` が壁の乗った頂点を拒む。遮るのが目的である以上、下から土地を
抜けては意味が無い。逆に言えば、これが安い城壁で相手の整地を止められる唯一
の使い道であり、資料が「使い方がかなり難しい」と言う神技に値段分の仕事を
与えている。

## 検証

- `npm run typecheck` / `npm run build` パス、テスト847件パス（+8）。
- `heightmap.test.ts` に、平地では真／1段の差で偽／**壁の胸壁は斜面と
  数えない**／斜面には敷けない・築けない／**平地なら線に繋げられる**／
  壁の下は上下できない／隣は上下できる。
