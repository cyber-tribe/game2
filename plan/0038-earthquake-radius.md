# 0038 earthquake-radius

## 背景

ユーザーからの指摘：「地震が強すぎませんか？原作ではどのようなもの
なのですか?」

原作（Populous）の地震は「中」位の奇跡で、最終決戦・洪水・火山ほどの
最強クラスではない。効果も対象範囲の地形をランダムに荒らして平地を
壊し、経済基盤（家の維持条件）をじわじわ弱らせる間接的な妨害が主目的
で、火山（直接破壊）や洪水（広域壊滅）のような即座の決定打ではない。

このゲームの数値を見直すと：

- `EARTHQUAKE_MANA_COST = 20`（「中」tier、最も安い部類）
- `DEFAULT_EARTHQUAKE_RADIUS = 3` → 7×7マス
- 家のレベル維持に使う`HOUSE_UPGRADE_FLATNESS_RADIUS`はわずか2マス

つまり地震の範囲(3)が家の平坦度判定の範囲(2)より広く、1発のcastで
複数の家の平坦度を同時に壊せてしまっていた。火山（40マナ・3×3マスを
直接破壊）の半額で、範囲は倍以上という、原作の「地震は経済への嫌がら
せ、火山は決定打」という力関係とは逆転した状態になっていた。

## アプローチ

`DEFAULT_EARTHQUAKE_RADIUS`を3から2へ縮小し、`HOUSE_UPGRADE_
FLATNESS_RADIUS`と揃えた。これにより、地震は「狙った1軒の家の平坦度
を崩す」効果に近くなり、周囲の複数軒を同時に巻き込む広域性は失う。
コスト（20マナ）や1マスあたりの変化量（`DEFAULT_EARTHQUAKE_MAX_
DELTA`=4）は変更していない。

`enemyMiracles.ts`の`densestOpponentCluster`（地震の的を選ぶ際、密集
した集落を狙う）も同じ定数を再利用しているため、狙う際の集積スコア
半径も自動的に2へ縮む——地震が実際に届く範囲と、狙い方の判断基準が
食い違わないようにするための一貫性はそのまま保たれている。

## テスト

- ロジックは`applyEarthquake`のデフォルト引数のみの変更で、既存の
  `heightmap.test.ts`の`applyEarthquake`関連テストは全て明示的に
  radiusを渡しており影響なし。
- `enemyMiracles.test.ts`の密集判定テストは、テスト内の家同士の距離
  （1マス）が新しい半径（2）でも十分カバーされるため無変更で通過を
  確認。
- `npm run typecheck` / `npm run test -- --run`（222件）/
  `npm run build`がすべて成功。テストスイート全体を3回連続実行し、
  実乱数を使うテストにフレーキーさが出ていないことを確認。

## 残作業

- コスト（20マナ）自体は今回変更していない。範囲縮小後の体感が
  それでもまだ強いと感じられた場合は、コスト増額や
  `DEFAULT_EARTHQUAKE_MAX_DELTA`の引き下げも追加の調整候補として
  残っている。
