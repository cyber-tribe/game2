# マナ不足時のフィードバック改善

## 背景

ユーザーからの一連のフィードバックのうち:

- 「人口というか信者の総エネルギーによってコマンドが徐々に使えるようになる」
- 「上げ下げができているのか分からない」

を受けて調査したところ、地形操作(隆起/沈降)を含む全ての奇跡はマナを
消費して発動する仕組みが既に実装されている(`trySpendMana`)一方、
**マナが足りずタップが失敗した際のフィードバックが一切無い**ことが
分かった。タップしても何も起きないため、「編集自体が効いていないのか」
「マナが無くて発動していないだけなのか」をプレイヤーが判別できない。

ツールバーのボタン自体も、そのワールドで未解禁の奇跡・
`terrainEditRule`が禁止する方向は起動時に一度だけ`disabled`になるが、
現在のマナ残高に応じた見た目の変化は無く、コストを払えるかどうかが
一目で分からない。

## 対応

`src/main.ts`:

1. **失敗時の明示**: `trySpendPlayerMana`がマナ不足で失敗した場合、
   既存の「🔍 照会」情報パネルを使って
   「マナが足りません（必要 X / 現在 Y）」を表示するようにした
   （自陣が画面内に見えていない場合の既存メッセージと同じ仕組み）。
2. **ボタンの見た目によるフィードバック**: 毎フレーム、各ツールの
   マナコスト(`MANA_COST_BY_TOOL`)と現在のプレイヤーのマナを比較し、
   払えない場合はCSSクラス`mana-low`を付与して少し暗く表示する
   (`updateToolbarAffordability`)。既存の`disabled`（そのワールドで
   永続的に使えない）とは意図的に別のクラスにした:
   - `disabled`にすると隆起/沈降ボタン自体が押せなくなり、マナが
     貯まって再び使えるようになった際に選び直す手間が生まれてしまう。
   - タップ自体は引き続き通し、上記の明示的なメッセージで理由を
     伝える方が「操作できたが効果が発動しなかった」と「そもそも
     操作を受け付けない」を区別しやすい。

`src/game/simulation.ts`: 上記のためだけに`world`を直接触らせるのは
避け、`getBehaviorMode`と同じパターンで読み取り専用の`getMana(faction)`
を追加した。

`index.html`: `.toolbar-row button.mana-low`のスタイル（opacity 0.55、
`disabled`のopacity 0.35より薄い区別）を追加。

## 検証

- `npm run typecheck` / `npm run test -- --run`(413件、`Simulation.
  getMana`の新規テストを含む) / `npm run build`: すべて成功。
- Playwright（chromium）で実機確認: マッチ開始直後（マナがほぼ0）の
  状態で地震ボタン(コスト20)が`mana-low`クラスを持つことを確認。
  隆起ツールで地形を連打してマナを使い切った後、タップすると
  「マナが足りません（必要 1 / 現在 1.0）」というメッセージが
  情報パネルに表示されることを確認。コンソールエラーも無かった。

## 備考: 今回対応しなかった項目

同じフィードバックの中には以下の項目も含まれていたが、それぞれ
独立した機能追加であるため別PRで対応する:

- 平坦化専用ツールの追加
- 段階的な溺死モデル（即死ではなくエネルギー減少+陸上復帰、
  面ごとの即死制約）
- 面ごとの敵地干渉制約（terrainEditRuleは方向のみ制限しており、
  誰の土地かは考慮していない）
