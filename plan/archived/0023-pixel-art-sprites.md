# 家とウォーカーをドット絵で描く

## 報告された問題

「グラフィックが分かりにくいので、人間や家のドット絵をちゃんと描いて
ください」

これまで`EntityLayer.ts`は家を単色の正方形（`rect()`）、ウォーカーを
単色の円（`circle()`）として描いていた。勢力ごとの色分けはできて
いたが、「これが家なのか」「これが民なのか」を形から読み取ることが
できず、地形の色と紛れやすいという指摘だった。

## 対応

`src/render/pixelArt.ts`を新設し、文字列配列でドット絵パターンを
定義して小さな正方形（`rect()`）の集合として描画する
`drawWalkerSprite`/`drawHouseSprite`を実装した。

- **ウォーカー**：頭・胴・足のある簡単な人型パターン（5×7セル）。
  勢力色（騎士化していれば`KNIGHT_COLOR`）で全身を塗る、既存の単色
  円と同じ「1色で状態を表す」考え方を保っている。
- **家**：レベルごとに専用パターンを用意した（hut/lodge/manor/castle）。
  屋根・ドアは固定色（勢力によらず統一）、壁だけを勢力色にすることで
  「誰の家か」は今まで通り一目で分かるようにしつつ、屋根・ドア・窓
  （lodge以上）を描き加えて実際に家らしいシルエットになるようにした。
  castleは屋根の代わりに凹凸（銃眼）にして、レベルが上がるほど
  「立派になっていく」のが見た目でも伝わるようにした。
- 各レベルのパターンは、それまでの`HOUSE_SIZE`（10/14/18/24px）と
  ほぼ同じ画面上の大きさになるよう、パターンの列数から逆算した
  ピクセルサイズで描画している（`HOUSE_PATTERN_WIDTH`）。家がどの
  レベルでも地図上のレイアウトが変わらないようにするため。
- リーダーの強調表示は、ドット絵に輪郭線を引くのが難しいため、白い
  半透明の円を人型ドット絵の後ろに描く「後光」方式に変更した
  （以前の「太い白枠」と同じ役割）。

`EntityLayer.update()`自体の構造（`Graphics`を`clear()`して
毎フレーム再構築する既存方式）は変えていない。1エンティティあたりの
`rect()`呼び出し数は増えた（家で最大100個ほど）が、PixiJSの
`Graphics`は蓄積した形状を1つのメッシュにまとめて描画するため、
毎フレームのドローコール数自体は変わらない。

## テスト

- `npm run typecheck` / `npm run test`（177件、ロジック変更なし） /
  `npm run build` すべて成功。
- ヘッドレスブラウザでcanvasをCSS transform（`scale()`+
  `image-rendering: pixelated`）で拡大表示し、家のドット絵が屋根・壁・
  窓のはっきりした形で描画されることを確認した。ウォーカーは実プレイ
  中の画面サイズでは小さいままだが、家と同じ`drawPixelPattern`関数で
  描画しているため描画経路は同一。
