# 0120 sprog

## 背景

`plan/archived/0119-auto-flatten.md`の続き。原作の**評価点**「操作性の良さ」で
名指しされている2つのうち、残る**スプログ**を入れる。

> 自動整地（Xボタンで建物を中心に7x7マスの平地を確保）、スプログ（建物の
> 中心にカーソルを合わせてBボタンを押すと、信者の一部が追い出される）等、
> 操作性も練られている。
> **特にスプログは前作に無かった仕様で、ゲームの進行が早くなったと好評。
> 前作では建物の収容可能人数を超えるまで待たなければならなかった。**

game2には`releasePopulation`（UI上は「送出」）があったが、原作の
スプログとは別物だった。原作の記述で効いているのは次の2点で、送出は
どちらも満たしていない。

| | 原作のスプログ | game2の送出 |
|---|---|---|
| 対象 | カーソルを合わせた**1軒** | 勢力の**全戸**を一括 |
| 出る量 | 信者の**一部** | 人口を**0にリセット** |

## アプローチ

`releasePopulation`を`sprogHouse(world, house, maxHousesPerFaction)`へ
置き換えた。

### 1軒を狙う

原作はカーソルを建物に合わせる。game2はタッチなので、`自動整地`と同じく
**家をタップするツール**にした（`toolMode === "sprog"`）。対象は自分の家だけ。

`InspectableEntity`に`entity`（ECSのid）を持たせ、照会パネルが既に使って
いる画面座標での最近傍探索をそのまま流用している。「拾ったものに対して
操作する」ためにidが要る、というだけの追加である。

### 一部だけ出す

`SPROG_FRACTION`（0.5）——**残っている**人口の半分が出て、残りは家に残る。
家がゼロに戻らないことが「満杯を待たない」の意味で、「家を現金化する」の
ではない。

取り分が毎回半分になるので、連打は自然に止まる。満杯の家からは2体
（1 → 0.5、下限ちょうど → 0.25で拒否）出て、そこで打ち止めになる。
`POPULATION_RELEASE_MIN_FRACTION`（0.5）の下限はそのまま残した。下限が
無ければ、`settle.ts`の都合で1体でも家を建てられてしまうため、
ほぼ無価値なウォーカーの列を無限に吐けてしまう。

### 送出を残さなかった理由

game2独自のものは残す方針（守護者・平坦化）だが、送出は例外とした。
全戸を一括で空にするボタンがパネルにある限り、1軒を狙う理由が
どこにも無くなり、原作のコマンドが並んで存在できない。同じ操作の
**より雑な版**であって、別の選択肢ではない。

平坦化を自動整地と併存させたのとは事情が違う。平坦化は自由な範囲を
なぞるブラシで、家を中心に固定される自動整地とは狙えるものが別である。

### アイコン

既存の`releasePopulation`アイコン（扉の開いた家から人が出ていく図）を
そのまま`sprog`へ改名して流用した。図案は元から原作のスプログそのもの
だったので、描き直す理由が無い。

## 検証

`src/game/populationRelease.test.ts`を書き直した。

- 下限未満の家では何も起きないこと
- **一部**だけ出て残りが家に残ること、ウォーカーの強さが
  `出た人口/収容数 × 効率`になること
- **与えた1軒しか触らない**こと（他の家の人口が変わらない）
- 出たウォーカーが家と同じ陣営になること
- 家の上限に達している勢力では何も起きないこと／上限は自勢力の家だけを数えること
- 家でないエンティティを渡しても何も起きないこと
- 連打が自然に止まること（満杯から2体で打ち止め）

`npm run typecheck` / `npm run test`（725件）/ `npm run sprites:check` /
`npm run build` すべてパス。
