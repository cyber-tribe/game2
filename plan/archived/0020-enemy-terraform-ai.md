# 敵AIにも自陣の家の周囲を整地させる

## 背景

`plan/0019-house-flatness-indicator.md`と同じく、ユーザーから共有された
スーファミ版参考ゲームの初心者向け攻略要約がきっかけ。攻略要約は
「整地→発展→人口増加→戦争」というプレイヤー視点の核ループを説明する
ものだったが、参考ゲームの元の設計では「敵の神もプレイヤーと同じ
ルールで介入する」ことが前提になっている。

対して本実装の`enemyAi.ts`はウォーカー数の閾値でbehaviorModeを
切り替えるだけで、地形操作を一切行わない。敵の家がアップグレードする
かどうかは`createHeightmap`が生成した地形がたまたま平らだったかどうか
任せになっており、「敵も自分と同じように整地して発展する」という
対等な競争が成立していなかった。

## 対応

`world/heightmap.ts`に`findLeastFlatVertex(heightmap, x, y, radius)`を
追加した。`countFlatNeighbors`の逆で、中心から半径内で最も高さが
異なる頂点と、それを中心に合わせるための delta（+1/-1）を返す
（既に平らなら null）。

`game/systems/enemyTerraform.ts`の`createEnemyTerraformSystem`は、
一定間隔ごとに敵陣営の家それぞれについてこの関数で「最も平らでない
隣接頂点」を1つ選び、`trySpendMana`でプレイヤーのタップと全く同じ
`TERRAIN_EDIT_MANA_COST`を払って`raiseVertex`で1段階だけ整地する。
`simulation.ts`のスケジューラに追加し、`heightmap`を他の地形依存
システムと同様に渡している。

これにより敵の家も`createHouseUpgradeSystem`の同じ仕組みで自然に
アップグレードするようになり、`plan/0019`で追加した進捗バーが敵の
家にも意味を持つようになった（実際に敵の家の下にもバーが表示される
ことをヘッドレスブラウザで確認済み）。

## テスト

- `heightmap.test.ts`に`findLeastFlatVertex`の単体テストを追加
  （平坦時null、最も差が大きい頂点を選ぶこと、delta の向き、
  マップ端でのウィンドウ縮小、小数座標の丸め）。
- `enemyTerraform.test.ts`を新設（heightmap未指定時no-op、実際に
  整地してマナを消費すること、他陣営の家には影響しないこと、
  既に平らな場合は何もしないこと、マナ不足時は地形を変更しないこと、
  decisionInterval経過前は再実行しないこと）。
- `npm run typecheck` / `npm run test`（188件）/ `npm run build`
  すべて成功。
- ヘッドレスブラウザで30秒間実行し、コンソールエラーが出ないこと、
  複数の家（自陣営・敵陣営とも）の下に整地進捗バーが表示されることを
  スクリーンショットで確認した。

## 積み残し

- 敵の整地はhouseごとに独立して「最も差が大きい頂点1つ」を選ぶ
  貪欲な実装で、プレイヤーのような「広い範囲を意図的に平らにする」
  計画性はない。プロトタイプとしては十分だが、より賢い敵AIが必要に
  なった場合はここが起点になる。
