# 0140 square-terrain-mesh

## 指摘

> 今の仕様では三角メッシュになっていますか？ 原作同様に正方形メッシュにしては？

なっていた。`IsoRenderer.redraw` は1タイルを `(x,y)-(x+1,y+1)` の対角線で
2枚の三角形に割り、それぞれを自分の法線で陰影付けしていた。

原作のスクリーンショットを拡大して確かめると、地面は**1マス1枚**の
テクスチャが連続したもので、対角線の継ぎ目はどこにも無い。菱形（等角
投影された正方形）の格子がそのまま面になっている。

## なぜ三角形だったか

コードにその理由が書いてあった——四隅の高さが全て違うタイルは平面に
ならない（鞍型に歪む）ので法線が1つに決まらない。3点は必ず同一平面なので、
2枚に割れば各面の法線が確定する、と。

理屈は正しいが、代償が2つあった。

1. **鞍型タイルで対角線に折り目が出る。** 2つの半分が別々の明るさを
   取るため、原作には対応物の無い線が入る。
2. **その対角線を全タイルが同じ向きに引いていた。** 割り方はこのコードの
   任意の選択でしかないのに、世界全体に一方向の畝（コーデュロイ）の
   目が乗っていた。

## 直し方

**ニューウェル法**（`polygonNormal`）に置き換えた。閉じた多角形の
面積重みつき法線を求める古典的な方法で、平面ならその平面の法線に一致し
（三角形では従来の外積と完全に同じ）、平面でない多角形にはその表面の
平均を与える。「法線が1つに決まらない」に対する答えがまさにこれである。

これで1タイルを `poly` 1回、正方形1枚で塗れる。

### ついでに直った境界

「平ら」の判定が **四隅すべてが一致** になった。以前は分割後の三角形
ごとに見ていたので、三隅が水平で一隅だけ上がっているタイルは、その隅を
含まない側の三角形にだけディザ（＝整地済みの見た目）が出ていた。整地の
ご褒美が半分だけ出る状態だったことになる。

## テストで前提が変わったところ

10件が落ち、うち1件は**前提そのものが成立しなくなった**ので書き直した。

「同じ隅を上げたときと下げたときで陰影が変わる」——正方形1枚では
**変わらない**。この隅を動かすとタイルは対角線 (1,1) 方向に傾くが、
光源の水平成分は (1,-1) で直交しているため、上げても下げても入射角は
等しい。ランベルト反射としてこれが正しい。以前差が出ていたのは、対角線
で割ったせいでタイルの対称性が崩れていたからにすぎない。

そこで、正方形が実際に答えられる軸——北辺を上げる／下げる（光源は
-y/+x から来る）——で「光を向いた面は明るく、背けた面は暗い」を確認する
形に書き換えた。ついでに、傾け過ぎると光源方向を通り越して再び暗くなる
（最も明るいのは鉛直から約27°）ので、±0.5 で見ている。

もう1件、「平らのすぐ外側でも陰影が付く（不感帯が無い）」は、0.03 の
傾きでは輝度差が 8bit の1段に満たず色として出ない。**どの分岐に入るか**
（ディザではなく単色シェーディング）を見る形にした。測れない色を測ろうと
していたテストである。

## 検証

- `npm run typecheck` / `npm run build` パス、テスト800件パス。
- 実機で**同じ地形**の前後を撮って比較した（`Math.random` を
  `addInitScript` で固定シードに差し替え、変更あり／なしで2枚）。
  三角形の斜めの目が消え、菱形の面が並ぶ見た目になった。
