# 0096 火山に溶岩の流れを追加する

## 背景

`docs/original-miracles.md` の実装順序に従い、「既にあるが性質が違うもの」の
第3弾（津波 plan/0094、地震 plan/0095 に続く）。

原作の火山（#24）は「発動地点を一気に隆起させ、**火口から溶岩を流します**。
溶岩は土地を建築不能な状態へ変え、**水地形で止まります**」。

旧 `applyVolcano` は円錐を作り、**その円錐と全く同じ範囲だけ**を岩で覆って
終わりだった。溶岩の流れがないので、周囲の地形が何であろうと常に同じ大きさの
土地を奪う。地形との相互作用がゼロである。

## 溶岩は「常に最も低い前線」を取る

`flowLava` は前線のうち**標高が最も低い頂点を1つずつ**取っていく。これにより
溶岩は谷を下り、窪地に溜まる。同じ量でも、谷なら長い舌に、平地なら丸い水溜り
になる — これが円をもう1つ描くのではなくシミュレートする理由そのものである。

半径ではなく**量**（`DEFAULT_LAVA_VOLUME`）で制御しているのも同じ理由。

### 層ごとに広げる実装では駄目だった

最初は前線を丸ごと1段ずつ広げ、その中から低い順に取る実装にした。
一見同じだが、**量が控えめだと最初の1周でほぼ使い切ってしまい、どこへも
到達しない**。溶岩が谷を下れないなら、このシミュレーション自体に意味がない。
テスト（「低い方へ流れ、高台は避ける」）がこれを捕まえた。

## 水で止まる

これがこの奇跡の周りで起きる駆け引きである。**水路や湖は防火帯になり、
高台はならない** — 溶岩は登らないが、回り込むことは平気でする。

原作には「水を埋め立てるとさらに外側へ流れ出すことがある」ともあるが、
これは溶岩が発動時に解決される一撃ではなく**後から再開する生き物**である
必要がある。作る理由ができるまで意図的に見送った（文書化済み）。

## eruptVolcano は覆った頂点を受け取る形にした

以前は中心と半径から正方形の footprint を再計算していた。噴火が**その正方形
そのもの**だった間は正しかったが、溶岩が流れる今、覆われる範囲はどんな半径
でも記述できない不規則な舌になる。

ここがズレると見た目の問題では済まない。**建築不能な岩の上に家が残る**か、
**きれいな地面に立っていた民が死ぬ**。`applyVolcano` が覆った頂点を返し、
`eruptVolcano` がそれを受け取る形にした。

## 検証

- `npm run typecheck` 通過、`npm run test -- --run` 473件通過
- 円錐の形状テストは `lavaVolume: 0` で分離した。流れを走らせたまま
  「範囲外は岩でない」を確かめることはできない（実際、この変更で
  その assertion が正しく落ちた）
- 流れ: 円錐を超えて広がること、**水を越えないこと**、**低い方へ流れて
  高台を避けること**、量をちょうど使い切ること
- `eruptVolcano`: 覆われた地点の家/民が消えること、離れた溶岩の舌が
  届いた先も消えること、無関係な場所は残ること
- 実ゲームで噴火させて目視確認。円錐より遥かに広い不規則な岩の領域が
  縁を発光させて広がること、コンソールエラー0件

## 次

「既にあるが性質が違うもの」はこれで一通り。次は相互作用の土台になる
**森・道・岩礁（済）・花**。花は plan/0095 で作った `crevice` と、
この溶岩の両方を修復する役になる。
