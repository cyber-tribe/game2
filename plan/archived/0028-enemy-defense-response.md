# 0028 enemy-defense-response

## 背景

戦略レビューが敵AIの最優先課題として挙げた点のひとつ：`enemyAi.ts`は
「歩行者数がしきい値を超えたら戦闘、それ以外は定住」という単純な集計値
判定しかしておらず、実際に自陣の家が攻められているかどうかを見ていない。
その結果、敵の総戦力がまだ少ない序盤では、家がプレイヤーの軍勢に包囲
されていても敵は「定住」のまま無抵抗で家を失う、という不自然な挙動に
なっていた（`enemyMiracles.ts`で地震・騎士化・最終決戦は追加済みだが、
これらは全て人口優位を前提にした「攻め」の判断で、「守り」の判断が
存在しなかった）。

## アプローチ

`enemyAi.ts`の意思決定に、歩行者数によるしきい値判定と並んで「自陣の
家の`ENEMY_AI_THREAT_RADIUS`タイル以内に敵の歩行者がいるか」という
判定を追加し、どちらか一方でも真なら`fight`モードに切り替える
（`isUnderThreat`）。`fightTargetingSystem`が既に持つ「最寄りの敵を
目指す」ロジックと組み合わさることで、家を守るために近くの敵歩行者へ
向かうという、狙い通りの防御的な振る舞いになる。

しきい値・脅威半径ともに`EnemyAiConfig`で上書き可能にし、
`ENEMY_AI_THREAT_RADIUS`定数（既定4タイル）を`constants.ts`に追加した。
`opponentId`もこれまで`enemyMiracles.ts`等で使ってきたパターン通り
設定可能にし、既定値`"player"`。

## テスト

- `enemyAi.test.ts`に2件追加：しきい値未満でも家の近くに敵歩行者がいれば
  `fight`に切り替わること、脅威半径の外なら`settle`のままであること。
- `npm run typecheck` / `npm run test -- --run`（192件）/ `npm run build`
  がすべて成功。

## 残作業

- 判定は`decisionInterval`（既定5秒）ごとにしか走らないため、脅威検知
  から実際に防御へ切り替わるまで最大でその間隔ぶん遅れる。今回の目的
  （「無反応で家を失う」を防ぐ）には十分だが、より緊迫感のある反応速度
  にするなら別途検討が必要。
- 「守り」の判断はbehaviorMode切り替えのみで、マナを使った防御的な奇跡
  （例：敵が迫ったら地震で足止めする、など）は未実装。
