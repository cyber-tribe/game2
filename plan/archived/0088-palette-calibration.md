# 0088 マスターパレットの原作スクリーンショットからの較正

## 背景

`src/render/palette.ts`（0084「原作型UI基盤」で導入）の初版は、
**推測で置いた色**だった。この実行環境から原作のスクリーンショットを
取得するネットワーク経路がなく（`w.atwiki.jp` などへの外向き通信は
`EGRESS_BLOCKED`）、「Populous 2 は石とブロンズの神殿調」という
一般的な知識だけを頼りに組んだ値である。

その後ユーザーが原作のスクリーンショット計6枚を会話に直接貼ったため、
推測値を実測値に置き換えられるようになった。本タスクはその較正作業の記録。

## 採色の方法

スクリーンショットは JPEG 圧縮を経ているため、単純なピクセル抽出では
圧縮ノイズを拾う。以下の手順で支配色を取り出した。

1. 領域ごとに切り出す（画面外周の枠、下部コマンドパネル、地面、水面）。
2. 各領域を Pillow の `Image.quantize(colors=8, method=MEDIANCUT)` に
   かけ、パレット化した上で各色の占有率を出す。
3. 全6枚を横断して、どの画面でも共通して上位に来る色だけを採用する。
   1枚にしか出ない色はステージ固有の色調とみなして捨てる。

## 草原の色 — 一度取り違えた点

較正の初回パスでは、地面をオリーブ／カーキ（`#4c4d00` `#666600`
`#928100`）と結論づけた。**これは誤りだった。**

ユーザー（原作の経験者）から次の指摘を受けた:

> それはたまたまそういうステージなのであって通常は新緑が正しいと思います

再検証したところ指摘の通りだった。最初の6枚は乾燥／後期エポックの
ステージに偏っており、そこの地面色を「通常の草地」と取り違えていた。
ユーザーが追加で提供した緑のステージ2枚に対し、緑成分が優勢な画素だけを
残すフィルタ（`g > r` かつ `g > b`）をかけて再採色すると、
`#5b7d47` / `#638153` / `#7c9864` — 色相およそ95°、緑が支配的な苔色が
出た。くすんで見えるのは JPEG 圧縮によるもので、色相そのものは
オリーブではない。

したがって:

- `grassLight` / `grassMid` / `grassDark` は新緑（`#86b95a` / `#4f8a35` /
  `#35601f`）に戻した。色相だけ、実測の苔寄り（95°付近）へごく僅かに寄せている。
- 取り違えたオリーブ系は捨てずに `scrubMid` / `scrubDark` として残し、
  「乾燥ステージ固有の地面色」と明記した。
- `palette.ts` の doc コメントに、乾燥ステージのスクリーンショットを
  根拠に草地をオリーブへ「再較正」し直さないよう警告を書いた。
  同じ誤りを繰り返させないための注意書きである。

## 反映範囲

- `src/render/palette.ts` — 実測値へ置換。`scrubMid` / `scrubDark` を追加。
- `src/render/IsoRenderer.ts` — `TERRAIN_COLOR` / `WATER_COLOR` /
  各 speckle 色を `GAME_PALETTE` 参照へ。`TERRAIN_COLOR` を export。
- `src/render/Minimap.ts` — 地形色を `GAME_PALETTE` 参照へ。
  ミニマップは標高を明度バンドに量子化して重ねるため、最も明るいバンドで
  白飛びしないよう本編より暗い段（`grassDark` など）を基準色に取る。
- `src/render/IsoRenderer.test.ts` — 直書きだった `0xd6b25e` を
  `TERRAIN_COLOR.desert` 参照へ。以後のパレット調整でテストが壊れない。
- `index.html` — CSS カスタムプロパティを実測のサンドストーン段へ。
- `src/main.ts` — 画外の背景色を紺 `#0a1a2a` から `GAME_PALETTE.ink` へ。
  サンドストーンのUIと緑の大地の背後に青い余白があると、原作というより
  現代のWebキャンバスに見えるため。
