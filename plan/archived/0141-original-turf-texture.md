# 0141 original-turf-texture

## 指摘

> 原作のようにタイルのテクスチャにこだわってください

原作のスクリーンショットを拡大して確かめたことが2つある。

1. **地面に単色の面が無い。** 平らな所も傾いた所も、全部テクスチャが
   乗っている。あるのは「光の当たり方が違う同じ草」だけである。
2. **テクスチャに向きがある。** 短い線が**タイルの2本の辺の向き**
   （画面上では2:1の斜線）に沿って走っており、隣り合うセルが稜線で
   作るシェブロン模様が原作の草原にははっきり見える。

game2 はどちらも満たしていなかった。

- **斜面は単色だった。** ディザ（テクスチャ）が出るのは四隅が揃った
  タイルだけで、起伏のある土地ではほぼ全面が単色になる。前回の
  スクリーンショットが「ポリゴンの塊」に見えていた最大の理由がこれである。
- **テクスチャに向きが無かった。** `ditherPixelHash(x, y)` は等方的な
  ノイズで、方向という情報を持っていない。世界の上に砂嵐を敷いたのと
  同じで、そこに生えている草には見えない。

## 直したもの

### 1. タイルの軸に沿った織り（`createTurfTexture`）

タイルの辺 (x,y)→(x+1,y) は画面上で (2,1)、(x,y)→(x,y+1) は (2,-1)
の向きに投影される。この2軸を `isoAxes` として取り出し、

- 一方の軸方向に定数となる量でハッシュを引けば、その軸に沿った線が引ける
- 線の太さを2pxにするため、直交側の座標を `>> 1` して見る
  （2:1の斜線は「横2px進んで縦1px下がる」ので、1pxだけ塗ると点線になる）

という2点で、両方向に短い線が走る織りを作った。3色（地・明・暗）で、
2色の斑点より値の幅が広い。

繰り返しの単位は**ちょうど1タイル**（64x32）。タイルの原点は画面上で
(32, 16) の倍数に落ち、`ELEVATION_STEP` も 16 なので、`textureSpace:
"global"` のまま**どの標高のどのタイルも4通りの位相のどれか**に収まる。
模様がグリッドに属し、その4位相が隣接セルの単調さを消す。

### 2. 斜面にもテクスチャを乗せる

テクスチャは乗算では白方向へ持ち上げられないので、**明るさを量子化して
事前に陰影を付けたテクスチャをキャッシュ**する（`turfFillFor`）。
24段階。使われた段だけ作るので、実際には1種類あたり20枚程度である。

整地の見返りは残る。**平らなタイルだけが素の色**で描かれるので、整え
終えた区画は周囲の斜面より明るく落ち着いて見える。変わったのは
「面の質感まで変える」のをやめたことだけで、これは原作の描き方ではなかった。

### 3. 明るくする方向を色相保存にした

`shadeColor` は明るい側を**白へのlerp**でやっていた。単色の面ならこれで
よかったが、テクスチャが乗ると一目で分かる——日の当たる草地だけ
彩度が落ちて灰緑になる。原作の明るい地面は「同じ色を強くした」もので
あって白に寄ってはいない。チャンネルごとの乗算（クランプ付き）に変えた。
暗い側は元から黒へのlerp＝乗算そのものなので、挙動は変わらない。

## テストの置き場所を変えた

陰影の規則を確かめるテストが、レンダラ経由で「塗られた色」を読んでいた。
斜面がテクスチャになった今それは読めないので、**規則そのものを
`faceBrightnessOf` の単体テストへ移した**——平らは正確に1、急なほど1から
離れる、光を向けば1より上・背ければ下、ごくわずかな傾きでも1ではない。
レンダラ側には残す価値のある2件だけを置いた：平らなタイルが素の
テクスチャを使うこと、斜面が**自分の傾きに対応する**テクスチャを使うこと
（`turfFillFor(kind, faceBrightnessOf(corners))` と同一物か）。

「斜面は単色になる」を主張していたテストは、逆の主張——**内側の地面は
どんな傾きでも必ずテクスチャを持つ**——に置き換えた。

## 検証

- `npm run typecheck` / `npm run build` パス、テスト806件パス（+6）。
- 実機で同じ地形（乱数固定）の前後を撮影。
- **描画負荷を測った。** テクスチャ枚数が増えるので、同条件で4秒間の
  平均フレームレートを比較した——変更前 17.1 fps、変更後 18.5 fps
  （ヘッドレスのソフトウェアGLなので絶対値は低いが、差は誤差の範囲で
  悪化なし）。Pixi はテクスチャをまとめてバッチするので、20枚程度の
  内訳は描画回数をほとんど増やさない。

## 残した差分

原作の草原は game2 より**オリーブ／黄土寄り**である（原作のスクリーン
ショットを8色に量子化すると #6e5e1c, #4e430d, #877435, #8b8745, #b09e62
が出る）。今回は色相に手を付けていない。`GAME_PALETTE` の草の色は
`plan/archived/0088-palette-calibration.md` で一度合わせたもので、
ミニマップ・アイコン・スプライトが共有している。テクスチャの話とは
別の判断なので、独立して扱う。
