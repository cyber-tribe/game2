# 0097 森と火の雨 —— 最初の相互作用ペア

## 背景

`docs/original-miracles.md` の実装順序で、「既にあるが性質が違うもの」
（津波 0094・地震 0095・火山 0096）を終えた次の段階、**相互作用の土台**。

ユーザーが挙げた落としてはいけない相互作用の**筆頭が「森 → 火の雨」**
である。この2つは互いの片側なので、**同じPRに入れないと意味を成さない**。
森だけなら地味な成長バフ、火の雨だけならただの円である。

## 森（#6）

`Heightmap.forest: boolean[][]` を追加。`applyForest` が建築可能な地面に
だけ木を生やす（水・溶岩の岩・海面下には生えない）。

効果は2つで、**両方が要る**:

1. 森の中の家は成長が速い（`FOREST_GROWTH_MULTIPLIER = 1.5`）
2. **よく燃える**

倍率を1.5に留めたのは意図的である。**誰も失う危険を冒したがらないほど
強い成長バフにしてしまうと、森を焼くという相互作用そのものが死ぬ。**

## 火の雨（#22）

`applyFireRain` は円状に燃やし、**森に当たると森づたいに燃え広がる**。
燃えた森は消えるので、火が自分の通った道を戻ることもない。

裸の地面ではただの小さな円。森に落とすと森の長さ分だけ走る。
つまり**森は自分に向けて使われうる投資**になる。29個の奇跡が29個の
ダメージ数値ではなく意味を持つのは、こういう構造があるからである。

`burnFire` は火山の `eruptVolcano` と同じく**燃えた頂点の一覧**を受け取る。
延焼する以上、実際に燃えた範囲はどんな半径でも記述できない。

## 描画

森は独自の基準色と、草地よりずっと密なディザを持つ。上から見た森は
林冠であって草の色違いではない。**見分けがつくことは見た目の問題ではなく
プレイの問題**で、森は燃料であり、プレイヤーは火がどこを走るかを一目で
把握できる必要がある。

`fillTerrainTriangle` に `isForest` を足した。平坦な三角形はテクスチャで
塗られるため、ここを通さないと森が草地として描かれる（plan/0095 の
地割れで踏んだのと同じ穴）。

## 検証

- `npm run typecheck` 通過、`npm run test -- --run` 482件通過
- 森: 半径内に生える／範囲外は生えない／水に生えない／溶岩の岩に生えない／
  既に森なら「何も植えていない」と返す（呼び出し側がキャストを拒否できる）
- 火の雨: 裸地では円で止まる／**森の長さ分だけ走る**／通った森を消費する／
  **森の切れ目は飛び越えない**（燃料がなければ火は進まない）
- `burnFire`: 燃えた地点の家・民が消える／離れた火の腕が届いた先も消える／
  家と民で異なる impact type が飛ぶ
- 成長: 森の中の家が裸地の家より速く育つ
- 実ゲームで確認。森の帯を斜めに植え、その端に火の雨を1回落とすと
  **帯の端から端まで焼け、途中にあった家も消えた**。コンソールエラー0件

## 注意

アイコンの双方向テストが漏れを1つ捕まえた。アトラスに forest/fireRain の
フレームを足したが TS 側の一覧に入れ忘れており、「アトラスに使われない
フレームがある」で落ちた。この検査が実際に働いている。
