# 0029 miracle-haptics

## 背景

レビューが指摘した「奇跡にスペクタクル感がない」という弱点への、もう一つの
軽量な対応。画面演出（シェイク・トースト、#0027）はまだ未マージの
`enemy-god-ai`系ブランチに依存しているため、それとは独立に、Vibration API
による触覚フィードバックを追加した。このゲームは縦持ちスマートフォン専用
（`index.html`の`@media (orientation: landscape)`警告、PWAとしての
インストール想定）なので、画面を見ていなくても「何かが起きた」ことが
指に伝わる触覚フィードバックは相性がよい。

## アプローチ

`main.ts`に`vibrate(pattern)`ヘルパーを追加し、`navigator.vibrate`が
存在する場合のみ呼び出す（iOS Safari／iOSのホーム画面インストールでは
Vibration API自体が未対応のため、何も起きず静かに無視される — try/catch
ではなくoptional chainingで十分）。

`applyTool`内の各奇跡（集結地移動・地震・沼・火山・騎士化・最終決戦・
洪水）のマナ消費成功直後にそれぞれ異なる強さ・パターンで呼び出す：
- 集結地移動：15ms（最も軽い操作）
- 地震：40ms
- 沼：25ms
- 火山：[40, 30, 60]（噴火→間→衝撃、の起伏を表現）
- 騎士化：30ms
- 洪水：50ms
- 最終決戦：[60, 40, 60, 40, 100]（最も派手な演出）

素の隆起・沈降（`toolMode`の既定分岐）には振動を追加していない。ゲームの
コアループで最も頻繁に叩く操作であり、毎タップ振動すると煩わしいだけに
なるため。

## テスト

- `navigator.vibrate`はNode/vitest環境に存在しないAPIで、DOM操作のない
  ユニットテストの対象外のため自動テストは追加していない。
- ヘッドレスブラウザで`navigator.vibrate`をスタブして呼び出しを記録し、
  地震ツールをタップした際に`vibrate(40)`が実際に呼ばれることを確認した。
- `npm run typecheck` / `npm run test -- --run`（192件、ロジック変更なし）
  / `npm run build` がすべて成功。

## 残作業

- 各パターンの強さ・持続時間は感覚的に決めたもので、実機での調整余地が
  ある。
- 敵AIの奇跡発動（画面外で起きた場合）にも振動を連動させるかは、
  #0027（画面シェイク・トースト）がマージされてから改めて検討する。
