# 0092 Walkerの状態別ポーズ（戦闘・溺れ）

## 背景

ご指示 §11「Walkerの状態別animation」。plan/archived/0091 で walker の絵は
精細化したが、**どの状態でも同じ歩行アニメーション**だった。ECS には
`WalkerState`（`seeking` / `traveling` / `fighting` / `knight` / `guardian`）と
`Drowning` コンポーネントがあるのに、画面上はすべて同じに見える。

## 追加した2つのaction

フレームキーに `action` の次元を足した。

| action | いつ | 絵 |
| --- | --- | --- |
| `walk` | それ以外すべて | 4フレーム歩行（従来） |
| `fight` | `state === "fighting"` | 構え／突きの2ポーズ、足は踏ん張り |
| `drown` | `Drowning` あり | 両腕を頭上に、水面から上だけ |

`seeking` と `traveling` は**意図的に同じ絵**にしている。どちらも
「どこかへ向かっている人」であり、プレイヤーが行動を変えられない差を
描き分けても情報にならない。

`drown` は `fight` より優先する。沈みかけている walker はもう戦力ではなく、
プレイヤーにとってはそちらの方が急を要する情報である。

## silhouetteで差をつける

最初の実装では、腕を数ピクセル動かすだけの差にしていた。**11px幅の図形では
輪郭の内側で起きたことは何も読めない。** 戦闘は「立っている」ようにしか
見えず、溺れは「肩」にしか見えなかった。

作り直した版では:

- **戦闘の突き**は、先の腕を体から2列はみ出させて水平に伸ばす
- **溺れ**は、両腕を**頭より上**へ伸ばす（頭の横では自分の輪郭に埋もれる）

どちらも輪郭そのものが変わるので、実寸でも「何をしているか」が分かる。

## 溺れは体を切り落とす

`_render_drown` はスクラッチのCanvasに頭・肩・腕を描き、**水面より下を
捨ててから**本体のCanvasへ写す。切り落とすこと自体が「水の中にいる」と
いう表現であり、同時に見えない部分の絵を用意せずに済む。

`DROWN_BOB_BY_FRAME = [0, 1, 2, 1]` で沈み具合が上下する。静止していると
「水の上に立っている」ように見えてしまう。

溺れているときは剣も盾も描かない。沈みかけている人物が剣を掲げていたら
攻撃に見えてしまい、起きていることと逆になる。

## アトラスがインライン化されなくなった

192 → **576フレーム**（2陣営 × 6ポーズ × 3action × 4方向 × 4フレーム）。
`walkers.png` が 3.8KB → **14.6KB** になり、Vite の
`assetsInlineLimit`（4KB）を超えたため、data URI ではなく
**ハッシュ付きの独立アセット**として出力されるようになった。

これは望ましい方向（キャッシュが効く）だが、**本番の base パス
`/game2/` を初めて実際に通る**ことになるので検証した。

`vite preview` は base を `/` のまま serve する（vite.config.ts の
コメント通りの意図的な挙動）ため、**preview では本番のパス構成を再現
できない**。`dist` を `game2/` という名前で静的サーバに置いて確認した:
コンソールエラー0件、失敗リクエスト0件。

## 検証

- `npm run typecheck` 通過、`npm run test -- --run` 462件通過（+5件）
- `walkerAction` の単体テスト（`seeking`/`traveling` は歩行、hero は歩行、
  溺れが戦闘に優先する）
- フレームキーの双方向照合を `action` 込みに拡張
- `npm run sprites:check` — クリーンで exit 0
- 本番ビルドを `/game2/` 配下で実際にブラウザに読ませ、エラー0件を確認
- **実行時に fight / drown のフレームが解決して描画されること**を、
  EntityLayer に一時的なフックを入れて action を強制し、拡大
  スクリーンショットで目視確認した（フック自体はコミットしていない）。
  戦闘は構えの腕と踏ん張った足、溺れは頭上の腕と水面で切れた体が
  出ていることを確認
