# 0146 magnet-bound-to-leader

## 原作ではマグネットとリーダーは一組である

攻略資料に2つ、game2 が持っていなかった規則がある。

> **マグネット移動**：ただし、**リーダーがいない状態ではこのコマンドは
> 使用できない**（リーダーがいない場合は、まず啓示コマンドの「集合」で
> リーダーを作る必要がある）。

> **ペルセウス**：味方リーダーがヒーローに変身する。**影響で、味方リーダーが
> いなくなる。マグネットはリーダーのいた場所に移動する。**

後者は6英雄すべての説明に**一字一句同じ文**で置かれている。読み違えようが
ない。

## 何が変わるか

この2つは噛み合って1つのループを作る。

1. 集結でリーダーを立てる
2. リーダーが居るからマグネットを敵陣へ動かせる
3. 英雄に変えると**リーダーが居なくなり**、マグネットはその場に残る
4. マグネットはもう動かせない。次のリーダーを立てるにはまた集結する

原作の攻略が「敵リーダーを潰す→マグネットがその場に残る→別の敵ウォーカーが
触れてリーダーになる→また潰す」を得点稼ぎの型として挙げているのは、この
ループがあるからである（`popum01`）。

game2 は英雄を出してもリーダーのままで、マグネットは常に動かせた。集結は
1回打てば以後ずっと元が取れる操作になっていた。

## 実装

- `faction.ts` の `moveShrine` はリーダーが居なければ**動かさず false を
  返す**。`main.ts` は岩礁と同じ形で、マナを取る前に断る。
- `hero.ts` の `promoteHero` は昇格後に `leaderId` を消し、
  `shrinePosition` をリーダーが立っていた場所にする。

### 消えたもの：`heroBase`

英雄がリーダーでなくなるので、**英雄に別の英雄の神技を重ねる経路が無くなる**。
`heroBase`（再専門化で倍率が累乗にならないよう昇格前の値を覚えていた）は
到達不能になったので、フィールドごと消した。到達しないコードを、起きえない
挙動を説明するコメント付きで残す方が悪い。

## 検証

- `npm run typecheck` / `npm run build` パス、テスト822件パス（+2）。
- `faction.test.ts`：リーダーが居れば動く／居なければ動かず旗はそのまま／
  指していたリーダーが死んでいても動かない。
- `hero.test.ts`：昇格でリーダーが居なくなる／マグネットが立っていた場所へ
  移る／その後は集結地移動が使えない／英雄は再専門化できない。
- 既存テストを2件直した。`moveShrine` の「シンボルを差し替える」はリーダーを
  与える形に、`promoteHero` の「ヘラクレス→オディッセウス」は同じ盤面を
  2回作る形にした——**連続昇格そのものが起きなくなった**ので、数値の確認を
  経路から切り離す必要があった。
