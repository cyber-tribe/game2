# 0030 enemy-volcano-and-smart-targeting

## 背景

再評価レビューが指摘した敵AIの弱点のうち、優先度が最も高いとされた2点への
対応：

1. 「敵AIに地形・人口・マナ・都市価値を理解させる」— 現状の地震ターゲット
   選択は`randomOpponentHouse`という名の通り、敵の家からほぼ完全ランダムに
   1つを選んでいた。「どこを壊せば相手が一番困るか」という判断が一切ない。
2. 「敵に火山・洪水・沼を戦略的に使わせる」— `enemyMiracles.ts`が扱う奇跡
   はこれまで地震・騎士化・最終決戦のみで、経済的圧力の中間段階
   （地震ほど安くはないが最終決戦ほど大仰でもない一手）が存在しなかった。

## アプローチ

### ターゲット選択：ランダムから「最も密集した集落」へ

`randomOpponentHouse`を`densestOpponentCluster(world, opponentId, radius,
rng)`に置き換えた。各敵家について、指定`radius`以内にある敵家の数を
「密集度スコア」として数え、最も高いスコアを持つ家（複数あれば同点）を
候補とし、同点の中からのみ`rng`で選ぶ。単独の孤立した家より、寄り集まった
集落の方が必ず選ばれるようになる。

地震にはその効果範囲そのものである`DEFAULT_EARTHQUAKE_RADIUS`、火山には
`DEFAULT_VOLCANO_RADIUS`をスコアリング半径として使う——つまり「実際にその
一撃が巻き込む家の数」を直接最大化する形になっている。

### 敵の奇跡に火山を追加

人口比（自陣人口 ÷ 敵陣人口）による判断の中間段階として
`VOLCANO_POPULATION_RATIO`（1.3、既存の`ARMAGEDDON_POPULATION_RATIO`=1.8
と互角の1.0の間）を`constants.ts`に追加。優先順位は：

1. 人口比が`ARMAGEDDON_POPULATION_RATIO`以上 → 最終決戦（既存）
2. 戦闘態勢でリーダー未騎士化 → 騎士化（既存）
3. 人口比が`VOLCANO_POPULATION_RATIO`以上 → 最も密集した敵集落へ火山
   （新規）。地震と違い恒久的に土地を奪うため、まだ最終決戦ほどではない
   が確実なリードがある場合にのみ選ばれる、地震より一段強い経済圧力
4. それ以外は地震（既存、ターゲット選択のみ変更）

各段階は`trySpendMana`でマナを消費するプレイヤーと同じ経済を通すため、
火山を打てるだけのマナがなければ地震にフォールバックする。

## テスト

- `enemyMiracles.test.ts`に3件追加：
  - 人口比が`VOLCANO_POPULATION_RATIO`以上・最終決戦未満のとき、マナが
    足りれば火山を発動し対象の家を破壊すること
  - `VOLCANO_POPULATION_RATIO`未満では火山を打たず、より安い地震に
    フォールバックすること（消費マナ額で確認）
  - 一様ランダムなら最後の要素を選びがちな`rng`（0.99固定）を与えても、
    孤立した家ではなく密集した2軒の集落の方を地震のターゲットに選ぶこと
- `npm run typecheck` / `npm run test -- --run`（204件）/ `npm run build`
  がすべて成功。

## 残作業

- 洪水・沼はまだ敵の戦略判断に組み込んでいない。特に洪水は「相手の文明が
  低地に集中しているか」を判定する必要があり、地形解析がもう一段複雑に
  なるため別タスクとする。
- 敵神ごとの「性格」（拡張型・要塞型・災害型など）はまだ実装していない。
  現状は全ての敵が同じ優先順位ロジックに従う単一の人格。
