# 0054 terraform-brush

## 背景

POPULOUS 2との比較調査で、S評価の1項目として「大マップでも苦痛に
ならない造成UI」が挙げられていた。現状の地形編集（隆起/沈降）は
1回のタップで頂点1つだけを編集する仕組みで、`docs/game-system.md`の
核となるループ（`HOUSE_UPGRADE_FLATNESS_RADIUS`＝2、つまり家1軒を
アップグレードするには最大5×5＝25頂点を平らにする必要がある）を
こなすには、同じ操作を何十回も繰り返す必要がある。マップを拡張
すれば、この負担はそのまま比例して増える。

調査資料自身が例として挙げていた「長押し造成・ブラシ造成・連続
ドラッグ」のうち、既存の操作体系（タップ＝地形編集、ドラッグ＝
パン、2本指＝回転/ピンチズーム）を一切壊さずに追加できる案として、
「長押ししてからなぞる」ブラシ方式を採用した。

## アプローチ

### なぜ「長押し」なのか

既存の1本指ドラッグは常にカメラのパンに使われている
（`plan/archived/0009-pan-for-vertex-picking.md`）。もしドラッグ
そのものを地形編集に転用すると、隆起/沈降ツール選択中はパンが
一切できなくなってしまう。かといって新しいトグルボタンを追加すると
覚えることが増える。

そこで「その場で指を止めたまま`LONG_PRESS_DURATION_MS`（350ms）待つと
ブラシモードへ切り替わり、以降そのままなぞった頂点を次々編集する」
という方式にした：

- 素早いタップ（動かずにすぐ離す）→ 従来通り1頂点だけ編集。
- 素早いドラッグ（`DRAG_THRESHOLD`を超える前にブラシが発動しない）
  → 従来通りパン。
- その場で少し（350ms）待ってからなぞる → ブラシで連続編集。

3つとも既存のジェスチャーの延長線上にあり、新しいUIを覚える必要が
ない。ドラッグが先に`DRAG_THRESHOLD`を超えれば長押しタイマーは
即座にキャンセルされる（`clearLongPressTimer`）ため、パン操作の
体感は一切変わらない。

### 対象を隆起/沈降のみに限定

ブラシは`toolMode`が`"raise"`/`"lower"`のときだけ有効にした。他の
`toolMode`（集結地移動・地震・沼・火山・騎士化・最終決戦・洪水）は
いずれもマナを消費する単発の奇跡で、ドラッグでなぞって連打できて
しまうと経済バランスが崩れる（例：火山をなぞって連続発動するなど）
うえ、そもそも「1点を狙って発動する」操作性を壊してしまう。

### 実装

`main.ts`に以下を追加：

- `applyTerrainEditAt(vertex)`：マナ消費＋`raiseVertex`＋再描画という、
  既存の`applyTool`末尾（タップ時の隆起/沈降処理）と全く同じ処理を
  切り出した共通関数。タップ経由でもブラシ経由でも同じ関数を呼ぶ。
- `pointerdown`（1本指）：`toolMode`が隆起/沈降ならタイマーを仕込む。
  発火時、まだドラッグが始まっておらず・まだ1本指のままなら
  `painting = true`にし、押した位置の頂点を即座に1つ編集する
  （軽い振動で切り替わったことを知らせる）。
- `pointermove`：`painting`中は、現在の頂点が直前に編集した頂点と
  違う場合だけ`applyTerrainEditAt`を呼ぶ（`lastPaintedVertex`で
  重複編集を防止——指を止めたままだと毎フレーム同じ頂点へ課金され
  続けてしまうため）。
- `pointerup`/`pointerupoutside`/2本指への移行：`stopPainting()`で
  状態をリセット。

マナコストは頂点1つあたり`TERRAIN_EDIT_MANA_COST`のまま変更していない
——タップを何度も繰り返すのと同じ経済コストで、操作の手間だけを
減らす形にした。

### チュートリアルヒントへの追記

`index.html`の初回ヒントに「長押ししてなぞると、まとめて地形を
編集できる」を追記した。ブラシ自体は見た目の変化（新しいボタンなど）
が一切ないため、テキストで存在を伝えないと気づかれない。

## テスト

`main.ts`はユニットテスト対象外（ブートストラップ処理）のため、
ヘッドレスブラウザで実際のポインター操作をシミュレートして確認した：

1. 素早いクリック（`page.mouse.click`）→ 頂点が1つだけ変化すること。
2. 素早いドラッグ（`page.mouse.down`→即座に大きく`move`→`up`）→
   頂点が1つも変化しないこと（純粋なパンとして動作）。
3. 長押し（450ms待機）してからなぞる（3段階の`move`）→ 複数の頂点
   （実測5個）が変化すること。

`npm run typecheck` / `npm run test -- --run`（250件）/
`npm run build`がすべて成功。

## 残作業

- マップサイズそのものの拡張は別PRの予定——この造成UI改善はその
  前提となる独立した改善として先に実装した。
- 「都市周囲自動整地」（家をタップすると周囲を自動で平らにする）は
  今回実装していない。ブラシで手動になぞる方式で十分な改善になる
  と判断したが、マップを拡張した後で改めて必要性を見直す余地がある。
- ブラシ中の視覚的なフィードバック（なぞっている軌跡のハイライトなど）
  は追加していない。振動と、頂点が実際に変化していく見た目だけで
  モード切り替えを伝えている。
