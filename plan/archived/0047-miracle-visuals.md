# 0047 miracle-visuals

## 背景

ユーザーからの一連のフィードバック：

- 「沼ですが円だと範囲がよくわからないので、マス目を紫にするのは
  どうでしょうか？」——`EntityLayer.ts`の沼描画は、スクリーン座標に
  そのまま円を描いていた。等角投影のマス目は画面上では菱形に
  見えるため、円の縁がどのマスと重なっているのか判断しづらい。
- 「火山ですが、今は山の稜線にしか見えませんから、火山らしく
  マグマの表現が欲しいです。また頑張れば平地に戻せますよね?」
- （1回目の対応後）「全然火の表現になっていないので世の中の火山の
  表現を調べてください」
- （2回目の対応後、参考画像付き）「発行する亀裂ってなんですか
  普通はマグマが上の方にだけ流れている表現をしますよ」

なお「頑張れば平地に戻せる」は一貫して既存仕様の通り——`raiseVertex`
が呼ばれるたびに`rockHardness`が1減り、0になれば通常の地形へ戻る
（`docs/game-system.md`の「復旧には大量の地形操作が必要」）。今回の
一連の変更はこの既存挙動に、冷えていく見た目を追加しただけで、
ゲームロジック自体は変えていない。

## アプローチ

### 沼：円からマス目の紫塗りへ

`EntityLayer.ts`に`swampAffectedTiles(pos, radius, mapWidth, mapHeight)`
を新設（純粋関数、Graphics不要でユニットテスト可能）。沼の中心から
`radius`以内に中心を持つマス目だけを選び、そのマス目1つ1つを
`IsoRenderer.redraw()`と同じ菱形ポリゴンとして紫で塗る。
`swampSystem`自体の判定（ウォーカーの実座標と沼の中心の直線距離）
は変更していない——あくまで見た目をその判定に近い形で近似する。

### 火山：3回の描き直しを経た最終形

**1回目**：`rockHardness`に応じてタイル全体を暗い岩色〜明るい
マグマ色へ単純に線形補間するグラデーション塗り。→「全然火の表現に
なっていない」との指摘。

**2回目**：実在のゲーム（Terrariaの地獄、Stardew Valleyの火山
ダンジョン、Minecraftの溶岩、SimCity/RCTの災害火山）を調べ、
「岩は常に暗いまま、火は岩の中の亀裂として明るい別の色で描かれる」
という共通パターンを踏まえ、タイルの塗りを常に暗い岩色に固定し、
各タイルの中心から放射状に伸びる発光する亀裂を描く方式に変更。
→ 参考画像（クリップアート調の火山イラスト）とともに「発行する
亀裂ってなんですか、普通はマグマが上の方にだけ流れている表現を
しますよ」との指摘。市販の火山イラストは、山頂（火口）付近だけに
マグマが集中し、そこから山肌を数本の筋になって流れ下る——山の
どこにでも亀裂が散らばっているわけではない、という点を見落として
いた。

**3回目（最終形）**：`applyVolcano`は指定半径の頂点をすべて同じ
`MAX_ELEVATION`に一括で持ち上げるため、地形としては傾斜のある
円錐ではなく平らな台地になる。この形状で「山頂だけにマグマがある」
を再現できる場所は、台地が周囲の低い通常地形と接する**縁
（リム）**しかない。そこで：

- タイルの塗りは常に暗い岩色（`VOLCANO_ROCK_COLOR`）で固定。
- 4方向の隣接タイルをチェックし、隣が「岩でない（＝マップ外か
  通常地形）」タイルだけを**縁タイル**と判定する
  （`drawLavaFlow`内の`isRim`）。岩に囲まれた内側のタイルは、
  実物の火山の山体と同じく何もない暗い岩のまま。
- 縁タイルは、岩でない隣と共有する辺から、その方向へしずくが
  垂れるような三角形（`poly`）でマグマを描く——辺で幅広、先端で
  細くなる「流れ落ちる」形。辺の中点には小さな発光する核（噴出口）
  も添える。
- 本数・長さ・明るさは`rockHardness`に応じて変化し
  （`volcanoGlowIntensity`——純粋関数、`elapsedTime`と`tileHash`
  によるタイルごとの位相のずれで、全タイルが同期して点滅しない）、
  最低限の不透明度（`LAVA_MIN_ALPHA`）で冷えかけでも完全には
  見えなくならないようにした。
- 描画順は「全タイルの地形塗り→全ての溶岩流」の2パスに分離し、
  溶岩流が必ず最前面に来るようにした（先に描いた縁タイルの流れが、
  後から描かれる隣の低いタイルの地形塗りで上書きされて消えて
  しまう問題を避けるため）。

## テスト

- `src/render/EntityLayer.test.ts`：`swampAffectedTiles`が中心を
  囲む4マスだけを返すこと（半径1.2）、マップ端でのクランプ、
  半径が大きいほど対象マスが増えることを検証。
- `src/render/IsoRenderer.test.ts`：`volcanoGlowIntensity`が
  rockHardness＝0で常にゼロになること、rockHardnessが多いほど
  （パルス1周期分の平均で比較して）明るいこと、時間経過で明滅する
  こと、タイルごとに位相がずれること、純粋関数であることを検証。
- `npm run typecheck` / `npm run test -- --run`（245件）/
  `npm run build`がすべて成功。
- ヘッドレスブラウザで、半径2〜5の火山パッチを実際に配置し
  スクリーンショットで確認：内側は暗い岩のまま、縁だけにオレンジ色
  の溶岩が山肌を流れ落ちるように見えること、既定のカメラ位置
  （ズームアウト時）でも山の裾野に沿ってジグザグの発光帯として
  視認できることを確認した。最初の不透明度設定（0.45）では暗い岩
  との混色でくすんで見えたため、0.7へ引き上げて再確認した。

## 残作業

- 火山の発光表現・沼のマス目化は視覚的な改善のみで、ゲーム
  ロジック（`applyVolcano`/`eruptVolcano`/`swampSystem`）は一切
  変更していない。
- `applyVolcano`自体が台地状（平ら）にしか地形を持ち上げないため、
  今回の「縁だけ発光」は疑似的な近似——本物の円錐状に傾斜させる
  （中心から離れるほど低くする）よう`applyVolcano`を変更すれば、
  見た目上も本物の山らしくなり、マグマの流れもより自然に配置できる
  はずだが、地形そのものの形状を変えるゲームロジックの変更になる
  ため今回は見送った。
- 本物の加算合成（additive blending）は使っていない（Graphicsの
  半透明図形を重ねる擬似的な光暈）。
