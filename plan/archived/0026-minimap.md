# ミニマップ（世界儀）を追加する

## 背景

`docs/game-system.md`の「UI要素」節には元々こう書かれている。

> **世界儀（ミニマップ）**：世界全体の俯瞰。クリックで視点移動。

しかしこれまで一度も実装されていなかった。ユーザーから受け取った
戦略レビューも「画面全体にマップを収めるとタイルが小さくなるため、
ズームした状態でパンして操作する設計になっている。その結果、画面外で
敵に攻撃されていた、ということが起こり得る」「敵AIを高度化する前に、
世界全体で何が起きているか把握できるUIが必要」と指摘していた。特に
`plan/0025`で敵AIが自発的に地震・騎士化・最終決戦を仕掛けるように
なった直後だけに、この指摘は一層重い。

## 対応

`src/render/Minimap.ts`を新設した。等角投影（アイソメトリック）では
なく、単純なx/y平面への正射影で、世界全体を`size`×`size`ピクセルの
小さな枠に縮小して描く。

- 背景は地形タイプに応じた単色（`草原`/`砂漠`/`雪原`/`溶岩地帯`）。
- 家は勢力色の小さな正方形、ウォーカーは勢力色の小さな円。近くで
  見るドット絵ほど詳細ではないが、「どこに何があるか」を伝えるのが
  目的なのでこれで十分と判断した。
- `main.ts`で画面右上（HUDのテキストと重ならない位置）に固定表示し、
  毎フレーム`minimap.update(world)`で再描画する。

**クリックで視点移動**（原文通り）も実装した。ミニマップに
`eventMode = "static"`と専用の`hitArea`を設定し、タップされた
ミニマップ上の座標をワールド座標に変換したうえで、`renderer.view`の
`position`をそのワールド座標が画面中央に来るよう再計算する。
二本指回転（`plan/0024`）で導入した「ある画面座標に対応するワールド
座標を固定したまま`position`を再計算する」手法をそのまま流用できた
（回転角はそのまま、平行移動だけ求める特殊ケースとして書ける）。

ミニマップのタップが背後の本編マップ（`app.stage`のポインタハンドラ）
にも伝播して地形編集やパン開始を誤爆させないよう、ミニマップ自身の
`pointerdown`ハンドラで`event.stopPropagation()`している。

## テスト

- `npm run typecheck` / `npm run test`（190件、ロジック変更なし） /
  `npm run build` すべて成功（`Minimap`は他の`render/`配下のクラスと
  同じく描画専用のためユニットテストは追加していない）。
- ヘッドレスブラウザで、両陣営の家・ウォーカーが世界中に散らばった
  状態でミニマップに両陣営の点が正しい配置で表示されることを確認。
  ミニマップの一角をタップし、本編側のカメラが実際にその方向へ
  移動する（それまで見えていなかった水域が新たに視界に入る）ことを
  スクリーンショットで確認した。

## 積み残し

- 現在の可視範囲（ビューポート）を示す枠線はミニマップ上に描いて
  いない。アイソメトリック投影の逆変換が必要になるため今回は
  スコープ外とした。
- 奇跡発動などのイベントをミニマップ上でハイライトする（例:
  地震が起きた場所を一瞬光らせる）といった通知機能は未実装。
