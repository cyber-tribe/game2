# 0095 地震を原作の「方向を持つ長い地割れ」に作り替える

## 背景

`docs/original-miracles.md` の実装順序に従い、「既にあるが性質が違うもの」の
第2弾（第1弾は plan/0094 の津波）。

原作の地震（#13）は:

- 指定地点から**長い地割れ**を発生させる
- **方向を持つ**（原作はポインタで示す）
- **亀裂に落ちると死亡**し、**修復されるまで残る**

旧 `applyEarthquake` は半径2の円内の頂点をランダムに上下させるだけだった。
方向がなく、残るのは「一時的に平地でなくなる」ことだけで、原作の3点を
どれも満たしていない。

## 地割れを地形の新しい層にした

`Heightmap.crevice: boolean[][]` を追加した。**標高とは別の層である必要が
ある。** 地割れは単なる低地ではない — 落ちれば死に、埋めるまで残り、
後に花（#7）が塞ぎ、ヘラクレス（#15）は落ちない。これらは「標高0である」
では一つも表現できない。低地は民が平気で立っている場所である。

- `applyEarthquake` が中心線を `MIN_ELEVATION` まで削り `crevice` を立てる
- `isBuildable` が地割れを弾く
- `systems/crevice.ts` が地割れ上の walker を毎tick殺す
- `raiseVertex` で埋め戻すと `crevice` が下りる（岩の hardness を削るのと同じ形）

`creviceSystem` は**毎tick走る**。洪水の `drownFlood` のような一度きりの
掃引ではない。地割れは残るので、危険なのは「開いた瞬間にそこにいたこと」
ではなく「後から入ってしまうこと」である。これが旧地震との決定的な差で、
旧版は地面を掻き回した後は何の意味も持たなかった。

## タップUIで方向を決める

原作はポインタで方向を示すが、タップには方向を運ぶ第2の軸がない。
**自陣の集結シンボルからタップ地点へ向かう向き**を採った。「自分のいる所から
狙った所へ」が自然に読め、しかも**自陣へ向けて地面を割ってしまうことがない**。
敵AIも同じ規則で自分のシンボルから狙う。

## 描画のバグを1つ潰した

地割れが**草地として描かれていた**。`fillTerrainTriangle` は平坦な三角形に
対して `baseColor` を無視し地形のディザテクスチャで塗る近道を持っており、
地割れは床まで平らに削られるので必ずその経路に入っていた。

引数を `isRock` から `hasOwnColor` に変えて、岩と地割れの両方がこの近道を
迂回するようにした。

## 太さ

当初は中心線に加えて垂直方向の隣接頂点も削っていた。タイルは4隅のどれかが
地割れなら地割れとして描かれるので、これだと**黒い塊**になり亀裂に見えない
（実測でスクリーン上10043px）。中心線のみにして4909pxになり、裂け目として
読めるようになった。

殺傷判定には幅は要らない。`creviceSystem` は毎tick見ており、幅1頂点の帯でも
walker は数十tickその中にいる。

なお、**描画される範囲は殺傷範囲より広い**。タイルは4隅のいずれかが
地割れなら暗く描かれるが、殺傷判定は最近傍頂点で行うため。危険に見えて
実は安全、という方向のズレなので安全側に倒れている。逆（見えないのに死ぬ）
にはならない。

## 検証

- `npm run typecheck` 通過、`npm run test -- --run` 477件通過（+6件）
- `applyEarthquake`: 方向通りに走ること、逆向きに撃てば逆へ走ること、
  線であって円でないこと、床まで削ること、建築不能になること、
  地図の縁で止まること、方向ゼロでも何かすること、埋め戻すと閉じること
- `systems/crevice.ts`: 地割れ上の walker が死ぬこと、無関係な walker は
  生きること、**単に低いだけの地形では死なないこと**（層を分けた理由そのもの）、
  **開いた後のtickでも殺すこと**（永続性）、`onImpact` が飛ぶこと
- 実ゲームで撃って目視確認。集落から離れる向きへ長い亀裂が走り、
  暗く描かれ、コンソールエラー0件
