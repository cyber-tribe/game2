# 0049 miracle-counters

## 背景

これまでの実装は奇跡それぞれが独立していて、奇跡同士が互いに影響し
合うことがなかった。「原作の基本システムはかなり再現しているが、
（続編的な意味での）システム同士の相互作用の豊かさにはまだ達していない」
という調査結果を踏まえ、既存の奇跡だけで成立する、最初の相互作用
（カウンター/コンボ）を2つ追加した。新しい奇跡・新しいUI・新しい
アセットは追加せず、既存の`地震`・`沼`・`洪水`・`火山`の間に関係性を
足すことに絞った。

## アプローチ

### 地震 → 沼 のカウンター

`地震`は元々「対象範囲の地形をランダムに隆起・陥没させ、平地を壊す」
という経済妨害目的の奇跡だが、地面を掘り返すという性質上、そこに
沼があれば当然干上がる/崩れると考えるのが自然。`src/game/swamp.ts`に
`collapseSwampsNear(world, x, y, radius)`を追加し、地震の着弾範囲
（`applyEarthquake`と同じ半径）と沼の危険範囲が重なっていれば、
その沼を即座に消滅させるようにした。プレイヤー・敵AI両方の地震発動
箇所（`main.ts`のtoolMode==="earthquake"、`enemyMiracles.ts`の地震
分岐）から呼ぶ。

これにより、`地震`に「相手の沼を安全に踏み荒らす」という新しい使い道
が生まれる。逆に言えば、沼を設置する側も、相手が地震で無力化して
くる可能性を意識する必要が出てくる。

### 洪水 → 火山 のコンボ

`火山`の岩（`rockHardness`）は`raiseVertex`を繰り返し当てることでしか
冷えない。`洪水`が海面（`waterLevel`）を上げる奇跡である以上、
文字通り「溶岩が海に沈んで冷える」を再現したくなるが、火山の頂点は
常に`MAX_ELEVATION`（20）に固定されるのに対し洪水1回の上昇量は
`DEFAULT_FLOOD_AMOUNT`（1）しかなく、実際に沈むには数十回の洪水
詠唱が必要で、`FLOOD_MANA_COST`（70）を踏まえると現実的にまず
到達しない条件になってしまう。

そのため「水位が上がる」という洪水の性質を、個々の頂点の水没判定
ではなく、マップ全体の水位上昇として捉え直し、`applyFlood`に
「詠唱するたびに、存在する全ての火山岩の`rockHardness`を
`FLOOD_ROCK_COOLING`（1、`raiseVertex`1回分と同じ量）だけ下げる」
処理を追加した。特大コスト（70）で全体に影響する数少ない奇跡である
洪水に、既存の`頑張れば平地に戻せる`（`rockHardness`を地道に削る）
プロセスを一気に後押しする副次効果を持たせた形。

## テスト

- `src/world/heightmap.test.ts`：`applyFlood`が既存の火山岩の
  `rockHardness`を`FLOOD_ROCK_COOLING`だけ下げること、0未満には
  ならないこと、岩でない頂点には影響しないことを検証。
- `src/game/swamp.test.ts`：`collapseSwampsNear`が範囲が重なる沼を
  破壊すること、重ならなければ何もしないこと、範囲内の沼すべてを
  まとめて破壊すること（範囲外は残す）を検証。
- `npm run typecheck` / `npm run test -- --run`（256件）/
  `npm run build`がすべて成功。

## 残作業

- 今回追加したのは2つの相互作用のみ。他の組み合わせ（例：森×火の雨に
  相当するような「延焼」、ハリケーン×沼のような「押し流してから沈める」
  連携）は、対応する片方の奇跡（森・ハリケーンなど）自体がまだ存在
  しないため見送った。
- 敵AIは`洪水`をそもそも詠唱しないため、火山カウンター側の恩恵は
  今のところプレイヤー側にしか回らない。敵AIに洪水を持たせるかは
  別タスク。
