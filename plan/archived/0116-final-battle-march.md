# 最終決戦が終わらない試合を直す

## 見つけ方

「10分放置しても決着しない」と報告したが、**それは測り方の産物だった**。
`MIN_ARMAGEDDON_TIME = 600` で、敵は10分経つまで最終決戦を撃てない設計
（plan/archived/0045・0053）。600秒ちょうどで切っていたので、決着が
出ないのは当たり前だった。

600秒を超えて回すと最終決戦は**8試行中7試行で発動する**。条件は壊れて
いない。壊れていたのは**その後**だった。

## 原因

`systems/goToShrine.ts` は

1. **リーダーが生きていること**を要求し（`state.leaderId` が死んでいたら
   その陣営の処理を丸ごと `continue`）
2. リーダー以外は**シンボルではなくリーダーの位置**へ向かわせる

一方 `leaderSystem` は「集結」中しかリーダーを立てない（plan/archived/
0067）。最終決戦中にリーダーが死んでも**誰も後任を立てない**。

計測がそのまま出た（最終戦線、無操作）:

```
t= 600  リーダー 自分:生存 敵:生存   中央 自分1 / 敵0
t= 780  リーダー 自分:生存 敵:死亡   中央 自分171 / 敵1    ← 敵の軍が来なくなる
t=1140  リーダー 自分:死亡 敵:死亡   中央 自分29 / 敵0     ← 両軍とも散る
```

**リーダーが死んだ瞬間、その陣営の軍は行進をやめて放浪へ戻る。** 両軍が
散ると二度と接触せず、`getOutcome()` は「両陣営とも民が残っている」と
見るので永久に決着しない。5試合中4試合で、決戦の途中にどちらかの
リーダーが死んでいた。

## 直し方

**最終決戦の行進だけリーダーを介さない。** `finalBattle` が立っている
間は、民は自分でシンボル（＝中央）へ向かう。リーダーが居ても居なくても
関係ない。

docs の「全ての民が家を捨てて**中央に集まり**」がまさにそれで、
**中央は場所であって人ではない**。リーダー追従は通常時の「集結シンボル
へ」の挙動として残っている。

## 計測（最終戦線・無操作・8試行×1500秒、同一条件でA/B）

| | 最終決戦が発動 | うち決着した | 決戦の長さ |
|---|---|---|---|
| 変更前 | 7/8 | **2** | 42秒, 362秒 |
| 変更後 | 6/8 | **6（全部）** | 65〜97秒（中央値80秒） |

変更前は25分回しても6試合が未決着のまま。変更後は**発動した決戦が
すべて1〜1.6分で終わる**。

変更後にも「未決着」が2試合あるが、これは**最終決戦が一度も発動しなかった**
試合（人口比が25分間 1.53 に届かなかった）で、別の話——発動条件そのものは
今回は触っていない。

なお決着した6試合のうち2試合は**放置していたプレイヤーが勝っている**。
敵は人口比1.53で決戦を宣言して、そのあと乱戦で負けている。これは
「決着ボタンは賭けでもある」という意味では筋が通っているが、宣言条件を
総戦力ベースへ変える話（原作マニュアルの "population is larger and
stronger"）はここでは扱わない。

## 検証

- 698 → 706テスト。`goToShrine`（最終決戦ではリーダーではなく中央へ／
  **リーダーが死んでも行進が続く**／リーダーが一度も立っていなくても
  行進する／相手陣営の民には触れない／**病んだ民と魅了された民は
  除外のまま**）
- typecheck / build / `sprites:check` / `palette:check` 通過
- 実機確認は行っていない。この変更は10分以上経ってから起きる挙動で、
  描画にもUIにも触れていないため、実時間で再現するより上のA/Bの方が
  証拠として強い
