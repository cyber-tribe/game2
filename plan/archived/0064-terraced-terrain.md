# 0064: 地形をメッシュから断層（テラス状）表現に変更する

## 背景

ユーザーから、原作Populous風の参考画像（テラス状に段になった地形、
階段状の断面が見える崖）を添えて次の要望があった。

> メッシュではなくこれと同じように断層で表現できないですかね?

これまでの`IsoRenderer.redraw()`は、タイルの4頂点それぞれの高さを個別に
`toScreen(x, y, elevation)`で投影し、4点をつなぐ四角形として描画していた。
これは頂点間の高低差をなめらかな傾斜（スロープ）として表現するもので、
「メッシュ」的な見た目になっていた。参考画像のような、平坦な台地とその間の
垂直な崖面で構成される段々（テラス）状の見た目にはなっていなかった。

## 設計

地形データモデル（`Heightmap.vertices`、頂点ごとの高さ）自体は変更しない。
`raiseVertex`/`lowerVertex`・地震・洪水・火山などのゲームロジックは
すべて頂点ベースの実際の高さを見ているため、ここを変えると影響範囲が
非常に大きくなる。あくまで**描画方法だけ**を変える。

### タイルを「平らなブロック」として描画する

各タイルの4頂点の高さの平均（`tileHeight`）を求め、4隅すべてをこの
`tileHeight`で投影して描画する。これにより各タイルは必ず水平な
（画面奥行き方向に傾かない）面になり、ブロックの「天面」になる。

### 隣接タイルとの高低差を崖面として描画する

各タイルについて、上下左右4方向の隣接タイルの`tileHeight`と比較し、
自分の方が高ければ、その差分だけ下に伸びる四角形（崖面）をタイル境界に
沿って描画する（`drawCliffWalls`）。色は天面の色を`CLIFF_SHADE_AMOUNT`
（0.35）だけ黒に近づけたもので、天面よりわずかに暗い陰影のついた
垂直面として見える。

マップの外側（範囲外の隣接タイル）は高さ0（海面）とみなす。これにより、
標高のあるマップの外周には必ず崖面が描かれ、ジオラマの台座のような
縁取りになる。

隣接タイルとの高低差が`CLIFF_MIN_STEP`（0.05）以下の場合は崖を描かない。
これは`update()`によるイージング中の浮動小数点の微小な差でチラつく
崖が一瞬発生するのを防ぐための閾値。

### 描画順序

崖面はタイルの天面と全く重ならない（天面は同一標高の水平な面、崖面は
境界線上を高低差ぶんだけ垂直に埋める面なので、幾何学的に交差しない）。
ただし、非常に高い崖（最大`MAX_ELEVATION`×`ELEVATION_STEP`=320px）は
画面上で何行分も離れた別のタイルの領域まで届きうるため、遠くのタイルとの
前後関係だけは描画順序が正しくないと破綻する。

そのため、従来の行優先（y→x）ループから、対角線（x+y が小さい順）の
ペインターズアルゴリズム順に変更した。x+yが小さい（画面奥）タイルから
先に描画し、x+yが大きい（画面手前）タイルを後から描画することで、
奥のタイルの崖が手前のタイルより後に上書きされてしまう事態を防ぐ。

## 検証

- `npm run typecheck` / `npm run test -- --run` / `npm run build` すべて通過。
- `src/render/IsoRenderer.test.ts`に`IsoRenderer.redraw (terraced blocks)`
  を追加し、以下を確認:
  - 海面高度で完全に平らなマップは崖を1つも描かない。
  - 一部を隆起させると崖の描画（fillの数の増加）が発生する
    （頂点共有の性質上、単一タイルの隆起は隣接タイルの平均高度にも
    波及するため、正確な枚数ではなく「増える」ことのみを確認）。
  - 崖の色は天面の色よりRGB各チャンネルが暗い。
  - `CLIFF_MIN_STEP`未満の差では崖が描かれない。
  - マップ外周（標高0未満とみなされる範囲外）でも崖が描かれる。
- Playwright（headless Chromium）で実際にワールドを選択し、隆起ツールで
  地形を持ち上げてスクリーンショットを確認したところ、参考画像同様の
  段々状の台地と陰影のついた崖面が描画されることを目視で確認した。
- デバッグ用に一時的に`window`へフックを生やし、標高20（最大値）の
  単独の尖った隆起と、標高2/8のチェッカーボード状の地形を直接
  ハイトマップに書き込んでスクリーンショットを取得し、非常に高い崖でも
  奥のタイルとの重なり（zファイティングや隙間）が発生しないことを
  対角線描画順の効果として確認した（デバッグフックはコミット前に削除済み）。

## 影響範囲外

- `pickVertex`は引き続き頂点の実際の高さを使って最寄りの頂点を探す
  （編集対象は変わらず頂点なので）。天面が平均高度で描画される境界タイル
  では、選択中の頂点マーカーが見た目の地面よりわずかに浮く/沈むことが
  ありうるが、ブロック状表現をとる以上避けられない副作用として許容する。
- 水位・溶岩（`VOLCANO_ROCK_COLOR`・`drawLavaFlow`）の判定ロジックは
  変更していない（`tileHeight`を使うようになった以外は同じ比較）。
