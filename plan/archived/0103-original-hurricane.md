# 0103 ハリケーン —— 用意した地形へ押し込む

## 背景

ユーザーが挙げた「落としてはいけない相互作用」の**最後の1つ**、
**ハリケーン → 沼／亀裂**。

原作 #20:

> 指定方向へ強風。建物を壊し人を吹き飛ばす。**方向を持つ**

相互作用の表:

> 吹き飛ばす先に沼や亀裂を用意して即死地形へ押し込む

受け皿（沼・亀裂）は両方とも既に入っているので、**方向を持つ吹き飛ばし**を
足せばこの相互作用は閉じる。

## 何も殺さない奇跡

`applyHurricane` は**誰も殺さない**。家は壊すが、民は移動させるだけである。

これが原作の言う相互作用そのもので、専用のルールを1行も書いていない。
ハリケーンは人を動かし、`swampSystem`・`creviceSystem`・`fungusSystem`・
`drowning.ts` が次のtickでそれぞれの仕事をする。**開けた土地に吹けば軍が
散り、沼の上へ吹けば軍が消える。違いは撃つ側が何を用意していたかだけ**で、
それがこの奇跡の全部である。

テストも「ハリケーンの中に沼判定を書く」のではなく、
**ハリケーン → 既存システム**の順に呼んで結果を見ている。

## 形が奇跡そのもの

長さ12・幅2（軸の両側）の細長い回廊で、円ではない。**方向を持つ**のがこの
奇跡の特徴なのに、広い爆風にしてしまうと狙う意味がなくなる。

発動方向は地震・竜巻と同じく**自軍の集結地から見て指定地点の向こう**。
ここでは方向こそが奇跡の中身で、「何の中へ吹き込むか」を決める。

## 竜巻との違い

同じ「風」でも、竜巻は**さまよい続ける**もの、ハリケーンは**一度きりで
狙える**もの。原作が両方持っている理由はここにあり、実装でも竜巻だけが
エンティティとして残り、ハリケーンは即座に解決して消える。

## 検証

- 569 → 579テスト。進路上の民を風下へ飛ばす／家を壊す／**後ろは無傷**／
  回廊の外は無傷／射程外は無傷／斜めに撃てば斜めに飛ぶ／**単体では誰も
  死なない**。相互作用は、風下に沼を置いたとき／地震の亀裂が走っていたとき
  に死に、何も無ければ生きたまま
- typecheck / build / `sprites:check` / `palette:check` 通過
- **本番ビルドを静的配信して**実機確認（`dist` を `/game2/` に置いて
  `python3 -m http.server`）。沼を置いてからその方向へハリケーンを撃ち、
  どちらも発動して戦績に「あなたが沼を作った」「あなたがハリケーンを
  起こした」が並ぶことを確認。コンソールエラーなし

### dev サーバーではなく本番ビルドで確認した理由

`vite dev` だと確認スクリプトの途中でページが再読み込みされ、ワールド選択
画面に戻ってしまう事象が続いた（service worker を止めても、ソース変更以外
でも起きる）。`dist` を静的配信すれば HMR も SW 更新も無く、ついでに
**本番の `base: "/game2/"` のパス解決も一緒に検証できる**。以後の実機確認は
この方法を既定にする。

## 気づいたこと（要判断）

実機確認で、**開始46秒の1発で試合が終わった**（敵の家がすべて回廊に入って
いた）。序盤は敵の家が集結地の周りに固まっているので、そこへ真っ直ぐ吹くと
一掃できてしまう。

面積で比べると、火の雨が半径3の円（約28タイル）で25マナ、ハリケーンが
12×4の回廊（約48タイル）で28マナ。ただしハリケーンは**民を殺さない**ので
1発あたりの致死力は火の雨より低い。強すぎると判断される場合、調整の
つまみは長さ（`HURRICANE_LENGTH`）で、9まで縮めれば面積はほぼ火の雨と並ぶ。
1回の観測で数字を動かすのは避け、事実だけ記録しておく。
