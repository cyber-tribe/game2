# 0136 no-terraform-stages

## 背景

原作記事の問題点に、折りたたまれたステージ解説がある。

> **土地上げ不可ステージ**
> 必然的に開始時にある山を切り崩して平地を確保するのだが、間違って海面に
> まで掘り下げると復帰不能。
> **土地下げ不可ステージ**
> 上記と同様の理由。今ある山の周辺は諦めて、海岸沿いの建物を中心に自動整地
> すればいいのが救い。
> **土地上下不可ステージ**
> 互いに建物を建てられるマス数が両手で数えられるほどであり、互いの島も
> 繋がっていない。よって神業で敵の住める土地をゼロにすることになる。

game2 の `TerrainEditRule` は `both` / `raiseOnly` / `lowerOnly` の3値で、
最初の2種は入っていた。**3種目が無かった。**

## 実装

`TerrainEditRule` に `"neither"` を足し、`isTerrainEditAllowed` が常に
false を返すようにした。既存の呼び出し側（プレイヤーのタップ、
`enemyTerraform`、`flattenTile` の頂点ごとの判定）は全てこの1関数を
通っているので、判定そのものの追加は1行である。

UI 側で足したのは2点。

- **封じるボタンは4つ。** 隆起・沈降だけでなく**平坦化・自動整地も**
  無効にする。どちらも同じ頂点編集（`flattenTile`）でできているので、
  有効なまま残すと「押せるのに何も起きないボタン」が2つ増える。
- **初期選択を「照会」にした。** `lowerOnly` のときに `lower` を初期値に
  していたのと同じ理由——最初のタップが何も起こさないのは避ける。
  照会はパネル自身が「何も構えていない状態」に使っている中立の道具で
  （`ui/toolbar.ts` は系統を切り替えたとき照会へ戻す）、新しい約束事を
  作らずに済む。

## どの面に置くか

**最後の神（冥王ハデス）だけ**にした。記事の言う「神業で敵の住める土地を
ゼロにする」が成立するのは、奇跡が揃っている場合だけである。ハデスの面
では最終決戦を含む全ての奇跡が解禁済みなので、鋤を取り上げても手は残る。

これはワールドの難易度曲線（`WORLDS` の「どの軸も緩まない」という並び）
の終点としても自然である。上下とも可 → 片方向のみ → 上下不可。

カスタム対戦の抽選（`TERRAIN_EDIT_RULE_WEIGHTS`）にも 0.25 で入れた。
記事がこの面を**問題点**として挙げている以上、引けはするが滅多に
当たらない、が正しい重みである。

## 検証

- `npm run typecheck` / `npm run build` パス。
- `npx vitest run` 796件パス（+4）。
- `heightmap.test.ts` に `neither` が全方向を禁じる件と、抽選で引ける件。
  既存の重みテスト2件は新しい列挙子を持つよう直した。
- `worlds.test.ts` に「キャンペーンが原作の制限3種を全て使う」件と
  「上下不可の面では奇跡が全解禁されている」件。後者は数合わせではなく、
  この面が成立する条件そのものである。
- 実機で確認した。一時的に1面目を `neither` にして撮影し、隆起・沈降・
  平坦化・自動整地の4つが暗く、照会が選択済みで、HUDに「土地上下不可」が
  出ることを見た（撮影後に戻した）。

## 積み残し

そのHUDの行は**ミニマップの下に隠れて読めない**。これは今回入れた面に
限らず、`raiseOnly` の面でも、そもそも常に出ている「地形: 草原」の行でも
同じで、ミニマップを左上へ動かしたとき（`plan/archived/0130`）から続いている
別の不具合である。この面を入れたことで見える機会が増えるだけなので、
独立したPRで直す。
