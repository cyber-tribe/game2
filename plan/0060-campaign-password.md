# 0060: 征服モードにパスワード継続機能を追加する

## 背景

plan/0059でワールド選択画面を追加したが、全ワールドが常に選択可能な
ままで、`docs/game-system.md` 10節が定める「クリアするとパスワード
（ワールド名）が与えられ、そこから再開できる」というロック/継続の
仕組みがなかった。ロック機構なしのパスワード入力は、既に選べる
ワールドを選び直すだけの意味のない機能になってしまうため、この
PRでロックとパスワードの両方をセットで実装する。

「勝ち方の内容（残存人口など）に応じて数ワールド先へスキップできる」
という細かいスキップ量の調整はスコープ外——今回は「勝てば必ず次の
1ワールド分だけ解禁」というシンプルな規則にした。

## 実装

- `src/game/worlds.ts`: `nextWorldId(worldId)`（クリアしたワールドの
  次のワールドのid＝パスワードそのもの）と`unlockedCountForPassword
  (password)`（そのパスワードが何番目までのワールドを解禁するか）を
  追加。パスワードをハッシュ化したり別の文字列に変換したりせず、
  ドキュメントの「パスワード（ワールド名）」という注記の通り、
  ワールドのid自体をパスワードとして扱う。
- `src/main.ts`:
  - `showWorldSelect()`に`unlockedCount`（初期値1＝最初のワールドのみ）
    を持たせ、それ以降のワールドは🔒付きで無効化して表示。パスワード
    入力欄で有効なワールドidを入力すると`unlockedCount`を更新して
    再描画する。無効なパスワードは`#world-select-password-error`で
    知らせる。
  - あえて`localStorage`等での自動引き継ぎは行わない——
    ページ再読み込み（`#play-again`の`window.location.reload()`）の
    たびに`unlockedCount`は1にリセットされ、プレイヤーは前回表示された
    パスワードを自分で控えて再入力する必要がある。昔ながらの
    「紙に書き写すパスワード」の体験をそのまま再現する意図的な設計。
  - `showMatchRecord()`にプレイヤーが勝った場合の分岐を追加し、
    `nextWorldId(world.id)`の結果をパスワードとして表示
    （最終ワールドをクリアした場合は代わりに祝辞を表示）。
- `index.html`: `#world-select`にパスワード入力欄とエラーメッセージ、
  ロックされたワールドボタンの見た目（🔒アイコン・disabled・半透明）を
  追加。

## 検証

- `npm run typecheck` / `npm run test -- --run`（310件）/ `npm run build`
  すべて通過。
- `worlds.test.ts`に`nextWorldId`/`unlockedCountForPassword`の単体テスト
  （中間ワールド、最終ワールド、存在しないid、パスワードの往復）を追加。
- headless Playwrightで確認: 起動直後は最初のワールド以外すべて🔒表示・
  クリック不可であること、無効なパスワードでエラーが出ること、有効な
  パスワード（例:`frozen-border`）でそこまでのワールドが解禁される
  こと、実際に敵陣営を全滅させて勝利すると「🔑 次のワールドの
  パスワード: dry-highland」のように表示されることを確認
  （検証用に一時追加した`window.__debug`フックは確認後に削除済み）。
