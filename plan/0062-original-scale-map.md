# 0062: 原作同様に64×64の広いマップの一部だけを表示し、パンして操作する

## 背景

これまでは各ワールドのマップ全体を画面の高さに収まるよう自動で
縮小して表示していた（`layout()`が`baseScale`をマップサイズと画面の
空き高さから逆算）。plan/0061でワールドごとのマップサイズが最大
32×32まで育ったことで、この自動縮小の影響がより強く出て、
タイルが小さくなりすぎて操作しにくいという指摘があった。

原作の意匠に合わせ、マップ全体は固定64×64とし、画面には常に原寸大
（タイルの本来のピクセルサイズ）の一部だけを表示し、プレイヤーが
パンして移動する方式に変更する。

## 実装

### カメラ

- `main.ts`: `layout()`のマップ全体を画面に収める自動縮小ロジックを廃止。
  `BASE_MAP_SCALE = 1`固定とし、ピンチ/ホイールによるズーム倍率
  （`MIN_ZOOM_FACTOR`〜`MAX_ZOOM_FACTOR`、0.5〜2.5倍）だけが
  この上に乗る。
- 初回起動時のみ、プレイヤー自身の本拠地（`Simulation.getShrinePosition
  ("player")`、新規追加）を画面中央に表示するようカメラを合わせる。
  以後のレイアウト再計算（画面回転など）ではカメラ位置を保持し、
  プレイヤーが移動した場所を勝手に戻さない。
- `IsoRenderer.centerOn()`（マップ全体を画面に合わせて配置していた
  旧メソッド）は使われなくなったため削除。

### 描画のスケール対応（ビューポートカリング）

64×64（4096タイル）を毎フレーム全部再構築すると、素朴に実装した
場合フレーム時間が32×32比で4倍近くに悪化することを計測で確認した
（後述）。原作のハード制約と同じ理屈で、画面に映る範囲だけを
再構築するようにした：

- `IsoRenderer.visibleTileBounds()`（新規、純粋関数）: 画面4隅を
  `view.toLocal()`でローカル座標に変換したものを受け取り、
  `toScreen(x,y,elevation=0)`の逆変換でタイル座標の範囲を求める。
  標高（最大`MAX_ELEVATION`=20）による見た目のズレ分だけ余白を
  加える。
- `IsoRenderer.redraw(bounds?)`: `bounds`が渡されればその範囲だけを
  再構築する（省略時は従来通り全体、コンストラクタやテストで使用）。
  岩盤・溶岩流の判定に使う`isRockTile`/`avgHardnessGrid`もこの範囲
  だけをオフセット付きで構築するよう書き換えた。
- `main.ts`: 毎フレーム`visibleBounds()`で現在の可視範囲を求め、
  `renderer.redraw(bounds)`に渡す。地震・火山・洪水などその場で
  即座に見た目を反映させたい既存の呼び出し箇所も同様に更新。

### 無駄な再構築のスキップ

カメラが静止していて地形も変化していないフレームでは、
`redraw()`は直前と全く同じメッシュを作り直すだけの無駄な処理になる。
`IsoRenderer.isAnimating(bounds)`（新規）で「地形の高さがまだ
イージング中」または「範囲内に溶岩が点灯中」を判定し、可視範囲が
変わっておらずこれもfalseなら`redraw()`自体を呼ばないようにした
（`main.ts`のticker）。他勢力が画面外で地形を編集し続けていても
無関係に再構築が走らないよう、判定は渡された`bounds`の範囲だけを
見る。

### マップサイズに伴うバランス調整

- `TILES_PER_HOUSE_CAP`（`src/game/constants.ts`）を12→48に変更。
  32×32→64×64はタイル数が4倍になるため、変更前のまま据え置くと
  `maxHousesPerFaction`も4倍に膨らみ、戦闘/合流系のO(n²)処理の
  最悪ケースが悪化する。plan/0055と同じ考え方で、4倍にスケールし
  据え置くことで`maxHousesPerFaction`自体はほぼ変わらない
  （約85）ようにした。
- `src/game/worlds.ts`: 全ワールドの`worldWidth`/`worldHeight`を
  固定64に統一（`WORLD_SIZE`定数）。マップサイズは難易度軸ではなく
  なったため、doc commentとワールド選択画面の説明文からサイズ表記を
  削除。

## 検証

- `npm run typecheck` / `npm run test -- --run`（323件）/ `npm run build`
  すべて通過。
- `IsoRenderer.test.ts`に`visibleTileBounds`（往復・複数コーナー・
  余白・マップ境界クランプ）と`isAnimating`（イージング中/溶岩点灯中/
  範囲外は無視、の各ケース）のユニットテストを追加。
- パフォーマンス計測（esbuildで`IsoRenderer.ts`を直接バンドルしNode上で
  計測）: 32×32全体再構築が約2.2ms/frame、64×64全体再構築が約9ms/frame
  （カリングなし）、64×64を実際の画面サイズ相当のビューポート＋余白で
  カリングすると約3ms/frame（ズームアウト時でも約6ms/frame）——4倍の
  マップ面積でも、以前の32×32と同等以下のコストに収まることを確認。
- headless Playwright（ソフトウェアレンダリングのサンドボックス環境、
  実機のGPUとは条件が異なる点に注意）で、`requestAnimationFrame`の
  実測フレーム時間を計測しながら追加のボトルネックを特定：
  当初の余白設定（`MAX_ELEVATION+2`）が実際に必要な量の倍近く過大
  だったため縮小し、さらに`antialias: false`に変更したところ
  （フラットシェーディングのローポリ表現のため見た目への影響は
  軽微）、64×64での待機時フレーム時間が変更前の32×32での待機時
  フレーム時間（約34ms/frame、この環境自体が既にバジェット比2倍
  ほど重い）と同水準の約32ms/frameまで改善したことを確認。
- headless Playwrightで、起動直後にプレイヤーの本拠地を中心に
  原寸大でマップが表示されること、実際に大きくパンして64×64の
  マップ内を移動できること、エラーが出ないことを確認。
