# マナのペース感の見直し（奇跡の連発対策）

## 報告された問題

- 「ゲームバランスが合っているか分からない、何が面白いのか分からない」
- 「マナを使ってもすぐに上限まで貯まるので、敵の地形を壊し放題（地震の連発）」

## ジャンルの祖の設計を再調査

`docs/game-system.md`が参照する1980年代末の「神視点リアルタイム戦略
ゲーム（ゴッドゲーム）」というジャンルの祖にあたる作品について、
公開されている攻略情報・レビュー・研究記事をあらためて調査した
（商標名は本リポジトリの方針上ここには記載しない。詳細は会話内で
共有した内容を参照）。特に本タスクに関係する設計上のポイントは以下。

1. **マナは人口比例で自動蓄積するが、精神的には「じわじわ貯まる貴重な
   資源」として設計されている**。信者が増えるほど供給は増えるが、
   その蓄積は決して一瞬では終わらない。奇跡はマナゲージ上のアイコンとして
   並び、ゲージの位置が閾値を超えた時だけ使用可能になるという「解禁」の
   演出そのものが、資源の希少性を前提にしている。
2. **地形を平らにするほど、その集落からのウォーカー輩出は遅くなる**
   （収容人数が大きく育つ一方、人口増加の速さ自体は変わらないため、
   輩出までの時間が延びる）。「小さく荒れた土地は拡張が速いが脆弱、
   広い平地は拡張が遅いが強固」という明確なトレードオフが常に働いている。
   本プロジェクトの`houseGrowth.ts`はこの部分（人口増加率は家のレベルに
   関わらず一定、容量だけがレベルで増える）を既に再現できていた。
3. **奇跡の強さと「使える頻度」は反比例するよう設計され、終盤の
   最大奇跡（最終決戦に相当するもの）は人口で明確にリードしている時だけ
   現実的に使える「決着ボタン」として機能する**。中位の妨害系奇跡
   （地震に相当するもの）も、連発できるようなペースでは供給されない。

## 現状の実装との差分

`src/game/systems/mana.ts`の`manaSystem`は`deltaSeconds`（実時間の秒数）
ごとに`HOUSE_LEVELS[level].manaRate`を素直に加算する設計で、これ自体は
「人口に比例して自動蓄積する」という仕様を正しく実装している。

問題は`HOUSE_LEVELS`の`manaRate`（旧: hut=1, lodge=3, manor=6, castle=12）
と`EARTHQUAKE_MANA_COST`（20）・`MAX_MANA`（120）との**比率**だった。
このゲームは1tickが実時間1秒に相当する連続シミュレーションのため、
家がわずか2〜3軒あるだけで地震のコストを2〜4秒で再チャージでき、
`MAX_MANA`（ゲージ全体）も十数秒で埋まってしまっていた。これは
ジャンルの祖が前提としていた「マナは容易には貯まらない」という
体感と正反対で、`trySpendMana`によるコストゲートが実質機能しておらず、
「敵の地形を壊し放題」という報告の直接の原因になっていた。

## 対応

`game/constants.ts`の`HOUSE_LEVELS`の`manaRate`を全レベルで概ね1/5に
縮小した（hut: 1→0.2, lodge: 3→0.5, manor: 6→1, castle: 12→2）。
レベル間の相対比（1:2.5:5:10 相当）はほぼ維持しているため、
「大きな家ほどマナ供給が多い」という設計意図はそのまま。

この変更により、たとえば家2〜3軒程度の序盤経済では地震1発の再チャージに
数十秒単位の実時間がかかるようになり、連発ではなく「ここぞという場面で
使う」判断を要する頻度に近づく。一方、複数の城砦を抱える終盤の経済は
序盤よりずっと速くマナを貯められるという相対的な強さの差も保たれている。

地形操作（`TERRAIN_EDIT_MANA_COST=1`）は据え置き。ジャンルの祖でも
「頂点の上げ下げ」は最も基本で常用する操作として最初から使えるため、
最も安価なままにしておくのが自然と判断した。

`mana.test.ts`・`simulation.test.ts`の既存テストは`HOUSE_LEVELS`を
シンボリックに参照しているため、値変更に追従して修正不要だった
（`npm run typecheck` / `test` / `build`で確認済み）。

## 積み残し：「何が面白いのか分からない」への対応

マナのペース修正は「連発できてしまう」という具体的な不具合には
対応したが、「何が面白いのか分からない」という感想への根本対応には
まだ次のような積み残しがある（別タスクとして要検討）。

- 地形タイプ（草原/砂漠/雪原/岩）が現状`main.ts`で常に`grass`固定
  になっており、地形選択によるプレイの違いをプレイヤーが体感できない
  （征服モードの複数ワールド実装を待つ状態）。
- 「平地を広げて大きな集落を作る」vs「荒れた土地のまま素早く拡張する」
  というトレードオフはシステム上は存在するが、プレイヤーへの提示・
  フィードバック（HUDでの可視化など）が薄く、選んでいる実感が湧きにくい。
- 敵AIが単純（ウォーカー数の閾値だけでfight/settleを切り替え）なため、
  対人戦のような読み合いが生まれにくい。
