# 暫定の85軒上限を、地形由来の自然な拡張限界へ置き換える

## 目的

`TILES_PER_HOUSE_CAP` から導出していた「一陣営あたり約85軒」という上限を
撤廃し、**平地がどれだけあるか**で拡張が止まるようにする。

この上限はコメント自身が "Placeholder land-scarcity proxy ... until real
terrain-based flat-land scarcity is implemented" と認めていた暫定策であり、
原作には対応する固定上限が存在しない（`docs/original-system.md` §4）。
`plan/0117-original-gap-analysis.md` の着手順①。

## 変更

### 1. 定住に平地を要求する（`systems/settle.ts`）

`docs/game-system.md` は以前から「平地を探して**定住**し家を建てる」
「ウォーカーが**平地に**定住すると家を建てる」と書いていたが、実装は
`isBuildable`（海面より上・岩でない）しか見ておらず、**平らかどうかを
一度も確認していなかった**。新しい `isSettleable()` が
`countFlatNeighbors(..., HOUSE_UPGRADE_FLATNESS_RADIUS) >=
HOUSE_SETTLE_FLATNESS_REQUIREMENT`（25頂点中9）を要求する。

家のアップグレード要件（`HOUSE_LEVEL_FLATNESS_REQUIREMENT.hut = 0`）とは
別の定数にした。**建てるには平地が要るが、既に建っている小屋は地面が
荒れた瞬間に取り壊されはしない**——`houseUpgrade.ts` が小屋まで格下げして
そこで止まる、という現在の挙動を変えないため。

### 2. 家1軒が土地を占める（`HOUSE_SPACING` 1 → 3）

平地要求だけでは足りない。`HOUSE_SPACING = 1` では家が肩を並べて建てられ、
64×64 に数千軒入ってしまうので、結局何か恣意的な数字で止める必要が残る。
3にすると1軒が現実的な広さを占める（城の農地半径 `FARMLAND_RADIUS` が
2.5なので、隣家の農地がようやく重ならなくなる）。

### 3. 上限の撤廃と、性能ガードへの置き換え

- `settle.ts` / `populationRelease.ts` / `houseGrowth.ts` の3か所から
  `maxHousesPerFaction` を削除。`TILES_PER_HOUSE_CAP` と
  `FactionSummary.housesCap` も削除した（`housesCap` の参照はテストのみで、
  UIは使っていなかった）。
- 代わりに `MAX_WALKERS_PER_FACTION = 120` を **性能ガード**として置く。
  `createWalkerCombatSystem` と集結系が全ウォーカーに対して O(n²) なので、
  無制限にはできない。
- **土地を使い切った陣営は生産を止めない。** 定住できないウォーカーは
  "seeking" のまま残り、軍勢として積み上がる。これが「経済が完成した陣営が
  戦争を始める」圧力になる。原作でも信者は上限なく増え、増えすぎることが
  問題点として挙げられている（`docs/original-system.md` §4）。
- houseGrowth の「ウォーカー0の陣営は上限を無視して1体だけ湧かせる」
  脱出弁を削除した。ウォーカー上限に対しては、ウォーカー0の陣営は
  常に上限から最も遠いので、脱出弁そのものが不要になる。

### 4. ウォーカーが平地へ向かうようになる（`systems/wanderTarget.ts`）

平地要求を足すと、まっさらな64×64地図で定住可能なのは4096頂点中703だけに
なる。一様ランダムに歩かせると大半が「着いたが建てられない」で終わるため、
候補点のうち `isSettleable` を満たすものを優先し、無ければ従来通り
`isBuildable` な点へフォールバックする。この系のドキュメントが以前から
"stands in for real 'find the nearest flat land' pathing (which would also
consider flatness, not just dryness)" と書いていた、その平地側だけを入れた
形（本物の経路探索ではない）。

## 測定

### 地形の収容力（まっさらな64×64、grass）

| 条件 | 定住可能な頂点 | `HOUSE_SPACING` で詰めた軒数 |
|---|---|---|
| `isBuildable` のみ（変更前） | 3815 / 4096 | 3815（間隔1）|
| 平坦度 ≥ 7 | 1353 | 277（間隔3）|
| **平坦度 ≥ 9（採用）** | **703** | **167（間隔3）** |
| 平坦度 ≥ 12 | 120 | 39（間隔3）|

167は**両陣営の合計**で、旧上限が一陣営に配っていた85とほぼ同じ規模。
数値そのものより、**平坦化すれば増え、地震や火山で減り、両陣営が同じ数を
配られるわけではない**ことが目的。

### 放置テスト（AI対無操作プレイヤー、25分=15000tick）

`quiet-plain`（`allowedMiracles` は地震のみ）:

| | 変更前 | 変更後 |
|---|---|---|
| t=900s | 両陣営とも 85軒・1体、人口 2071 / 4821 | 81軒120体 / 19軒15体 |
| t=1200s | **完全に同一の値** 85軒・1体、2071 / 4821 | 81軒120体 / 19軒14体 |
| t=1500s | **完全に同一の値** 85軒・1体、2071 / 4821 | 81軒120体 / 19軒14体 |

**変更前の膠着は再現し、そして解消した。** 変更前は900秒以降、
人口が小数まで1つも動かない完全な不動点になっている。双方が上限に達し、
houseGrowth の脱出弁が配る1体ずつしか歩いておらず、その1体も互いに
遭遇しない。この世界は `allowedMiracles: ["earthquake"]` なので敵は
最終決戦を撃つことすらできず、**永久に終わらない**。
変更後は不動点が消え、家数もウォーカー数も動き続ける。

### この変更で悪化したこと（重要）

`final-frontline`（`allowedMiracles` 全開放）:

| | 変更前 | 変更後 |
|---|---|---|
| 決着 | **t=667s に決着（player勝利）** | 1500秒でも決着せず |

原因は測定して特定した。変更前の敵は85軒の家に**人口を溜め込んでいた**
（上限に達すると houseGrowth がウォーカーを出さなくなり、人口が capacity で
止まる）。その溜め込みのおかげで人口比 1460:578 ≒ 2.5 となり、
`ARMAGEDDON_POPULATION_RATIO = 1.8` を超えて敵が最終決戦を撃ち、決着していた。

変更後は人口が家に溜まらず（ウォーカーへ変換され、戦って死ぬ）、
どちらも1.8倍の人口差を作れない。**つまり現在の決着条件は、いま撤廃した
上限が生んでいた人口溜め込みに依存していた。**

これは `plan/0117` の②（マナ／人口の作り直し）と、決着条件そのものの
見直しが次に必要だということ。オーナーの当初の見立て
「ここを直すとArmageddon条件を無理にタイマー化せずに済む可能性がある」は
方向としては正しいが、**順序が逆**で、上限を外すと決着条件が先に壊れる。

もう一つ、敵AIが19-20軒で頭打ちになる。ほぼ常に "fight" モードにいるため
（`ENEMY_AI_ECONOMY_FLOOR = 16` を超えた時点で進軍し続ける）、
土地の取り合いに参加しない。土地が有限になって初めて表面化した既存の
AIの弱さで、この変更が作ったものではないが、この変更が顕在化させた。

### 性能

25分の放置テストの実時間: `quiet-plain` 36秒（1tickあたり約2.4ms）、
`final-frontline` 63秒（約4.2ms）。変更前はそれぞれ8.5秒・14.6秒なので
**3-4倍重くなっている**——ウォーカーが常時120体いるため。
1tickの予算（60fpsで16ms）には収まっているが、`MAX_WALKERS_PER_FACTION` を
これ以上上げる前に、combat/gather の空間分割が要る。

## 検証

- `npm run typecheck` / `npm run test`（707件）通過。
- 差し替えたテスト:
  - `settle.test.ts` — 荒れ地に定住しない／その場を平らにすると定住する／
    軒数の上限が無く土地だけが尽きる。
  - `houseGrowth.test.ts` — ウォーカー上限で止まる／死ぬと再開する／
    **建てる土地が無くても生産を続ける**（膠着の核心）／ウォーカー0なら必ず湧く。
  - `populationRelease.test.ts` — ウォーカー上限で何もしない／
    上限までの残り分しか出さない。
  - `simulation.test.ts` — 土地が尽きた陣営が凍らない／
    `MAX_WALKERS_PER_FACTION` を超えない。
- `simulation.test.ts` のマナのテストが1回 `update(10)` では0になるため
  10tickに分けた。これは仕様変更の直接の帰結で、テストの辻褄合わせではない:
  1tickで capacity 分を貯めた家は即座にウォーカーへ変換して人口0に戻るため
  マナを生まない。従来これが通っていたのは、10×10の世界の上限が2軒で、
  その変換が上限で止められていたからである。
