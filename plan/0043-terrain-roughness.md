# 0043 terrain-roughness

## 背景

「game2 第4回 敵対的検証」への回答の中でユーザーから：「2分程度で
決着するなら、私はかなり気になります」「ここは次の修正前に、現在
なぜ2分で決着しているのかコードから原因分析した方がいいと思います」
という指摘があり、実装前に原因分析を行った。

## 原因分析（実測）

`Simulation`を実際に動かして計測した（プレイヤー側が一切操作しない
「放置」シナリオ——敵AIだけが自律的に行動する最悪ケースに近い条件）。

1点目の発見：**生成直後の地形が、既に「城」レベルの平坦度要件を
満たす場所を大量に含んでいた。** `countFlatNeighbors`で20x20マップの
全頂点を調べたところ、何も編集していない生成直後の状態で
castle要件（半径2＝5x5=25頂点中18以上が同じ高さ）を満たす頂点が
約15%、lodge要件（5以上）を満たす頂点は実に95%以上——「地形を
平らにして家を育てる」という核となる操作ループが、地形生成の時点で
ほぼ完了してしまっていた。原因は`createHeightmap`の波形関数の周波数
が低すぎたこと：`sin(x*0.35)`のような緩やかな波は、`Math.round`後に
隣接する5頂点程度の範囲でほぼ同じ高さになりやすい。

この結果、放置シミュレーションでも試合開始40秒程度でhouse数が
双方50前後（`maxHousesPerFaction`の上限）まで到達し、マナも
MAX_MANA（120）に到達していた。

2点目の発見（今回のPRでは未対応、残作業として記載）：地形を
`sin(x*1.3)`のように高周波化して「タダで平らな地形」をほぼゼロに
しても、放置シナリオでの決着時間は**平均108.8秒→112.1秒とほぼ変化
しなかった**（8回ずつ試行、詳細は下記）。つまり2分決着の主因は
地形生成の平坦さではなく、敵AIが自前で持つ地形編集（
`enemyTerraform.ts`、5秒に1回、家1軒につき1頂点）＋人口増加の速さ
＋`enemyMiracles.ts`の人口比1.8倍でのArmageddon自動発動、という
「敵の自律経済そのものの速さ」が支配的だった。

## アプローチ（今回の対応範囲）

ユーザーの選択：「地形生成を粗くして自然の平坦を減らす」を実装した。
これは2分決着の主因ではないと判明したが、「地形を平らにして家を
育てる」という原作由来の中心ループを地形生成が肩代わりしてしまう
のは独立した設計上の問題であり、直す価値がある。

`src/world/heightmap.ts`の`createHeightmap`の波形関数を、
`HOUSE_UPGRADE_FLATNESS_RADIUS`（5x5＝25頂点の窓）に対して十分高い
周波数に変更した：

```
旧: sin(x*0.35)*1.5 + cos(y*0.3)*1.5 + sin((x+y)*0.15)*2
新: sin(x*1.3)*1.5  + cos(y*1.1)*1.5 + sin((x-y)*0.9)*2
```

候補選定は複数の周波数の組み合わせを実際に`countFlatNeighbors`で
評価して比較した（`current`＝旧: castle対応=15.2%、複数候補を試し、
最終的に選んだ組み合わせ＝castle対応0.0%、manor対応2.5%、
lodge対応43.5%、hut止まり54.0%）。標高の範囲も[0,7]→[0,8]と
ほぼ変わらず、見た目の破綻はない。

## テスト

- `src/world/heightmap.test.ts`に回帰テストを追加：20x20マップの
  生成直後、`HOUSE_LEVEL_FLATNESS_REQUIREMENT.castle`を満たす頂点数が
  0であることを検証。
- `npm run typecheck` / `npm run test -- --run`（230件）/
  `npm run build`がすべて成功。既存テストは地形の具体的な数値に
  依存していなかったため無修正で通過。
- 放置シナリオ（`Simulation`を敵AIのみで自律運転）を8回ずつ試行し、
  決着時間を比較：
  - 旧地形：平均108.8秒（範囲69.3〜169.5秒）
  - 新地形：平均112.1秒（範囲82.3〜203.8秒）
  - 「タダで平らな地形」は解消したが、決着時間そのものへの影響は
    誤差の範囲に近い。

## 残作業（重要）

今回の変更だけでは「2分決着」問題は解決しない。実測から、支配的な
要因は以下だと判断している——次の一手を検討する際の材料として記録：

1. `DEFAULT_POPULATION_GROWTH_RATE`（2/秒）とhutの`capacity`（10）の
   組み合わせが速すぎる：1軒あたり5秒でウォーカーがあふれる。
2. `enemyTerraform.ts`の`decisionInterval`（5秒）が、人間のタップ
   ペースよりずっと速く、敵は自前の家を機械的に平らにし続けられる。
3. `maxHousesPerFaction`（20x20マップで50）が緩く、家の数がすぐに
   上限まで積み上がる。
4. `enemyMiracles.ts`の`ARMAGEDDON_POPULATION_RATIO`（1.8）判定に
   使う`totalPopulation`が、家の`population`（発展途上の値、頻繁に
   ウォーカーへ変換されてリセットされる）とウォーカー数の単純合算で、
   本来の「文明の規模」より振れ幅が大きく、早期に閾値を超えやすい。
5. `triggerArmageddon`発動後の「世界中央への総力戦」自体が数十秒
   程度で決着してしまい、原作が持つ「最終決戦の圧倒的な収束感」の
   時間的な重みが出ていない。

これらは`plan/0041`（hutマナ頭打ち）とは別の、より根本的な
ペーシング調整であり、対戦時間を狙って「序盤/中盤/終盤/決着」の
時間配分をどう設計するかというゲームデザイン判断そのものを含む。
次にどれから着手するかはユーザーと相談のうえ決める。
