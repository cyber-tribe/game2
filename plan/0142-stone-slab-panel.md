# 0142 stone-slab-panel

## 背景

原作の画面構成を採用したとき、下部パネルの石板化と雷文の縁取りは
**第二段階**として合意しつつ、着手していなかった。今回入れた。

原作のスクリーンショットを拡大すると、コマンドは彫られた石の上に載って
おり、世界に面した縁に沿って**雷文（グリークキー）**の帯が走っている。
石の面は単色ではなく、擦れた肌理がある。

game2 のパネルは `--stone-mid` のべた塗りに細い段差が付いただけで、
「石板」ではなく「色の帯」だった。

## 直したもの

### 雷文の帯

`src/ui/panelFrame.ts` に8x8の1単位を**文字列のドット絵**として置いた。
理由はコマンドアイコン（`tools/sprites/icons.py`）と同じで、この大きさの
模様は**ピクセルそのものが原稿であり査読対象**だからである。

1本の連続した線として読める形にした——下辺のレールから入り、2列目を
上がり、上辺を右へ走り、内側へ巻く。**下辺が端から端まで埋まっている
ことが、繰り返したときに1本の帯になる条件**である。ここが切れていると、
継ぎ目ごとに途切れた判子の列になる。

帯はパネルの上に**重ねず、その分だけ余白を取った**。読む必要のあるもの
が模様の上に乗ることは無い。

### 石の肌理

同じくデータURLで生成し、CSS変数として流している。画像ファイルにせず
生成にしたのはアイコンと同じ理由で、色を `GAME_PALETTE` から取るため——
パレットを直せばパネルも一緒に動く。

**最初は7pxの繰り返しで作って失敗した。** 肌理ではなく織り目の格子として
読まれる。目は模様より先に周期を見つけるからで、石には周期が無い以上、
パネルの幅の中で同じ並びが二度見えない程度に繰り返しを広く取る必要が
ある（32px）。濃さも 16% → 7% に落とした。パネルはアイコンと文字の地で
あって、それ自体として目に付く肌理は読みの邪魔になる肌理である。

## 寄せなかったところ

原作のコマンドは**等角の菱形の格子**に並んでいるが、ボタンの形は長方形の
ままにした。未実装ではなく決定事項である。

理由は入力装置が違うことにある。原作はカーソルを動かして選ぶが、game2 は
指で直接触る。菱形はタップ判定の面積が同じ外接矩形に対して半分になり、
しかも隣同士が噛み合うので、押し間違いが増える。見た目の一致より、
縦持ちスマホで押せることを優先する。

`docs/game-system.md` の11節にも書いた。後の「原作に寄せる」パスで
蒸し返されないようにするためで、`palette.ts` の草の色相に同じ趣旨の
注意書きが残っているのと同じ理由である（実際、今回それに救われた）。

## 検証

- `npm run typecheck` / `npm run build` パス、テスト812件パス（+6）。
- テストは**DOMに触らない部分**に置いた。雷文は「1辺の長さの正方形で
  `.`と`#`しか無い」「レールが左右両端に達している（＝繰り返せる）」
  「上下左右だけを辿って全ての点が繋がっている（＝1本の線）」の3件。
  肌理は「大半は素の色」「窪みは輝きの約2倍」「繰り返しはボタン1つより
  広い」の3件。最後の1件は上の失敗をそのまま条件にしたものである。
- 実機（390x844）で撮影し、帯が原作と同じ向き・同じ密度で読めること、
  肌理に周期が見えないことを確認した。
