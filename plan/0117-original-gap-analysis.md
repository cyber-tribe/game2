# 原作仕様（奇跡以外）の記録と、現状との差分の洗い出し

## 目的

原作の資料をオーナーから提供してもらい、`docs/original-system.md` として
記録した。あわせて、その記述と現在の `main`（403d2a06）を突き合わせ、
残っている差分と着手順を確定させる。

`docs/original-miracles.md` が奇跡29個を扱ったのと同じ役割を、
ステージ構成・啓示・マナ・人口上限・操作について果たす文書である。
この環境からは `w.atwiki.jp` へ到達できない（プロキシが CONNECT に 403 を
返す）ため、原作側の情報はオーナー提供分がすべてであり、以降の実装PRは
この文書を参照する。

## 提供された分析に対する事実確認

提供された差分の指摘のうち、**コードを読んで裏を取った結果、修正が
必要だったもの**を先に記録する。原作側は確認手段が無いので、
確認したのは常に game2 側である。

### スプログは「未実装」ではない（指摘の修正）

`src/game/populationRelease.ts` の `releasePopulation()` が、
満員前の家から信者を外へ出す「人口放出」として既に存在する。
`Sprog` という語で検索すると出てこないだけだった。

ただし**粒度が原作と違う**。原作はカーソル下の**1軒**をBで放出するのに対し、
game2 は `POPULATION_RELEASE_MIN_FRACTION` を満たす**自陣営の全戸**を
一度に放出する。「どの家をいつ空けるか」という原作の局所的な判断が、
「今、全部出す」という一括操作になっている。残件は実装ではなく**粒度**。

さらに、`releasePopulation()` は自陣営が `maxHousesPerFaction` に
達していると**何もせず0を返す**。後述の85軒上限と直結している。

### マナは既に人口比例している（指摘の修正）

`src/game/systems/mana.ts` は `levelManaRate * (house.population / capacity)`
で計算しており、「家のレベルごとの固定レート」ではない。空の家は
1マナも生まない。`docs/game-system.md` の「信者の総人口に比例して自動蓄積」
は既に部分的に満たされている。

原作との実際の差はそこではなく、次の2点である。

- **家に入っていない信者はマナを生まない。** 原作は信者数そのものが源泉
  なので、遠征中の軍勢や放出直後のウォーカーは game2 では収入0として扱われる。
- **レベル重みと `HUT_MANA_RATE_CAP` が比例を歪めている。** 小屋の合計は
  `5 * 0.2 = 1.0/秒` で頭打ちになる（`src/game/constants.ts:152`）。
  同じ人口でも、小屋に散っているか城に集まっているかで収入が変わる。

つまり「House生産型から信者数ベースへ」ではなく、
「**家という容れ物を経由するのをやめ、人口を直接数える**」が正しい表現。

### 「合体」は独立モードが無いだけで、処理は既にある（指摘の補足）

`BehaviorMode` は `"settle" | "gather" | "goToShrine" | "fight"` の4つ
（`src/game/components.ts:146`）で、原作の4啓示と**数は同じだが割り当てが違う**。

- 合体そのもの（`GATHER_RANGE` 内のウォーカー同士が強さを合算して1体になる）は
  `src/game/systems/gather.ts` に実装済み。
- 「合体対象がいなければ定住」というフォールバックも
  `src/game/systems/gatherTargeting.ts` に実装済みで、原作の記述と一致する。
- ただし game2 の `gather` は、**目標地点への集合と合体を1つのモードで
  同時に**行う。原作はこれを「集合」と「合体」の2つの啓示に分けている。
- 空いた4枠目を game2 は `goToShrine`（集結シンボルへ）に使っている。

よって残件は「合体の実装」ではなく「**集合と合体の分離**」であり、
分離すると原作に無い `goToShrine` の去就を決める必要が出る。
原作のマグネットは奇跡（`docs/original-miracles.md` #2 マグネット移動）
なので、`goToShrine` を啓示から外して「集合」の目標指定に寄せる案が
筋は良いが、原作の「集合」が具体的に何を目標にするのかは
提供資料からは読み取れない。**着手前にオーナーへ確認する。**

### 確認して指摘通りだったもの

- **6ワールドしかない。** `src/game/worlds.ts:217-225` に6件。
  16神×3面=48面とは別構造で、各ワールドが `enemySchool` を1つ持つ
  独自設計になっている点も指摘通り。
- **85軒上限は暫定策。** `TILES_PER_HOUSE_CAP = 48`
  （`src/game/constants.ts:225`）から `maxHousesPerFaction` を導出しており
  （`src/game/simulation.ts:278`）、64×64 で約85軒。コメント自身が
  "Placeholder land-scarcity proxy ... until real terrain-based flat-land
  scarcity is implemented" と書いている。原作に相当する上限は無い。
- **自動整地が原作操作ではない。** `flatten` は長押し＋ドラッグで任意範囲を
  塗るブラシ（`src/main.ts:572-616`）。原作の「建物中心7×7を一発」ではない。
- **Guardian が余分。** `MiracleId` に `"guardian"` がある
  （`src/game/worlds.ts:13-42`）。原作の英雄は6人で守護者はいない。
- **渦巻きに `MiracleId` が無い。** 実装は `src/game/systems/whirlpool.ts` に
  分裂・土地侵食まで揃っているが、`src/game/miracleSchools.ts:69` が
  「渦巻きは竜巻が海へ入った時にのみ生まれる」と明記している。
  現在の29個は「土地上下 + `ALL_MIRACLES` 28個」で、guardian を含み
  渦巻きを含まない構成になっている。**guardian を外して渦巻きを足すと
  29個のまま原作と一致する。**
- **敵の射程無制限は解消済み。** `src/game/systems/aiViewport.ts` が入っており、
  残件ではない。

### 未確認のまま残ったもの

- **地下巨石の押し続け生成。** 原作は押し続けで一帯に複数出せる。game2 の
  `applyMegalith` にチャージ／連続入力の仕組みは見当たらないが、
  入力側（`src/main.ts`）の長押し扱いまでは追い切れていない。個別精査が要る。

## 膠着（試合が動かない）との関係

放置テストで試合が動かなくなる件は、原作差の問題であると同時に、
上の2つが噛み合った結果である可能性が高い。

- 双方が85軒で頭打ちになる。上限に達すると `houseGrowth` が
  ウォーカーの生成を止め、`releasePopulation()` も何もしなくなるため、
  **戦力の供給が両陣営同時に止まる。**
- 小屋のマナも `HUT_MANA_RATE_CAP` で頭打ちになる。家を建てて増やす
  経路が閉じているので、**収入も両陣営同時に平らになる。**

結果として、どちらも相手を崩すだけの余剰を作れない定常状態に落ちる。
原作は平地・人口・破壊で自然に勢力差が生まれる設計なので、ここを直せば
ハルマゲドンの発動条件を無理にタイマー化せずに済む見込みがある。

## 着手順

`CLAUDE.md` の方針通り、以下はすべて別PRに分ける。本PRは文書のみ。

1. **暫定85軒上限を、地形由来の自然な拡張限界へ置換する**（膠着の主因）
2. **マナを家経由から信者数直接へ寄せる**（同上。1と合わせて経済が動き出す）
3. **集合と合体を別の啓示へ分離する**（`goToShrine` の扱いは要確認）
4. **Guardian を削除し、渦巻きを直接発動できる奇跡として追加する**
   （29個の構成が原作と一致する）
5. **スプログを「カーソル下の1軒」の操作にする**
6. **自動整地を建物中心7×7の原作操作にする**
7. **地下巨石の押し続け生成を精査する**
8. **16神×3面=48ステージ構成へ広げる**（最大の構造変更。上のどれよりも
   大きいので、経済が正常化してから着手する）
9. **6系統signature型の敵AIを、16神それぞれの原作挙動へ寄せる**（8の後）

1と2を先に置くのは、原作忠実度の観点でも上位である上に、
**現に試合が成立していない原因**だからである。8は最も大きな差だが、
経済が壊れたまま48面を用意しても各面が同じ膠着を再生産するだけになる。
