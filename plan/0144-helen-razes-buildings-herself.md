# 0144 helen-razes-buildings-herself

## 背景

`plan/0133` でヘレンに建物への被害を入れたとき、カタログ記事の

> 敵信者を魅了して**建物を更地にさせ**、信者が死ぬまで外を連れ回し続ける

を「魅了された民が（自陣の）建物を壊す」と読んだ。攻略資料
（`docs/original-maps.md` の出典）はヘレン自身の動作として具体的に書いて
いる。

> 敵ウォーカーと接触したところで竪琴を一閃すると戦うことなく相手を拘束
> 出来る。また、**敵建物に接触して竪琴を一閃すると建物が消滅し、現れた
> ウォーカーを拘束する**。
> 拘束した敵ウォーカーは歩き回っているうちに**次第にパワーが減少し、
> 力尽きると死んでしまう**。

読み違いは見た目の問題ではなかった。旧実装では**家のそばに立っている民を
先に魅了しないと何も壊れない**ので、民が出払っている町はヘレンに何ひとつ
奪われなかった。

## 直したもの

### 1. 家を壊すのはヘレン自身

最寄りの**敵ウォーカーまたは敵建物**へ向かい（以前はウォーカーだけを
狙っていたので、家しか無い町の前で立ち尽くした）、届いた家を消す。
中に居た人数を持ったウォーカーが1体出てきて、その場で拘束される。

出てくる強さを家の人口にしたのは `plan/0135` の続きである。強さは人数
そのもの（`population.ts` の `walkerFollowers`）なので、城砦を潰せば
60人が捕虜になり、力尽きた時点でそのぶん人口が落ちる。「敵の人口・
建築基盤を崩す」の両方が一度に起きる。人口0の家からも1人は出る——
誰かが扉を開けたのだから。

### 2. 拘束の上限を消し、消耗に置き換えた

`HELEN_CHARM_CAPACITY = 4` は game2 が発明した制約だった。資料は
「戦闘を行わないためにパワーの減りが遅く、**かなり多くの敵ウォーカーを
拘束出来る**」と書いていて、上限には触れていない。代わりに書いてあるのは
消耗である。上限を消し、`HELEN_CAPTIVE_DRAIN_RATE`（毎秒0.03）を入れた。

効果を区切るのは資料が言うほうの仕組みになった。強さ1の民は約30秒、
城砦から出た60人はその60倍もつ。

## 踏んだ罠：エンティティIDの再利用

最初、家を壊してから中の人を作った。テストが「家はもう生きていない」で
落ちた——`world.isAlive(house)` が **true** を返す。破棄したIDが直後の
`createEntity` にそのまま再利用され、**razed した家のIDを、そこから出て
きたウォーカーが持っていた**。

`systems/effects.ts` がまさにこれを警告している（インパクト演出をECS
エンティティにしなかった理由がこれである）。生成を破棄より先に置いて
直した。同じ順序を `settle.ts` も守っている。

回帰テストを1件足した。この罠は次に誰かが順序を入れ替えたら黙って戻る。

## 検証

- `npm run typecheck` / `npm run build` パス、テスト807件パス。
- `helen.test.ts` を書き直した。上限のテストは「届く範囲の全員を取る
  （12人でも）」に反転。家の破壊は4件（壊す／中の人を人口ぶんの強さで
  拘束する／空き家からも1人／自陣の家は壊さない）、行き先1件、消耗4件、
  ID再利用の回帰1件。
