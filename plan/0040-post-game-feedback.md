# 0040 post-game-feedback

## 背景

ユーザーからの要望：「プレイ後にフィードバックを投稿できるようにしましょう！
動線はgithub issueで良いです」。

「game2 第3回 敵対的検証」以来、コードレビューよりも実際のプレイヤーの
声そのものが次に価値のある情報源だという結論に至っていた。`plan/0038`
で「もう一度遊ぶ」ボタンを置き自発的再戦率を観測する導線は用意したが、
「何が良かった／気になったか」という言語化されたフィードバックを
拾う手段はまだなかった。動線はユーザー指定の通りGitHub Issueとした。

## アプローチ

`#match-record`パネル内、「もう一度遊ぶ」ボタンの下に「📝 フィード
バックを送る（GitHub Issue）」というリンクを追加した。新しいタブで
このリポジトリ（`cyber-tribe/game2`）のIssue新規作成フォームを開く。
アンケートフォームや外部サービスを新設せず、既存のIssueトラッカーに
そのまま流し込む——開発判断が実際に行われる場所に直接届くのが利点。

- `src/feedback.ts`（新規）：`buildFeedbackIssueUrl(outcome, events)`。
  GitHubの`issues/new`は`title`/`body`/`labels`をクエリパラメータで
  受け取り事前入力できる仕様を利用し、「感想を書く欄」と「勝敗・
  試合時間・記録イベント数」という試合の客観情報を`body`に埋め込んだ
  テンプレートを組み立てる。プレイヤーが手打ちしなくても済む分、
  一言だけの感想より裏付けのある報告になりやすい。
  `labels: "feedback"`も付けているが、このラベルがリポジトリに
  存在しない場合はGitHub側で単に無視される（エラーにはならない）。
- `index.html`：`#feedback-link`を`#play-again`の下に追加。「もう一度
  遊ぶ」（主導線・塗りボタン）と競合しないよう、こちらは控えめな
  アウトライン調のリンクにした。
- `main.ts`：`showMatchRecord`（試合終了を検知した最初のフレームで
  一度だけ呼ばれる）の中で`feedbackLink.href`を`buildFeedbackIssueUrl`
  の結果に差し替える。

## テスト

- `src/feedback.test.ts`（新規）：勝者ありの場合の`body`に勝敗・最終
  イベント時刻・イベント数が含まれること、引き分けの表記、イベントが
  0件のときは試合時間の行を省くこと、URLの向き先が
  `github.com/cyber-tribe/game2/issues/new`であることを検証。
- `npm run typecheck` / `npm run test -- --run`（230件）/
  `npm run build`がすべて成功。
- ヘッドレスブラウザで`#feedback-link`が存在し、`target="_blank"`
  `rel="noopener"`が設定されていることを確認。

## 残作業

- 実際に`feedback`ラベルをリポジトリに作成するかどうかは未検討
  （なくても機能自体は問題なく動く）。
- フィードバックの投稿率自体を計測する仕組みはない
  （`plan/0038`の自発的再戦率と同様、今回はまず導線を用意するところ
  まで）。
