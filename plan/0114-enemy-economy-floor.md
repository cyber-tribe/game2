# 敵が経済を作る前に出撃するのをやめさせる

## 見つけ方

城壁の計測で「敵の家が6〜7で頭打ち」なのが引っかかっていたので、
**両陣営とも誰も操作しない**状態で家の数を追った。プレイヤー側は
放置なので、差が出ればそれは敵AIの自業自得である。

草原・64x64・7分・最も難しい敵設定（判断間隔2秒、攻撃性2）:

| | 60秒 | 240秒 | 420秒 |
|---|---|---|---|
| プレイヤー（放置） | 42.4 | 42.4 | 42.4 |
| 敵 | 0.6 | 17.8 | **17.8** |

敵は最初の1分で家が0.6軒しかない。そこで敵の設定を変えて測り直した。

| 敵の設定 | 420秒時点の敵の家 |
|---|---|
| 最も難しい（判断間隔2、攻撃性2） | 17.8 |
| 最も易しい（判断間隔6、攻撃性6） | 81.4 |
| **一度も戦わない**（攻撃性を届かない値に） | **85（プレイヤーと同数）** |

**一度も戦わなければプレイヤーと完全に並ぶ。** つまりエンジンは対称で、
差は全部「行動方針の切り替え」から出ていた。

## 原因

`behaviorMode` は**陣営全体**への指示で、"fight" の間は**誰も定住しない**。
敵AIはウォーカー数だけで "fight" を決めており、しかも難しいワールドほど
その閾値が**低い**（最初のワールドが6、最後が2）。

結果として、最難関のワールドの敵は**ウォーカー2体の時点で建設を捨て**、
以後ずっと出撃したまま経済が育たない。**「難しい」設定が敵を強くではなく
貧しくしていた。**

## 対策

`ENEMY_AI_ECONOMY_FLOOR` を足した。家がこの数に届くまでは出撃せず
定住を続ける。**攻め込まれている時は無視する**——襲撃に建設で応じる
陣営はどちらにしても負ける。

床の値は測って決めた（プレイヤーは放置、最難関設定、7分後の家）:

| 床 | 草原 敵/プレイヤー | 岩 敵/プレイヤー |
|---|---|---|
| 0（従来） | 32.4 / 85 | 24.2 / 37.8 |
| 8 | 75.2 / 69.4 | 42.4 / 85 |
| **16（採用）** | **83.8 / 63.6** | **61.0 / 82.9** |

8ではなく16にしたのは、**最後の2ワールドが使う岩地形**で崩れ方が最も
激しく、8では半分しか直らないため（85に対して42）。8〜20の差は草原では
試行ごとのばらつきに埋もれるので、岩で12試行取って決めた。

プレイヤーの家が85→63.6へ減るのは副作用ではなく**目的**である。先に
建てた敵は攻める資産を持っているし、7分間何もしないプレイヤーは家を
失っていて然るべきである。

## 検証

- 688 → 691テスト。`enemyAi`（**建てるものが無いうちは出撃しない**／
  集落が足りれば出撃する／**小さくても攻められれば守る**）。既存の10件は
  「いつ判断するか」「ウォーカー数で決まるか」のテストなので
  `economyFloor: 0` を明示して従来の規則のままにした
- `Simulation` に `enemyEconomyFloor` を通した（`enemyAggressionThreshold`
  などと同じ形。ワールドごとに「敵の辛抱強さ」を変える余地でもある）
- typecheck / build / `sprites:check` / `palette:check` 通過
- 本番ビルドで実機確認（下記）
