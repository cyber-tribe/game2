# 0069: 集結モードも「対象がいなければ定住」にフォールバックする

## 背景

ユーザーのWiki再照合レポートの優先度②「啓示は排他的モードではなく、
定住を基本とした優先行動」への対応の一部。ユーザーの言葉を借りると:

> 合体 → 合体対象がいない → 定住
> 戦闘 → 敵がいない → 定住
>
> これは単なる細部ではありません。POPULOUS 2では命令が、「それだけを
> しろ」ではなく、「基本的には文明を広げながら、優先順位だけ変更する」
> という設計なんです。

前回（`plan/0067-gather-based-leader.md`）の調査で、`fightTargetingSystem`
（戦闘）は既にこの通りに動いていることが判明していた: 敵がどこにも
いなければそのWalkerには目標を割り当てず、`createWanderTargetSystem`／
`createSettleSystem`がモード非依存で拾って通常通り徘徊・定住させる。

一方`plan/0067`で新設した`gatherTargetingSystem`（集結）は、リーダーを
含む全Walkerに毎tick目標を割り当て続ける実装だった。リーダー自身への
自己ターゲット（現在地＝目標、放浪防止のノーオペレーション）は、
`createSettleSystem`側で無条件に除外されるようになっていたため、
「集結する相手が誰もいない」状態でもリーダーが永久にその場に留まり続け、
定住して文明を広げる側に一切回らない、という「戦闘」とは非対称な挙動に
なっていた。これは今回のユーザーの指摘に照らすと、まさに「合体対象が
いない→定住」が欠けているケースだった。

## 設計

- `gatherTargeting.ts`に`hasOtherSeekingWalkers(world, factionId, excluding)`
  を追加（エクスポート）。指定エンティティ（通常はリーダー）以外に、
  同じ陣営で"seeking"状態のWalkerが1体でも存在するかを返す。
- `gatherTargetingSystem`: リーダーの自己ターゲット割り当てを、
  `hasOtherSeekingWalkers`が真の間だけに限定。誰も集まってくる見込みが
  なくなったら（他の"seeking"Walkerが1体もいなくなったら）リーダーには
  何も割り当てず、目標なしの状態のまま次のシステムに渡す。
- `settle.ts`の`currentGatheringLeaders`も同じ条件を共有するように変更
  （`gatherTargeting.ts`からインポート）。「集結モードのリーダーは定住
  対象から除外する」という既存ルールを、「ただし集結相手がまだ残って
  いる間に限る」という条件付きに変更した。2箇所が同じ判定基準を共有する
  ことで、「リーダーを目標なしのままにする」タイミングと「そのリーダーを
  定住対象から除外する」タイミングが常に一致する。
- これにより、集結する相手がいなくなったリーダーは`createWanderTarget
  System`（モード非依存、目標なしの"seeking"Walkerに徘徊目標を与える）→
  `createSettleSystem`（モード非依存、目標なしの"seeking"Walkerを定住
  させる）という既存の汎用フォールバック経路にそのまま乗る。「戦闘」で
  既に機能していたのと同じ仕組みを「集結」にも適用した形。

`goToShrine`モードは意図的に対象外とした。既存テスト（"walks a lone
leader to a relocated shrine and settles it there"）が示す通り、
`goToShrine`モードでの「到着したら定住する」という挙動は既にドキュメント
通りの意図的な仕様（新拠点の建設）であり、「対象がいないから仕方なく
定住」ではない。

## 検証

- `npm run typecheck` / `npm run test -- --run`（374件、複数回連続実行で
  再現確認）/ `npm run build` すべて通過。
- `gatherTargeting.test.ts`: 集結相手がまだいる間はリーダーへの自己
  ターゲット割り当てが続くこと、集結相手（"seeking"状態の他のWalker）が
  1体もいなくなったらリーダーが目標なしになること、残っているのが
  "seeking"以外の状態（騎士など）だけの場合も同様に目標なしになることを
  追加。新規エクスポートした`hasOtherSeekingWalkers`自体のユニットテストも
  追加。
- `settle.test.ts`: 集結相手がまだいる間はリーダーが定住しないこと、
  誰もいなくなったら定住することを追加（この除外ルール自体、
  `plan/0067`で追加されたにもかかわらずこれまで直接のテストがなかった
  ギャップも同時に埋めた）。
- `simulation.test.ts`の既存の結合テスト2件が、「集結モードを一瞬だけ
  経由してリーダーを作ってから即goToShrineへ切り替える」という単独
  Walkerのテスト構築パターンに依存していたため、新しいフォールバックの
  影響で意図せず崩れた（集結の1tickの間に「誰も集まる見込みがない」と
  判定されて即座に徘徊→定住してしまい、目的の場所への行進が始まる前に
  別の場所へ定住してしまっていた）。これはテストのセットアップ方法の
  問題であり、`FactionState.leaderId`を直接設定してリーダー形成の過程を
  バイパスする既存パターン（他のgoToShrine系テストが既に使っている
  やり方）に書き直して解消した。実際のデバッグトレースで、単独リーダーが
  正しく徘徊→定住のフォールバック経路をたどることも直接確認できた。
