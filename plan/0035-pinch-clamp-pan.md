# 0035 pinch-clamp-pan

## 背景

`plan/0033-pinch-zoom-rotate.md`が残作業として明示していた項目。
ピンチ操作（拡大縮小＋回転）の直後に呼ばれる`applyPinchTransform`は、
一本指パンが常に通す`clampPan`（画面外へ大きくはみ出さないようにする
既存の制限）を一切適用していなかった。地図の端付近を軸にズームイン
を繰り返すと、視点が画面外へどんどんずれていき、操作不能な位置まで
地図が流れてしまう可能性があった。

## アプローチ

`applyPinchTransform`が最終的な`renderer.view.position`を計算する
箇所で、一本指パンと同じ`clampPan(x, y)`を通すようにしただけ。
`clampPan`自体は変更していない。

`clampPan`は地図の回転を考慮しない近似（`mapPixelWidth`/
`mapPixelHeight`を軸に沿った矩形として扱う）だが、これは一本指パンが
回転後も既に抱えている制約と同じなので、新たな不整合を持ち込むもの
ではない。

## テスト

- ロジック変更はクランプの適用箇所のみで、`main.ts`の対話ロジックは
  このプロジェクトの既存方針通り自動テスト対象外。
- ヘッドレスブラウザで、画面左上寄りの点を軸に二本指ピンチイン
  （ズームイン）を5回連続で行い、地図が視界から完全に外れず、
  画面内に留まり続けることをスクリーンショットで確認。
- `npm run typecheck` / `npm run test -- --run`（218件、ロジック変更
  なし）/ `npm run build`がすべて成功。

## 残作業

- `clampPan`自体の回転非対応は今回も未解消（回転中はマージンが実際の
  見た目の余白と厳密には一致しない）。実害が出るほど頻繁に問題になる
  ケースは未確認のため、優先度は低いとみている。
