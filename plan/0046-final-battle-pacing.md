# 0046 final-battle-pacing

## 背景

`plan/0043`〜`0045`で「2分決着」問題に取り組み、放置シナリオでの
決着時間は平均108.8秒→230.6秒まで伸びた。ただしその内訳を計測
したところ、Armageddon発動から決着までの「最終決戦」フェーズ
自体は平均22秒（範囲8.4〜32.9秒）しかなく、そのほとんどが世界
中央への移動時間で、戦闘自体は数ティックで決着していた。原作の
Armageddonが持つ「世界そのものが最終決戦へ収束していく圧倒的な
終末感」（第4回敵対的検証で挙げられた4つの重要要素の一つ）が、
この短さでは体感しづらい。

## アプローチ

`armageddon.ts`の`triggerArmageddon`で、最終決戦に参加する全
ウォーカーの移動速度を新設の`FINAL_BATTLE_WALKER_SPEED`（0.5、
通常の`DEFAULT_WALKER_SPEED`＝1.5の3分の1）に落とすようにした。

- 家から変換された新規ウォーカーだけでなく、**すでに存在していた
  ウォーカー**（発動前から徘徊中だった民、騎士など）も同じ速度に
  揃える。片方だけ速いと最終決戦の一体感が損なわれるため。
- 戦闘解決ロジック（`walkerCombatSystem`の強さ比較）自体には
  手を付けていない——それは通常戦闘全体に影響する、より大きな
  変更になるため今回はスコープ外。あくまで「中央への行軍」を
  長く見せることで最終決戦全体の体感時間を伸ばす、という狙い。

## テスト

- `src/game/armageddon.test.ts`：発動前から存在していたウォーカー
  の`strength`/`state`は変わらないが、`speed`が
  `FINAL_BATTLE_WALKER_SPEED`に変わることを検証するようテストを
  更新（従来は「一切変更されない」ことを検証していたテストを、
  新しい意図的な仕様に合わせて更新）。
- `npm run typecheck` / `npm run test -- --run`（235件）/
  `npm run build`がすべて成功。
- 放置シナリオ（敵AIのみで自律運転）を20回試行し比較：
  - 最終決戦フェーズ（Armageddon発動〜決着）：平均22.0秒→
    **平均63.7秒**（範囲27.3〜118.1秒）
  - 試合全体の決着時間：平均230.6秒→**平均302.7秒（約5分3秒）**
    （範囲236.1〜634.9秒）。ユーザーが示した目標
    （早期決着5〜8分、通常戦10〜15分）の範囲に入り始めている。

## 残作業

- 戦闘解決そのもの（1体ずつの強さ比較で一撃決着）は今回変更して
  いない。最終決戦の「戦闘」自体の見応えをさらに高めるなら、
  この解決ロジックへの着手が次の候補になるが、通常戦闘全体に
  影響する大きな変更になるため、プレイテストの結果を見てから
  判断する。
- `FINAL_BATTLE_WALKER_SPEED`＝0.5は初回の仮値。実測は目標範囲に
  入ってきているが、まだ「早期決着」寄りの分布であり、通常戦
  10〜15分をより安定して狙うならさらに調整の余地がある。
