# 0066: 芝生タイルをディザ柄のテクスチャで表現する

## 背景

`plan/0064`で地形を断層（テラス状のブロック）表現に変更した直後、ユーザー
から視覚表現そのものへの追加フィードバックがあった。

> 表現が酷いですね
> 原作の芝生を見習ってください

添付済みの参考画像（`plan/0064`で使ったものと同じ）を見返すと、原作の芝生は
単色の塗りつぶしではなく、明るい緑と暗い緑の2色を細かくディザ（網目状の
斑点）で混ぜた質感になっている。これまでの`IsoRenderer`は`TERRAIN_COLOR`
の単色フラット塗りだったため、「のっぺりして安っぽい」という指摘に繋がった。

## 設計

- 地形データやゲームロジックには一切手を加えず、`redraw()`の芝生タイルの
  塗り方だけを変更する。
- `createDitherTexture(size, baseColor, speckleColor, density)`: 小さな
  正方形のRGBAピクセルバッファを`tileHash`（既存の溶岩ひび割れ表現などで
  使っている決定論的疑似乱数）で1ピクセルずつ`baseColor`/`speckleColor`の
  どちらかに決めて埋め、`PIXI.BufferImageSource`→`PIXI.Texture`化する。
  - `BufferImageSource`は生のピクセル配列を直接受け取れるため、DOMの
    `<canvas>`やWebGLコンテキストなしでも動作する。これは既存のテスト環境
    （vitestのデフォルト"node"環境、実キャンバスなし）と相性がよい。
  - `addressMode: "repeat"`でタイル1枚の中に複数回繰り返させ、
    `scaleMode: "nearest"`でドットをぼかさずクッキリさせる（原作のドット
    絵らしいディザの質感に寄せるため）。
- `GRASS_FILL = { texture: ..., textureSpace: "global" }`: `textureSpace:
  "global"`は「テクスチャをスクリーンの上ではなく地面そのものに敷いた
  かのように」扱うPixiのモードで、`redraw()`が描く座標（`toScreen()`の
  結果、カメラのパン/ズーム/回転を含まない地面固有の座標）をそのまま
  UVとして使う。これによりカメラをパンしても斑点模様が地面と一緒に動き、
  画面に張り付いたように滑らない。
- `redraw()`のタイル塗りつぶし色決定ロジックはそのまま（水面/溶岩岩盤/
  地形色の判定）だが、水でも溶岩岩盤でもない芝生地形の場合だけ、天面の
  fillを`TERRAIN_COLOR.grass`の代わりに`GRASS_FILL`に差し替える。崖の
  壁面（`drawCliffWalls`）は従来通りフラット単色の陰影付けのままとした
  （テクスチャ付き壁面まではスコープ外）。
- 砂漠・雪原・岩など他の地形タイプは今回は変更していない（指摘が具体的に
  「芝生」だったため）。

## 検証

- `npm run typecheck` / `npm run test -- --run`（342件）/ `npm run build`
  すべて通過。
- `IsoRenderer.test.ts`のテストを更新・追加:
  - 崖の陰影テスト（`shades a cliff wall darker...`）は芝生ではなく
    砂漠地形に変更（このテストの主旨は壁面の陰影計算そのものであり、
    芝生のテクスチャ化とは無関係なため）。
  - 芝生タイルの天面がPixiのデフォルト白テクスチャ（単色塗りの目印）では
    なく、専用のディザテクスチャを使っていることを確認するテストを追加。
- headless Playwrightでワールドを選択し、通常表示とズームインした状態の
  両方をスクリーンショットで目視確認。単色の塗りつぶしから、明暗2色の
  細かい斑点模様に変わったことを確認した。
