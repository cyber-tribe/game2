# 自陣視認制約の骨抜き修正 + ツールバーのスクロール化

ユーザーからの実機フィードバックのうち、独立した小さめの2つの修正:
自陣視認制約のバグ修正と、ツールバーが画面を占有しすぎる問題への対応。

## 1. 自陣視認制約がTILE_BOUNDS_MARGINで骨抜きになっていた問題を修正

### 背景

ユーザーから「自勢力が映っていないと奇跡を発動できない制約が崩れて
います」との指摘。

### 診断

`main.ts`の`isOwnFactionVisible`は`trySpendPlayerMana`の入口で
「自分の勢力（拠点・民）が現在のカメラの画面内に映っているか」を
チェックする、`plan/0063-visibility-gated-casting.md`由来の制約。

このチェックに渡していた`visibleBounds()`は、`IsoRenderer.redraw()`用に
`TILE_BOUNDS_MARGIN`（`Math.ceil(MAX_ELEVATION/2)+2` = 12タイル）ぶん
画面の実際の四隅より広く水増しされた範囲だった。これは「高く隆起した
頂点が画面端でポップインしないように」というレンダリング都合の
マージンであり、`isOwnFactionVisible`のようなゲームルール判定に
そのまま流用すべきものではなかった。結果として、自陣が画面の実際の
四隅から最大12タイルも外側にあっても「見えている」と判定されてしまい、
本来の「自陣が画面に映っていないと奇跡を発動できない」という制約が
ほぼ機能しなくなっていた。

### 対応

`main.ts`に、同じ4隅の座標から`margin: 0`で計算する
`strictVisibleBounds()`を新設し、`isOwnFactionVisible`はこちらを使う
ようにした。`visibleBounds()`（マージンつき、redraw()用）と
`strictVisibleBounds()`（マージンなし、ゲームルール用）の重複を避ける
ため、画面四隅のワールド座標計算を`screenCornersInWorldSpace()`として
共通化した。

## 2. ツールバーが画面を占有しすぎる問題への対応

### 背景

ユーザーから「メニューボタンが増えすぎて操作するマップ画面が小さい
です。メニューをスクロール可能にしてバランスを整えてください」との
指摘。`#toolbar`は高さ無制限のflexカラムで、行動方針・人口・情報・
奇跡（今回の一連の対応で「平坦化」ボタンも追加済み）の全セクションを
常に画面下に固定表示していたため、ボタンが増えるたびにマップの
表示領域が圧迫されていた。

### 対応

`index.html`の`#toolbar`に`max-height: 46vh`と`overflow-y: auto`を
追加し、画面の半分弱を超えて伸びないようにした。ページ全体は
`touch-action: none`（ページ自体のスクロール/ズームを禁止）のため、
`#toolbar`にだけ`touch-action: pan-y`を指定し、ツールバー内での縦方向の
指のドラッグがマップ操作ではなくツールバー自体のスクロールとして
機能するようにした。

### 検証

- `npm run typecheck` / `npm run test -- --run`（432件）/
  `npm run build`: すべて成功。
- Playwright（chromium、iPhone 13）で確認: ツールバーの高さが
  viewport高さの46%（実測305px/664px）に収まり、地図の表示領域が
  大幅に広がったことを確認。`scrollTop`を操作するとツールバー内の
  スクロールが機能し、後続の行（沼・騎士化・守護者化・火山・洪水・
  最終決戦）が表示されることを確認。コンソールエラーも無かった。
