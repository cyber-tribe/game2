# 0169 readable-elevation

## 平らな土地は高さを一切名乗っていなかった

プレイして貰った報告：

> 高度が読み取りにくいです
> 上なのか下なのか分かりにくいので、平坦にするためには上げたら良いのか
> 下げたら良いのかがわからないです

原因は1行である。`IsoRenderer.fillTerrainQuad` が

```ts
const brightness = isFlat ? 1 : faceBrightnessOf(corners);
```

としていた。`faceBrightnessOf` はランバート——面の**傾き**を読む式であり、
平らな面には言うことが何も無い。だから高さ2の台地と高さ7の台地は
**1ピクセルも違わずに**描かれていた。

残る手掛かりは画面上の縦位置だけだが、アイソメトリックではそれは
**奥行きと区別が付かない**。手前の低い土地と奥の高い土地が同じ高さに
乗る。つまりプレイヤーが持っていた情報は、実質ゼロだった。

明暗が見えている場所は全部**斜面**であって、平地ではない。報告が
「読み取りにくい」ではなく「上か下か分からない」と書いているのは
そのためで、正確な指摘だった。

## 明るいほど高い

同じ世界の別の表示が既にそう言っている。`Minimap.terrainColorAt` は
高さを4段階の明暗に量子化しており（`plan/archived/0087`）、**明るい方が
高い**。2つの表示が上下について逆のことを言ってはいけないので、向きは
これに揃えた。

原作側も、高さは**数えられる段**として読ませている——攻略の
「1段まで下げたほうが」「3段以上の土地になるとほとんど浸食を受けない」は、
盤面を見て段が数えられることを前提にした書き方である。

- `HEIGHT_TINT_PER_STEP = 0.08` … 1段ぶんの明度差。
- `HEIGHT_TINT_MIDPOINT = 3` … 地形そのものの色で出る高さ。`createHeightmap`
  が生成する 0〜7 の中央。**`waterLevel` には追従させない。**「明るいほど
  高い」は試合中ずっと同じ意味である方が覚える価値があり、追従させると
  洪水のたびに、読み終えた丘が黙って塗り替わる。
- `MAX_HEIGHT_TINT = 0.32` … 上限。生成される 0〜7 の帯が**丸ごと単調**に
  なる位置に置いてある（どの1段も見える1段である）。それより上へ持ち上げた
  山や火山の20は飽和するが、そこは急斜面でランバート側が既に働いている。
  下端の上限には届かない——`MIN_ELEVATION` が0で、内側にある。

斜面側の幅（`MAX_SLOPE_DARKEN` 0.55 / `MAX_SLOPE_LIGHTEN` 0.25）より
意図的に小さい。斜面では形が既に見えているのだからランバートが主でよく、
これは**信号が皆無だった平地のため**の量である。

`fillTerrainQuad` は2つを掛ける。傾きと高さは別々のことを言っているので、
どちらかで代用はできない。

## 覚え方を1行で渡す

チュートリアルの一文に「明るい地面ほど高い——上げるか下げるか迷ったら
「平坦化」でならせる」を入れた。報告の後半（どちらへ動かせばいいか）は
配色だけでは片付かず、**迷ったときに押せるボタンがある**ことを知って
いれば済む話だからである。

この文はプレーンテキストのままにしてある。`src/main.ts` が PC 向けの
一文を `textContent +=` で足すので、タグを入れると PC でだけ剥がれる。

## 検証

- `npm run typecheck` / `npm run build` パス、テスト1018件パス（+5）。
- `IsoRenderer.test.ts` ——傾きと高さを掛け合わせて塗ること、**高さの違う
  2つの平らな台地が別の陰になること**（報告そのもの）、中点が地形色ちょうど
  であること、単調に明るくなること、隣り合う高さが `turfFillFor` の量子化
  （`TURF_SHADE_STEPS`）を跨ぐこと——これを跨がないと、まさに見せたかった
  小さな差だけが同じテクスチャに潰れる——、上で飽和して白飛びしないこと。
- 実機（ヘッドレス Chromium、実ビルドを `/game2/` で配信、seed 固定）で
  同じ視点を撮り直し、平らな段が段として読めること・高い所が白飛びして
  いないことを目視で確認。
