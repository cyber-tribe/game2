# 0165 wide-terrain-edit

## スマホで1頂点を狙うのは無理がある

「スマホで1マス選んで土地の上下を行うのが難しい」という指摘。測ると、
標準のズームで隣り合う頂点は**横32px・縦16px**しか離れておらず、指の接触面
は40〜50pxある。**指1本が横2つ・縦3つの頂点を覆う。** しかも押した瞬間に
確定するので、どれが動くのか見えないままマナが減る。

`plan/archived/0009` が既にこの問題に当たっており、ズームとパンとヒット
半径のスケール対応で「頂点が数px間隔になる」ところまでは直してある。残って
いるのは**その先**——40px の許容誤差を持たせても、隣の頂点までの距離が32px
なら曖昧さは消えない。

## 原作が同じ問題を持っていて、答えも持っていた

神技解説の土地上下の項に、そのまま書いてあった。

> 便利な操作としては **Ｌ＋Ａで3×3マスを1段上げ**(ＡＡＢと同じ効果)、
> **Ｌ＋Ｂで3×3マスを1段下げる**。

原作はカーソルとＤパッドを持っていて、それでも3×3をまとめて動かす修飾キーを
用意している。game2 には7×7の自動整地（Ｘ相当）はあったが、これが無かった。
差分表にも載っていない見落としである。

**狙いの精度を上げるのではなく、精度が要らないようにする。** 3×3 は指が覆う
範囲とほぼ一致するので、多少外しても意図どおりになる。

## 修飾であって道具ではない

原作のＬはＡ／Ｂを**修飾**する。だから3×3もツールを置き換えない——隆起／沈降
を選んだまま、その効き幅だけを変える。ボタンは隆起と**同時に点灯**する。

タッチスクリーンには押しっぱなしにする2つ目のボタンが無いので、押している間
ではなく**押すたびに切り替わる**（sticky）。1マスも残る（原作もＡ単体は1マス）。

平坦化には効かない。原作でもＬが修飾するのは上げ下げだけで、平坦化に相当する
のはＸの自動整地の側である。

## 値段は手でやるのと同じ

**動いた頂点の数だけ**マナを取る。9頂点動けば9倍。自動整地が既にこの規則で
（「Priced at exactly what the same work costs by hand」）、同じ考え方に揃えた。
手数の節約であって、地形操作の割引ではない。

## ついでに直したこと

`raiseVertex` は城壁のかかった頂点を動かさない（`plan/0149`）が、呼び出し側は
それを知らずにマナを取っていた。1頂点なら「1マナ取られて何も起きない」で
済んでいたが、3×3では黙って何倍にもなる。判定を `terrainEditRefusal` に
切り出したついでに、**城壁の頂点は課金対象から外した**（理由も表示する）。

## 検証

- `npm run typecheck` / `npm run build` / `sprites:check` パス、
  テスト1020件パス（+7）。
- `spadeBlock` 7件——1で1頂点、3で9頂点かつタップ点が中心、地図の端で
  切り詰めること、重複しないこと、偶数は下の奇数として扱うこと、
  小数のタップを最寄り頂点に丸めること、0や負でも空を返さないこと。
- **実機確認済み**（製品ビルドをヘッドレスで操作）。3×3ボタンが隆起と同時に
  点灯し、1タップの消費マナが1→9に変わり、もう一度押すと1に戻ることを確認。
