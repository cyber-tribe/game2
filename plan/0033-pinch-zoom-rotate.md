# 0033 pinch-zoom-rotate

## 背景

ユーザーからのフィードバック：「ピンチ操作による拡大縮小と、複数指
操作による回転に対応させてください」。二本指での回転自体は
`two-finger-rotate`（#27）で既に実装済みだったが、拡大縮小は
`layout()`が画面サイズから自動計算する`currentScale`（自動フィット
スケール）のみで、プレイヤーが自分でズームする手段が一切なかった。

地図アプリでの「ピンチ＆回転」は通常同時に行われる（二本指の距離と
角度は同じジェスチャーから両方取れる）ため、既存の回転処理に拡大縮小
を後付けするのではなく、1つの変換関数にまとめた。

## アプローチ

`currentScale`を`baseScale`（`layout()`が計算する自動フィット値）と
`zoomFactor`（プレイヤーのピンチによる倍率、既定1）の積に分離。
`layout()`は`baseScale`だけを再計算し`zoomFactor`はそのまま残すため、
（本アプリにはテキスト入力がなく起きないが）画面リサイズが起きても
ピンチでのズームが失われない。

`rotateAroundPivot`を`applyPinchTransform(pivot, deltaAngle,
scaleRatio)`に拡張。既存の「ピボット保存変換」パターン
（`renderer.view.toLocal(pivot)`で変換前のローカル座標を取り、
回転・スケールを更新した後、同じピボットが画面上の同じ位置に留まる
よう位置を再計算する）に、スケール変更のステップを追加しただけ。
`zoomFactor`は`MIN_ZOOM_FACTOR`（0.5）〜`MAX_ZOOM_FACTOR`（2.5）に
クランプする。

`pointerdown`で2本目の指が触れた瞬間に、既存の`lastTwoFingerAngle`と
並べて`lastTwoFingerDistance`も記録。`pointermove`では角度の差分と
距離の比（今回の距離 ÷ 前回の距離）を両方計算し、1回の
`applyPinchTransform`呼び出しにまとめて渡す。

## テスト

- ジオメトリのみの変更で、`main.ts`の対話ロジックはこのプロジェクトの
  既存方針通り自動テスト対象外（ヘッドレスブラウザでの目視確認のみ）。
- ヘッドレスブラウザで合成PointerEventを使い、以下を確認：
  - 二本指を広げながら回転させるジェスチャーで、地形が目に見えて
    拡大し、グリッド線が回転していること（スクリーンショット比較）
  - 二本指を大きく縮める操作を3回連続で行っても、`MIN_ZOOM_FACTOR`
    でクランプされ地図が消えたり壊れたりしないこと
  - ピンチ操作の直後に一本指でパンした際、正しく視点が移動すること
    （ジェスチャー状態が壊れて操作不能にならないこと）
  - `npm run typecheck` / `npm run test -- --run`（206件、ロジック
    変更なし）/ `npm run build`がすべて成功

## 残作業

- ピンチ操作中は`clampPan`（画面外への行き過ぎを防ぐ既存の一本指パン用
  ロジック）を適用していない。既存の回転ジェスチャーも同様に未適用
  だったため一貫性は保っているが、大きくズームインした状態で地図の端
  まで回転・パンすると画面外に大きくはみ出す可能性がある。
