# 0154 settle-drifts-outward

## 原作の定住は「端に向かいやすい」

攻略記事は定住をこう書く——「ウォーカーは適当に歩き回り、平地に建物を
建てます。**マップ中央よりは端に向かいやすい傾向があります**」。

game2 の `wanderTarget.ts` は角度を `rng() * 2π` で一様に引いていた。
一様な乱歩は原点からほとんど離れない（期待変位がゼロで、距離は
√歩数 でしか伸びない）ので、集落は最初に降りた場所の周りに団子状に
溜まり、島の残り半分は空いたままになる。原作の集落が海岸線に沿って
広がっていくのはこの偏りのためである。

## 傾き方

外向きの単位ベクトル（マップ中心 → ウォーカー）を、一様に引いた向きへ
`WANDER_OUTWARD_BIAS = 0.35` で混ぜ、長さを1に戻す。

- **向きだけを変える。** 混ぜたあと正規化するので歩幅は `rng() * radius`
  のまま。偏りが歩数や到達距離を変えない。
- **どの向きも塞がない。** 係数が 0.35 なら、真後ろ（中央向き）を引いた
  ときの合成は依然として中央を向く。原作が言うのは「傾向」であって
  規則ではないので、内側へ歩く民が居なくなってはいけない。
- **中心に立つ民には偏りが無い。** 外向きベクトルが定義できないので
  一様な引き方に戻す（ゼロ除算の回避でもある）。
- **heightmap を渡された時だけ効く。** 中心がどこかは heightmap しか
  知らない。地形を気にしないテストの呼び出しは今までどおり一様。

`0.5` を超えると真後ろの引きが外向きに反転して「規則」になってしまう。
0.35 は外半分を目に見えて厚くしつつ、その手前で止まる値である。

## 検証

- `npm run typecheck` / `npm run build` パス、テスト865件パス（+6）。
- 400回引いて外向きが内向きを上回ること、真後ろを引けば内側へ歩くこと、
  歩幅が `rng() * radius` のままであること、中心の民が一様であること、
  `outwardBias: 0` で以前の挙動に戻ることを各1件。
- 既存6件はそのまま通る（うち3件はウォーカーが中心に立っており、
  偏りが定義上かからない）。
