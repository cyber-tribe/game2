# 0047 miracle-visuals

## 背景

ユーザーからの2件のフィードバック：

- 「沼ですが円だと範囲がよくわからないので、マス目を紫にするのは
  どうでしょうか？」——`EntityLayer.ts`の沼描画は、スクリーン座標に
  そのまま円を描いていた。等角投影のマス目は画面上では菱形に
  見えるため、円の縁がどのマスと重なっているのか判断しづらい。
- 「火山ですが、今は山の稜線にしか見えませんから、火山らしく
  マグマの表現が欲しいです。また頑張れば平地に戻せますよね?」——
  `IsoRenderer.ts`の火山岩は、地形タイプ「rock」と同じ茶色一色で
  塗られており、火山らしさ（マグマ）が見た目に表れていなかった。
  なお「頑張れば平地に戻せる」は既存仕様の通り——`raiseVertex`が
  呼ばれるたびに`rockHardness`が1減り、0になれば通常の地形へ戻る
  （`docs/game-system.md`の「復旧には大量の地形操作が必要」）。
  今回はこの既存挙動に、冷えていく見た目のフィードバックを
  追加した。

## アプローチ

### 沼：円からマス目の紫塗りへ

`EntityLayer.ts`に`swampAffectedTiles(pos, radius, mapWidth, mapHeight)`
を新設（純粋関数、Graphics不要でユニットテスト可能）。沼の中心から
`radius`以内に中心を持つマス目だけを選び、そのマス目1つ1つを
`IsoRenderer.redraw()`と同じ菱形ポリゴンとして紫で塗る。
`swampSystem`自体の判定（ウォーカーの実座標と沼の中心の直線距離）
は変更していない——あくまで見た目をその判定に近い形で近似する。

### 火山：暗い岩＋発光するマグマの亀裂（改訂版）

最初の実装は、rockHardnessに応じてタイル全体を暗い岩色〜明るい
マグマ色へ単純に線形補間するグラデーション塗りだった。ユーザーから
「全然火の表現になっていない」との指摘を受け、実在のゲームでの
火山・溶岩表現を調べ直した：Terrariaの地獄（Underworld）、
Stardew Valleyの火山ダンジョン、Minecraftの溶岩、SimCity/
RollerCoaster Tycoonの災害イベントの火山——いずれも共通する
パターンとして、**岩そのものは常に暗いまま（黒曜石・灰・炭のような
色）で、「火」は岩の中の亀裂や溜まりとして明るい別の色で描かれる**。
タイル全体を暗色→明色へ均一に補間する最初のアプローチは、
コントラストを生む「暗い部分」が残らないため、単に茶色い/
オレンジ色い山にしか見えなかった。

これを踏まえて全面的に描き方を変えた：

- タイルの塗りは常に暗い岩色（`VOLCANO_ROCK_COLOR`）で固定——
  `rockHardness`によって変化しない。
- 岩とは別に、タイル中心から放射状に伸びる発光する「亀裂」を
  `drawLavaCracks`で描画する。本数・長さ・明るさは`rockHardness`
  に応じて変化し（新鮮なほど多く・長く・明るい）、時間経過で
  ゆるやかに明滅する（`volcanoGlowIntensity`——純粋関数、
  `elapsedTime`と`tileHash`によるタイルごとの位相のずれで、
  全タイルが同期して点滅しないようにしている）。
- 各亀裂の中心には、周囲ににじむような柔らかい光暈（半透明の
  大きな円を先に描いてから、小さく明るい核を重ねる）を追加し、
  「岩の中に熱源がある」印象を強めた。
- 最低限の不透明度（`LAVA_MIN_ALPHA`）を設け、冷えかけていても
  完全に見えなくなる直前まで「まだ光っている」と分かるようにした
  （「頑張れば平地に戻せる」の進捗は、亀裂の本数・長さの減少で
  伝わる）。

### 沼：円からマス目の紫塗りへ

`EntityLayer.ts`に`swampAffectedTiles(pos, radius, mapWidth, mapHeight)`
を新設（純粋関数、Graphics不要でユニットテスト可能）。沼の中心から
`radius`以内に中心を持つマス目だけを選び、そのマス目1つ1つを
`IsoRenderer.redraw()`と同じ菱形ポリゴンとして紫で塗る。
`swampSystem`自体の判定（ウォーカーの実座標と沼の中心の直線距離）
は変更していない——あくまで見た目をその判定に近い形で近似する。

## テスト

- `src/render/EntityLayer.test.ts`：`swampAffectedTiles`が中心を
  囲む4マスだけを返すこと（半径1.2）、マップ端でのクランプ、
  半径が大きいほど対象マスが増えることを検証。
- `src/render/IsoRenderer.test.ts`：`volcanoGlowIntensity`が
  rockHardness＝0で常にゼロになること、rockHardnessが多いほど
  （パルス1周期分の平均で比較して）明るいこと、時間経過で明滅する
  こと（同じ入力でも時刻が変われば値が変わる）、タイルごとに位相が
  ずれること、同じ入力には同じ結果を返す（純粋関数）ことを検証。
- `npm run typecheck` / `npm run test -- --run`（245件）/
  `npm run build`がすべて成功。
- ヘッドレスブラウザで実際に沼・火山（満タン/半分/ほぼ冷却済みの
  3段階）を配置してスクリーンショットを2枚（時間差あり）確認：
  暗い岩の上に明るい亀裂と光暈がはっきり浮かび上がり、2枚を
  比較して明滅（パルス）していることも確認した。沼は円ではなく
  等角グリッドに沿った紫の菱形クラスターとして表示されることも
  確認した。

## 残作業

- 火山の発光表現・沼のマス目化は視覚的な改善のみで、ゲーム
  ロジック（`applyVolcano`/`eruptVolcano`/`swampSystem`）は一切
  変更していない。
- 本物の加算合成（additive blending）は使っていない（Graphicsの
  半透明円を重ねる擬似的な光暈）。もしさらに炎らしさが必要なら、
  発光要素だけ別レイヤーに分けて`blendMode: "add"`を使う手が
  次の候補になる。
