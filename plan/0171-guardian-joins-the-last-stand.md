# 0171 guardian-joins-the-last-stand

## 守護者は最終決戦に立ち尽くす

最終決戦（アーマゲドン）で決着が付かない試合を実機で見て、`goToShrineSystem`
を読み直したときに見つけた。この不具合は**守護者が盤上にいるときだけ**起きる。

原作の最終決戦は「敵味方が住居を捨てて中央へ集まり、**全滅まで戦う**」
（`docs/original-miracles.md` 5番）。誰も欠けない。ところが game2 の守護者は、
撃った瞬間から**二度と動かなくなる**。

門が2つあり、どちらも閉じている。

1. **`guardianTargetingSystem`** は「自分の勢力の家の近くにいる脅威」しか
   狙わない。これは通常の試合では正しい——守護者は襲撃者ではなく守り手で
   あり、その doc comment もそう書いている。ところが `triggerArmageddon` は
   **両陣営の家を全て壊す**。つまり最終決戦では、この条件は**二度と満たされ
   ない**。「守るものが無ければ立っている」が、永久就職になる。
2. **`goToShrineSystem`** の最終決戦分岐は「全てのウォーカーが中央へ向かう」
   と自分のコメントに書いているが、実際に呼ぶ `assignTarget` は
   `walker.state !== "seeking"` で弾く。守護者の state は `"guardian"` なので、
   **中央への行軍命令も渡らない**。

結果、守護者は狙いもせず、中央へも行かず、その場に立つ。**総力戦に一切
参加しない。**

`summarize()` は守護者をウォーカーとして数えるので、その勢力は残りの民を
全て失っても「まだ生きている」ことになり、`getOutcome()` は決着しない
——**ただし、通りかかった敵が偶然その守護者を倒さなかった場合に限る**。

**この膠着は実機では再現できなかった。** argos-1（守護者化と最終決戦の
両方が配られる面）で2回試し、守護者の側が勝つ回（75秒）と負ける回（90秒）を
作ったが、どちらも普通に決着した。負ける回でも、中央へ向かう敵が立って
いる守護者に行き当たって倒したのだと考えられる。

つまり**恒久的な膠着は「起こりうる」であって「必ず起こる」ではない**。
確実に言えるのは、この節の見出しそのもの——守護者が最終決戦で何もしない
ことであり、それは下のテストが直接押さえている。原作が「全滅まで戦う」と
書いている以上、参加しないこと自体が差分である。

攻撃側の英雄（`ADVANCING_HERO_KINDS`）は `heroAdvanceTargetingSystem` が
「盤上どこでも最寄りの敵」を狙わせるので、2つ目の門は閉じていても自力で
戦いに加わる。**守護者だけが両方閉じている。**

## 直し方

`guardianTargetingSystem` に、その勢力が最終決戦中かどうかを見させる。
中なら、攻撃側の英雄と同じ `findNearestEnemyPosition` を使う。

守備範囲を広げたのではない。**守る家が1軒も無くなり、かつ「全滅まで戦う」
と決まった**という、この1つの状況だけの話である。留守番の対象が消えた以上、
留守番は終わっている。

`goToShrineSystem` の**振る舞いは触っていない**。攻撃側の英雄にも行軍命令は
渡っていないが、あちらは `heroAdvanceTargetingSystem` が盤上どこでも最寄りの
敵を狙わせるので、最終決戦では常に相手がいる。**行き場を失うのは守護者だけ
である。** 仮にあそこで中央を渡すと、`goToShrineSystem` は
`heroAdvanceTargetingSystem` より**先**に走るので、英雄が中央に釘付けになって
狩りをやめる——直す理由が無いうえ、直すと悪くなる。

**ただしコメントは直した。** あの doc comment は「every walker heads for
shrinePosition itself」と書いているが、`assignTarget` は `"seeking"` の
ウォーカーしか動かさないので、**英雄は一度も行軍命令を受け取らない**。
この一文はこのセッションで実際に私を誤らせた（英雄が中央へ行かないことを
膠着の原因だと考え、英雄なしでも決着しないことを確かめて取り下げた）。
「ordinary walker」と書き足し、英雄がどこで戦いに加わるのかを添えた。

## 検証

- `npm run typecheck` / `npm run build` パス、テスト1049件パス（+2）。
- **実機（argos-1、seed固定）で2回**：守護者の側が勝つ回 75秒、負ける回
  90秒——どちらも決着した。恒久的な膠着は**観測できていない**。上に書いた
  とおり、これは「起こりうる」であって「必ず起こる」ではない。
- `hero.test.ts` 2件——最終決戦中の守護者が遠くの敵を狙うこと（**先に落ちる
  テストを書いて不具合を確定させた**）、そして**同じ盤面で finalBattle だけを
  外すと狙わないこと**。2つ目が無いと、守護者を単なる襲撃者に変えていない
  ことが示せない。
- 既存の「家が1軒も無ければ狙わない」「範囲外の敵は狙わない」はそのまま通る
  ——通常の試合の振る舞いは変えていない。
