# 0171 guardian-joins-the-last-stand

## 守護者は最終決戦に立ち尽くす

最終決戦（アーマゲドン）で決着が付かない試合を実機で見て、`goToShrineSystem`
を読み直したときに見つけた。この不具合は**守護者が盤上にいるときだけ**起きる。

原作の最終決戦は「敵味方が住居を捨てて中央へ集まり、**全滅まで戦う**」
（`docs/original-miracles.md` 5番）。誰も欠けない。ところが game2 の守護者は、
撃った瞬間から**二度と動かなくなる**。

門が2つあり、どちらも閉じている。

1. **`guardianTargetingSystem`** は「自分の勢力の家の近くにいる脅威」しか
   狙わない。これは通常の試合では正しい——守護者は襲撃者ではなく守り手で
   あり、その doc comment もそう書いている。ところが `triggerArmageddon` は
   **両陣営の家を全て壊す**。つまり最終決戦では、この条件は**二度と満たされ
   ない**。「守るものが無ければ立っている」が、永久就職になる。
2. **`goToShrineSystem`** の最終決戦分岐は「全てのウォーカーが中央へ向かう」
   と自分のコメントに書いているが、実際に呼ぶ `assignTarget` は
   `walker.state !== "seeking"` で弾く。守護者の state は `"guardian"` なので、
   **中央への行軍命令も渡らない**。

結果、守護者は狙いもせず、中央へも行かず、その場に立つ。`summarize()` は
守護者をウォーカーとして数えるので、**片方の勢力が守護者だけになると
`getOutcome()` は永久に決着しない**。

攻撃側の英雄（`ADVANCING_HERO_KINDS`）は `heroAdvanceTargetingSystem` が
「盤上どこでも最寄りの敵」を狙わせるので、2つ目の門は閉じていても自力で
戦いに加わる。**守護者だけが両方閉じている。**

## 直し方

`guardianTargetingSystem` に、その勢力が最終決戦中かどうかを見させる。
中なら、攻撃側の英雄と同じ `findNearestEnemyPosition` を使う。

守備範囲を広げたのではない。**守る家が1軒も無くなり、かつ「全滅まで戦う」
と決まった**という、この1つの状況だけの話である。留守番の対象が消えた以上、
留守番は終わっている。

`goToShrineSystem` の方（英雄に行軍命令が渡らない件）は**触っていない**。
`goToShrineSystem` は `heroAdvanceTargetingSystem` より**先**に走るので、
そこで中央を渡すと英雄が中央に釘付けになり、狩りをやめる。直すなら
システムの順序の話になり、この不具合とは別の変更である。

## 検証

- `npm run typecheck` / `npm run build` パス、テスト1049件パス（+2）。
- `hero.test.ts` 2件——最終決戦中の守護者が遠くの敵を狙うこと（**先に落ちる
  テストを書いて不具合を確定させた**）、そして**同じ盤面で finalBattle だけを
  外すと狙わないこと**。2つ目が無いと、守護者を単なる襲撃者に変えていない
  ことが示せない。
- 既存の「家が1軒も無ければ狙わない」「範囲外の敵は狙わない」はそのまま通る
  ——通常の試合の振る舞いは変えていない。
