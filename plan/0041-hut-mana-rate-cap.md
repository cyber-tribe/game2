# 0041 hut-mana-rate-cap

## 背景

ユーザーからの実プレイ後のフィードバック：「ちゃんと家を育てないと
地震や火山分のマナがたまらないようにできると良いですね。地震連発
戦法が強すぎます」。

`plan/archived/0018-mana-pacing-rebalance.md`でmanaRateを1/3/6/12から
現行の0.2/0.5/1/2へ一律5分の1に下げた経緯があるが、これは「1軒あたり
の単価」を下げただけで、「家の数」に上限がなければ結局同じ問題が
再発する。実際に調べると、`maxHousesPerFaction`は
`floor(worldWidth * worldHeight / TILES_PER_HOUSE_CAP)`で20×20マップ
では50——人口が自然に溢れて自動で建つ家（`houseGrowth.ts`）の数に
実質かなり緩い上限しかない。地震の平らさを一切育てず"hut"のまま
放置しても、50軒 × 0.2 = 10.0/秒となり、地震（コスト20）は2秒で
再チャージできてしまう。「家を育てる」（`houseUpgrade.ts`が見る
周囲の平坦度でレベルアップする）努力を一切せず、ただ家の数だけで
奇跡コストを圧倒できてしまうのが「地震連発戦法」の正体だった。

## アプローチ

`manaSystem`（`src/game/systems/mana.ts`）で、hut（最低レベル）の家
から得られるマナレートの合計に上限`HUT_MANA_RATE_CAP`（新規定数、
`src/game/constants.ts`）を設けた。lodge以上はこれまで通り上限なしで
加算する。

- hut一軒あたりのmanaRateはそのまま（0.2）。少数の初期の家だけで
  普通に遊べる範囲（1〜数軒）ではこれまでと挙動が変わらない
  （`HUT_MANA_RATE_CAP`未満のため）。
- `HUT_MANA_RATE_CAP = 5 * HOUSE_LEVELS.hut.manaRate`（＝1.0/秒）。
  hutを何軒積み上げても地震（コスト20）の再チャージは最短20秒に
  制限され、ここから先に速くしたいならlodge以上へのアップグレード
  （周囲の地形を平らにする、本来の成長ループ）が必須になる。
- lodge/manor/castleへの到達は`HOUSE_UPGRADE_FLATNESS_RADIUS`分の
  地形操作という実際の投資を要求するため、そちらは引き続き上限なし
  で報われる設計のまま。

一律の単価引き下げ（0018）ではなく「量に対する頭打ち」にしたのは、
単価だけを下げるとまた家の数を増やすだけで同じ問題が再発するため。
上限を低レベルの家だけに絞ることで、初期の少数の家での基本操作
（隆起/沈降、コスト1）の体感速度には影響を与えず、後半の"hutを
量産して育てない"戦法だけを狙い撃ちできる。

## テスト

- `src/game/systems/mana.test.ts`に追加：
  - hutを50軒持っていても、マナレートが`HUT_MANA_RATE_CAP`で
    頭打ちになること。
  - 上限未満のhut数（1軒）では従来通り一切キャップされないこと。
  - hutが上限に達していても、lodge/castleの分はキャップの外側で
    そのまま加算されること。
- `npm run typecheck` / `npm run test -- --run`（233件）/
  `npm run build`がすべて成功。

## 残作業

- `HUT_MANA_RATE_CAP`の具体的な値（hut5軒相当）は初回の仮値。
  「地震が20秒に1回まで抑えられて丁度良いか」はプレイテストでしか
  確定できない。
- 今回のアプローチはhutだけを狙い撃ちしたが、理論上は
  lodgeを大量に量産して同様の"物量戦法"に走る余地は残っている
  （lodge以上は`HOUSE_UPGRADE_FLATNESS_RADIUS`分の地形操作を要求
  するため、hutほど量産が容易ではないと判断し今回は対象外とした）。
  プレイテストでlodge物量戦法が問題になるようなら同様の上限を
  検討する。
