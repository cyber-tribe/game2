# plan/ ディレクトリの運用ルール

以前は`docs/tech-stack.md`に全タスクの実装記録を1ファイルへ追記していたが、
どのタスクも同じ挿入位置（末尾）に追記するため、複数PRが並行すると
ほぼ毎回マージコンフリクトが発生していた。この問題を避けるため、
タスクごとに独立したファイルを作る運用に変更した。

## 運用

- 実装に着手する際、このディレクトリ直下（`plan/`）に、そのタスク専用の
  独立したMarkdownファイルを作成する。目的・設計判断・検証方法などを記録する。
- ファイル名は連番+短い英語スラッグ（例: `0018-conquest-mode.md`）とする。
  連番は`plan/`と`plan/archived/`を通じた既存最大値+1を使う。
- 1つの意味のある変更（1PR相当）につき1ファイルとする。無関係な複数タスクを
  1ファイルにまとめない（`CLAUDE.md`のPR粒度の方針と同じ考え方）。
- 対応が完了しPRがマージされたら、そのファイルを`plan/archived/`へ
  `git mv`する。ファイル自体は独立しているため、他のタスクの記録と
  競合することはない。

`docs/architecture.md`には、個々のタスクの経緯ではなく技術選定や
プロジェクト構成など頻繁には変わらない参照用の情報のみを置く。
